Types

CognitiveModeling.AbstractCognitiveModel — Type
AbstractCognitiveModel

Supertype for cognitive models, whose inputs are observations and whose outputs are actions.

In the REPL, a cognitive model shows its type, the values of its fields if it has any, and the names of its attributes, or not specified if it has no method of attribute_names. A kind of attribute with more than five names shows only how many there are, and attribute_names gives them. On one line, as inside a vector, a model shows its type and its kind.

Implementation

Create a subtype and add methods of apply_timestep_model, initialize_state and attribute_names for it. A model can also add methods of prepare_state_for_saving, default_parameters and stopping_criterion. Fitting with a PPL can need methods of its own, which the documentation for that PPL describes.

Examples

julia> struct ExampleModel <: AbstractCognitiveModel end

julia> function CognitiveModeling.attribute_names(model::ExampleModel)
           return ModelAttributes(;
               parameters = (:learning_rate, :noise),
               states = :expected_reward,
               inputs = :reward,
               outputs = (),
           )
       end;

julia> ExampleModel()
-- Cognitive model --
Type: ExampleModel
Parameters: learning_rate, noise
States: expected_reward
Inputs: reward
Outputs: none

julia> print(ExampleModel())
ExampleModel (cognitive model)

CognitiveModeling.AbstractEnvironmentModel — Type
AbstractEnvironmentModel

Supertype for environment models, whose inputs are the actions of a cognitive model and whose outputs are its observations.

An environment model shows in the REPL and on one line as a cognitive model does, with its own kind.

Implementation

Create a subtype and add the same methods as for an AbstractCognitiveModel: apply_timestep_model, initialize_state and attribute_names, and optionally prepare_state_for_saving, default_parameters and stopping_criterion. Fitting with a PPL can need methods of its own, which the documentation for that PPL describes.

See also simulate, which has an example.

Examples

julia> function CognitiveModeling.attribute_names(environment::ExampleEnvironment)
           return ModelAttributes(;
               parameters = :reward_probability,
               states = (),
               inputs = :choice,
               outputs = :reward,
           )
       end;

AbstractNoValue

Supertype for what stands in for an observation or an action that isn't there: NoValue and BeforeFirstTimestep, and in the data of a fitted session UnimputedMissingValue. A model which treats them all the same can check for it, as in context.input.reward isa AbstractNoValue.

CognitiveModeling.AgentStarts — Type
AgentStarts()

Make the agent move first on each timestep of a simulation or a fitted session.

On a timestep, the cognitive model updates and acts on the previous observation, and the environment then responds to its action. On the first timestep, the cognitive model receives an observation with every entry BeforeFirstTimestep. Both models receive it as the who_starts of their ModelContext, so that a cognitive model can act before it updates when that is what it means.

See also EnvironmentStarts, UnknownWhoStarts, simulate and SessionInfo.

source
CognitiveModeling.BeforeFirstTimestep — Type
BeforeFirstTimestep()

Stand-in for an observation or an action from before the first timestep, when there is none yet, as one entry of a NamedTuple, such as (; choice = BeforeFirstTimestep()).

A model receives it for every previous output on its first timestep, and for every input too when the other side hasn't moved yet: a cognitive model when the agent starts, and an environment model when the environment starts. NoValue is different: it says that nothing was observed or done on a timestep that did run.

Before the first timestep is timestep 0, which a simulation, a history and a fitted session start with when their SaveHistory saves the initial timestep values, as it does by default. Its observation and action are this marker unless others are given, and so is its size.

source
CognitiveModeling.Deterministic — Type
Deterministic(value)

An action or an observation that is always value, for a cognitive model or an environment model which gives it without any randomness, as in (; reward = Deterministic(1.0)).

A simulation samples every action and every observation with rand, and sampling from a Deterministic gives value itself. The value is kept in the field value.

A simulation throws an error for a number, a string or a symbol that isn't wrapped, since none of them is something to sample from. A vector, a tuple or a range that isn't wrapped is sampled from as it is: rand picks one of its elements, with no error.

Examples

julia> using Random: Xoshiro

julia> rand(Xoshiro(1), Deterministic(1.0))
1.0

julia> ModelOutput((; choice = Deterministic(true))).output_distribution.choice.value
true

CognitiveModeling.EnvironmentStarts — Type
EnvironmentStarts()

Make the environment move first on each timestep of a simulation or a fitted session.

On a timestep, the environment gives an observation in response to the previous action, and the cognitive model then updates and acts on it. On the first timestep, the environment receives an action with every entry BeforeFirstTimestep. Both models receive it as the who_starts of their ModelContext.

See also AgentStarts, UnknownWhoStarts, simulate and SessionInfo.

CognitiveModeling.InvalidParametersError — Type
InvalidParametersError(message)
InvalidParametersError()

An error for a model to throw from apply_timestep_model or initialize_state when its parameters aren't valid, as in throw(InvalidParametersError()).

The default message says that the parameters are not valid, possibly dependent on the observations, actions and states, and a model can give a more specific one. A simulation stops with it as with any other error, and fitting can catch it to give the parameters a probability of zero, so a model should throw this rather than an ordinary error when the parameters are the problem.

Examples

julia> try
           throw(InvalidParametersError())
       catch error
           sprint(showerror, error)
       end
"InvalidParametersError: Model parameters are not valid, possibly dependent on observations, actions and states."

julia> sprint(showerror, InvalidParametersError("The learning rate must be between 0 and 1."))
"InvalidParametersError: The learning rate must be between 0 and 1."

CognitiveModeling.ModelAttributes — Type
ModelAttributes(; parameters, states, inputs, outputs)

The names of the attributes of a model, which attribute_names returns.

For a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it receives and the outputs the observations it gives.

Each argument is a Tuple of Symbols, read as a property of the same name, such as attributes.parameters. A single Symbol is put in a tuple, and a Vector of them is made into one. All four must be given, and () means that the model has none of that kind. A name can only be used once across the four kinds, so that it says which attribute of the model is meant wherever the attributes are named together, and an ArgumentError is thrown otherwise.

Examples

julia> attributes = ModelAttributes(;
           parameters = (:learning_rate, :inverse_temperature),
           states = :expected_reward,
           inputs = [:reward],
           outputs = (),
       )

States: expected_reward
Inputs: reward
Outputs: none

julia> attributes.states
(:expected_reward,)

julia> ModelAttributes(; parameters = :choice, states = (), inputs = (), outputs = :choice)
ERROR: ArgumentError: The name choice is used for both a parameter and an output, but a model can only use a name for one attribute.

CognitiveModeling.ModelContext — Type
ModelContext(; input, previous_state, previous_output, parameters, timestep_size=1,
             rng=default_rng(), who_starts=UnknownWhoStarts())
ModelContext(input, previous_state, previous_output, parameters, timestep_size=1,
             rng=default_rng(), who_starts=UnknownWhoStarts())

Everything a model needs to run a single timestep, which apply_timestep_model receives. The arguments can be given by name, which says what each one is, or in this order.

Each argument is kept in a field of the same name, such as context.input. For a cognitive model the input is its observation and the output its action, and for an environment model the input is the action of the cognitive model and the output the observation it gives.

Arguments

  • input: what the model receives on this timestep, in a NamedTuple with the names the other side gave the entries, as in context.input.reward. An entry that isn't there on this timestep is NoValue. On the first timestep, when the other side hasn't moved yet, every entry is BeforeFirstTimestep.
  • previous_state: the state of the model after the previous timestep. On the first timestep, this is the output of initialize_state.
  • previous_output: what the model gave on the previous timestep, in a NamedTuple with the names the model gave the entries, as in context.previous_output.choice. On the first timestep, each of them is BeforeFirstTimestep.
  • parameters: the parameters of the model, in a NamedTuple.
  • timestep_size=1: how much time this timestep covers; the difference between the end of the previous and the end of the current timestep.
  • rng=default_rng(): the random number generator to sample from if anything in the model is random, so that a simulation can be reproduced.
  • who_starts=UnknownWhoStarts(): who moves first on the timestep, AgentStarts or EnvironmentStarts as the simulation or the fitted session was told, or UnknownWhoStarts when neither is known. A model which can update before it acts or act before it updates can choose by it: for a cognitive model, with EnvironmentStarts() the input is this timestep's observation, and with AgentStarts() the previous timestep's.

Examples

julia> input = (; reward = 1.0);

julia> previous_state = (; expected_reward = 0.5);

julia> previous_output = (; choice = BeforeFirstTimestep());

julia> parameters = (; learning_rate = 0.1);

julia> ModelContext(; input, previous_state, previous_output, parameters).timestep_size
1

julia> ModelContext(; input, previous_state, previous_output, parameters, timestep_size = 0.5).timestep_size
0.5

julia> ModelContext(input, previous_state, previous_output, parameters).who_starts
UnknownWhoStarts()
source
CognitiveModeling.ModelOutput — Type
ModelOutput(output_distribution, new_state=(;))

The outputs of a model for a single timestep, which apply_timestep_model returns.

Each argument is kept in a field of the same name, such as output.new_state.

Arguments

  • output_distribution::NamedTuple: what the model's outputs on this timestep are sampled from, in a NamedTuple with one entry for each output, such as (; choice = Bernoulli(0.7)) for the action of a cognitive model, or (; reward = Bernoulli(0.8)) for the observation an environment model gives. Each entry can be anything that works with rand, such as a distribution from Distributions.jl, or a Deterministic for an output that isn't random, and the sampled outputs keep the names. An output that isn't given on this timestep is NoValue, and a model without outputs gives an empty NamedTuple, (;).
  • new_state::NamedTuple=(;): the state of the model after this timestep, which is the previous_state of the next one, with one entry for each state in the model's attributes, also when the state is a single object, as in (; rl_env). A model without a state gives an empty NamedTuple, (;). The outputs are sampled after the state is made, so it can't depend on them: the model receives them as context.previous_output on the next timestep.

Examples

julia> using Distributions: Bernoulli

julia> ModelOutput((; choice = Bernoulli(0.7)), (; expected_reward = 0.5)).new_state
(expected_reward = 0.5,)

julia> ModelOutput((; choice = Bernoulli(0.7))).new_state
NamedTuple()

julia> ModelOutput((; choice = NoValue(), bet = Bernoulli(0.2))).output_distribution.choice
NoValue()
source

NoValue()

The who_starts of a ModelContext when neither side is known to move first on a timestep, as when a model runs on a single input with simulate, or is used outside a simulation. Functions that a model must implement

These and the functions that a model can implement are public, but not exported, so use them with the package's name, as in CognitiveModeling.apply_timestep_model.

CognitiveModeling.apply_timestep_model — Function
apply_timestep_model(model::AbstractTimestepModel, context::ModelContext)::ModelOutput

Run a single timestep of model: update its state, and return what its outputs are sampled from. For a cognitive model the outputs are its actions, and for an environment model the observations it gives.

Implementation

Every model must add a method of this function, which throws an error otherwise. A simulation samples the outputs itself, from the output_distribution of the ModelOutput that the method returns, so an output that isn't random is wrapped in a Deterministic. In simulations, anything else that is random, such as a change of the state, should be sampled from context.rng. If states are mutated in place, a prepare_state_for_saving method must be added. For use within PPLs, this function can also have special implementations, and there may be special constraints: see the documentation for the specific PPL for details.

Examples

using CognitiveModeling
using Distributions: BernoulliLogit

struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.apply_timestep_model(model::RescorlaWagner, context::ModelContext)

    ## Unpack the context ##
    #Reward observed on this timestep
    r = context.input.reward
    #Expected reward from the previous state
    V₋₁ = context.previous_state.expected_reward
    #Learning rate parameter
    α = context.parameters.learning_rate
    #Inverse temperature parameter
    β = context.parameters.inverse_temperature

    ## Update state ##
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁)

    ## Compute action probabilities ##
    #Softmax function, instantiated as a Bernoulli logit distribution
    Pₜ = BernoulliLogit(β * (Vₜ - 0.5))

    return ModelOutput((; choice = Pₜ), (; expected_reward = Vₜ))
end

parameters = (; learning_rate = 0.1, inverse_temperature = 2.0)
context = ModelContext(; input = (; reward = 1.0), previous_state = (; expected_reward = 0.5), previous_output = (; choice = NoValue()), parameters)

CognitiveModeling.apply_timestep_model(RescorlaWagner(), context).new_state

# output

(expected_reward = 0.55,)

CognitiveModeling.attribute_names — Function
attribute_names(model::AbstractTimestepModel)::ModelAttributes

Return the names of the parameters, states, inputs and outputs of model, in a ModelAttributes.

The names define the model, so they must match what the model uses. The parameters are the names that apply_timestep_model and initialize_state read from the parameters. The states are the names in the state that initialize_state returns and in new_state, which apply_timestep_model reads from context.previous_state. The inputs are the names that apply_timestep_model reads from context.input, and the outputs are the names in output_distribution, which are also those in context.previous_output. For a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it receives and the outputs the observations it gives. Nothing checks that they match while the model runs.

Implementation

Every model must add a method of this function, which throws an error otherwise. A model without one kind of attribute gives () for it. simulate and InstantiatedModel use the output names for the output before the first timestep, and check the parameters, the previous output and the state against the names. A simulation with an environment also checks that the two models fit together: the outputs of each must be the inputs of the other, unless a NameMap says which of them are passed on, and under which names.

Examples

julia> struct RescorlaWagner <: AbstractCognitiveModel end

julia> function CognitiveModeling.attribute_names(model::RescorlaWagner)
           return ModelAttributes(;
               parameters = (:learning_rate, :inverse_temperature),
               states = :expected_reward,
               inputs = :reward,
               outputs = :choice,
           )
       end;

julia> CognitiveModeling.attribute_names(RescorlaWagner()).parameters
(:learning_rate, :inverse_temperature)

CognitiveModeling.prepare_state_for_saving — Function
prepare_state_for_saving(model::AbstractTimestepModel, state)

Return what a simulation saves of state, the state of a cognitive model or of an environment model, as it is about to save it. The state that the next timestep starts from isn't affected.

Implementation

A model can add a method of this function. The default returns state as it is, so nothing is copied. One which changes an object in its state in place must add a method which copies it, or all the saved states show the final values, with no error. The method must return the state with the names in the model's attributes, since a SaveHistory selects states by those names. Nothing checks this while the model runs.

Examples

julia> struct LearnsInPlace <: AbstractCognitiveModel end

julia> function CognitiveModeling.prepare_state_for_saving(model::LearnsInPlace, state)
           return (; values = copy(state.values))
       end;

julia> state = (; values = [0.5, 0.5]);

julia> CognitiveModeling.prepare_state_for_saving(LearnsInPlace(), state).values === state.values
false

CognitiveModeling.parameter_domains — Function
parameter_domains(model::AbstractTimestepModel)

Return the values that the parameters of model, a cognitive model or an environment model, can take: a NamedTuple from the name of a parameter to its domain, which is a NamedTuple with any of lower, the smallest value it can have, upper, the largest, and discrete, whether it must be a whole number. What a domain leaves out is unbounded and continuous, and so is a parameter without a domain.

The parameters of a simulation and of a fitted session are checked against their domains before anything runs, and a value outside its domain throws an InvalidParametersError. An inference backend can also warn before a fit when a prior gives values outside a domain, and CognitiveModeling.discrete_parameter_names gives the discrete parameters, which are sampled in another way than the continuous ones.

Implementation

A model can add a method of this function. The default is an empty NamedTuple, (;), so that every parameter can take any value. A domain is best kept to the values the model can't run without, since a value outside it can't be fitted at all.

Examples

julia> struct CountsOptions <: AbstractCognitiveModel end

julia> function CognitiveModeling.parameter_domains(model::CountsOptions)
           return (;
               learning_rate = (; lower = 0, upper = 1),
               n_options = (; lower = 1, discrete = true),
           )
       end;

julia> CognitiveModeling.discrete_parameter_names(CountsOptions())
(:n_options,)

CognitiveModeling.stopping_criterion — Function
stopping_criterion(model::AbstractTimestepModel, state, parameters)

Return whether model, a cognitive model or an environment model, with state as its state after a timestep and its parameters, has signaled for a simulation to stop there instead of running all of n_steps.

simulate and simulate! check it for both models before each timestep, with the states that the timestep before left, unless they are given check_stopping_criterion = false. When it returns true for either, no further timestep runs, and what is returned and added to the histories has the timesteps that ran. When the environment starts, the cognitive model has then made its last observation and acted on it, and the environment doesn't receive that action. When the cognitive model starts, the environment has then responded to the last action with an observation, and the cognitive model doesn't receive that observation. A model whose criterion is already met before the first timestep can't be simulated, and throws an error: a new simulation starts from the initial state, and reset! puts an InstantiatedModel back there. A fitted session checks it as SessionInfo describes.

Implementation

A model can add a method of this function. The default returns false, so a simulation runs all of its timesteps.

Examples

julia> struct Maze <: AbstractEnvironmentModel end

julia> function CognitiveModeling.stopping_criterion(environment::Maze, state, parameters)
           return state.position == parameters.goal
       end;

julia> CognitiveModeling.stopping_criterion(Maze(), (; position = 4), (; goal = 4))
true

Environments from other packages

CognitiveModeling.CommonRLEnvironment — Type
CommonRLEnvironment(rl_env::CommonRLInterface.AbstractEnv; action_name)

An environment model around rl_env, an environment from CommonRLInterface.jl, which needs CommonRLInterface.jl to be loaded. action_name is the name of the cognitive model's action that act! receives, such as :arm.

Environments from POMDPs.jl and ReinforcementLearning.jl can be used through it. POMDPTools.jl wraps a POMDP as POMDPCommonRLEnv{Any}(pomdp) and an MDP as MDPCommonRLEnv{Any}(mdp), which give each observation, or each state of an MDP, as the problem gives it. Its convert(CommonRLInterface.AbstractEnv, pomdp) gives the same environment with each converted to an array, which a cognitive model that reads them as the problem gives them, such as one with a belief updater of POMDPTools.jl, can't use. ReinforcementLearningBase.jl defines convert(CommonRLInterface.AbstractEnv, rl_env) for its environments.

The state is (; rl_env): initialize_state resets rl_env with CommonRLInterface.jl's reset! and returns it in the state, every timestep changes it in place with act! and passes it on in the new state, and prepare_state_for_saving copies it, with clone if it provides it and with deepcopy otherwise. Every simulation with the same CommonRLEnvironment therefore resets and changes the same rl_env, so simulations that run at the same time, such as on several threads, need one each. A method of prepare_state_for_saving for a CommonRLEnvironment with a specific type of rl_env can save something lighter. The parameters aren't used, and neither is the random number generator, since an environment of CommonRLInterface.jl has its own randomness.

Each observation is a NamedTuple (; observation, reward, terminated): what observe gives, copied unless it is plain data such as a number, the reward that act! returned, and whether the episode has ended. Each is given in a Deterministic, so nothing more is sampled. Before the first action, when the action is BeforeFirstTimestep, the environment is at its initial observation, so the reward is NoValue and nothing is done with the action. The same goes for a timestep where the model takes no action, NoValue: the environment stays where it is. Its attribute_names are these three observations, the one action, no parameters and the state rl_env. Use EnvironmentStarts, so that the model observes before it acts.

A simulation stops by itself when the episode ends, since the stopping_criterion of the environment is terminated of rl_env, so n_steps is the most timesteps it can take. An episode that has ended isn't started again, and an action given to it throws an error. A new call of simulate starts a new episode, and so does reset! of an InstantiatedModel, since both reset rl_env through initialize_state.

Examples

using CognitiveModeling
using CommonRLInterface

#A two-armed bandit where the first arm always pays, in episodes of two pulls
mutable struct Bandit <: CommonRLInterface.AbstractEnv
    pulls::Int
end
CommonRLInterface.reset!(rl_env::Bandit) = (rl_env.pulls = 0; nothing)
CommonRLInterface.actions(rl_env::Bandit) = 1:2
CommonRLInterface.observe(rl_env::Bandit) = rl_env.pulls
CommonRLInterface.act!(rl_env::Bandit, arm) = (rl_env.pulls += 1; arm == 1 ? 1.0 : 0.0)
CommonRLInterface.terminated(rl_env::Bandit) = rl_env.pulls == 2

#A model which always pulls the first arm
struct PullsFirstArm <: AbstractCognitiveModel end
CognitiveModeling.initialize_state(model::PullsFirstArm, parameters) = (;)
CognitiveModeling.apply_timestep_model(model::PullsFirstArm, context::ModelContext) = ModelOutput((; arm = Deterministic(1)))
CognitiveModeling.attribute_names(model::PullsFirstArm) = ModelAttributes(; parameters = (), states = (), inputs = (:observation, :reward, :terminated), outputs = :arm)

#The simulation stops when the episode ends, before it has run all of n_steps
simulation = simulate(
    PullsFirstArm(),
    CommonRLEnvironment(Bandit(0); action_name = :arm);
    who_starts = EnvironmentStarts(),
    n_steps = 10,
    cognitive_parameters = (;),
    environment_parameters = (;),
    cognitive_save_history = SaveHistory(SaveEverything()),
)

#Timestep 0, before the first timestep, and then what the environment gave on each timestep
foreach(println, simulation.observations)

# output

(observation = BeforeFirstTimestep(), reward = BeforeFirstTimestep(), terminated = BeforeFirstTimestep())
(observation = 0, reward = NoValue(), terminated = false)
(observation = 1, reward = 1.0, terminated = false)
(observation = 2, reward = 1.0, terminated = true)
