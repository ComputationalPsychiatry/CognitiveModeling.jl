CognitiveModeling.turing_behavioral_session — Function
turing_behavioral_session(session_info::SessionInfo, cognitive_parameters)
turing_behavioral_session(session_info::SessionInfo, cognitive_parameters,
                          environment_parameters=(;))

Create a Turing.jl model of one session: the cognitive model in session_info goes through the timesteps of its data with cognitive_parameters, and the actions in the data are scored against the action distributions it gives. The second form is for a session with an environment model, which takes its parameters too. This needs Turing.jl to be loaded.

The model is a building block for a Turing.jl model which samples the parameters, as a submodel with its own prefix: to_submodel(prefix(turing_behavioral_session(...), @varname(session)), false). turing_multiple_behavioral_sessions runs one for each of several sessions, and turing_full_model samples their parameters too.

Arguments

  • session_info::SessionInfo: the data, the models and the settings of the session, prepared once with SessionInfo.
  • cognitive_parameters::NamedTuple: the parameters of the cognitive model, usually the random variables of the model around this one. Those it doesn't have take the values in default_parameters, if the model provides defaults for them.
  • environment_parameters::NamedTuple=(;): the parameters of the environment model, with its default values for those that aren't given, if it provides any. A session without an environment takes none.

What it does

In outline, the model of a session without an environment looks like this. It is not the actual code, which also checks the names and the parameters, and saves what is selected:

#The state where the session starts, which a model can sample
state ~ to_submodel(turing_initialize_state(cognitive_model, cognitive_parameters))

for t in 1:n_timesteps

    #The cognitive model gives a distribution for each action, under the prefix timestep[t]
    output ~ to_submodel(turing_apply_timestep_model(cognitive_model, context))

    #An action that is missing in the data is a latent variable with that distribution
    choice.imputed ~ output.output_distribution.choice
end

#The actions in the data are scored once, against the distributions of their timesteps
actions_to_condition_on ~ product_distribution(action_distributions)

#The trajectories over the timesteps that the save histories select
return saved_trajectories

A session which includes its environment runs the environment model in the same way on each timestep, before the cognitive model when the environment starts and after it when the agent starts, and scores the observations in the data like the actions.

The states where the session starts come from turing_initialize_state of each model with the parameters, so that a starting state which is a parameter is fitted like any other, and a model can sample its start. Both models are treated the same way on each timestep: turing_apply_timestep_model of the cognitive model runs as a submodel with the prefix timestep[t], so a model which samples within a timestep has its own variables for each timestep, such as timestep[3].noise, and an environment model runs with the prefix timestep[t].environment. The outputs of each, the actions and the observations, are then taken from the data where they are recorded, and where the data has MissingValue they are imputed from what the model gave: as a latent variable with that distribution, named timestep[3].choice.imputed or timestep[3].environment.reward.imputed, or as the value itself if it is a Deterministic. Where the data has UnimputedMissingValue, or a marker for nothing happening, the models receive the marker as it is, and nothing is sampled or scored for it. The sampler must handle the type of a latent variable: a continuous value can be sampled with NUTS, a discrete one needs a sampler for discrete variables. The actions in the data are scored at the end as observed values, in one product_distribution over every action and timestep, against the distributions the cognitive model gave for them. The observations in the data are scored the same way against the distributions the environment gave, so that they inform the missing values and the environment's parameters. A Deterministic is scored as a point mass, with a log density of 0 for its value and -Inf for any other, and only a number or a Bool can be, so a value in the data that the model gives as another kind of Deterministic is an error, and so is one where the model gave nothing, NoValue. When the session doesn't include its environment, as the include_environment of session_info decides, which by default is when nothing in the data is MissingValue() and the environment's history isn't saved, the session is the same as one without an environment, with the same variables. The stopping_criterion of the models is checked as the check_stopping_criterion of session_info says: by default only after the last timestep with data, so that a fit runs every timestep and a session from prepare_for_prediction can end early.

What it returns

The trajectories that the save histories of session_info select, in a NamedTuple with the same entries as simulate returns: states, observations, actions and action_distributions of the cognitive model, environment with the states, observations, actions and observation_distributions of the environment when the session has one, which are empty when it didn't run, and timestep_sizes. Each is a vector with one element for timestep 0, before the first timestep, and one for each timestep that ran, which returned(model, chain) gives for each sample. Timestep 0 has the previous observation and action, which are BeforeFirstTimestep unless others are given, BeforeFirstTimestep() for every distribution, and the initial states, which can depend on the parameters. Element t + 1 is then timestep t, and a SaveHistory with save_initial_timestep_values = false leaves timestep 0 out. The returned actions and observations are those the models received, with the imputed values. timestep_sizes has the size of each timestep, after BeforeFirstTimestep() for timestep 0 when it is there, when anything is selected, and is empty otherwise. Any latent variable in a session, imputed or from a model which samples within a timestep, greatly increases the amount of estimated variables, which will generally make fitting the model much slower.

Examples

using CognitiveModeling
using Turing

#The model to fit, a Rescorla-Wagner model with a softmax choice
struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = parameters.initial_value)
end

function CognitiveModeling.apply_timestep_model(model::RescorlaWagner, context::ModelContext)
    V₋₁ = context.previous_state.expected_reward
    Vₜ = V₋₁ + context.parameters.learning_rate * (context.input.reward - V₋₁)
    Pₜ = BernoulliLogit(context.parameters.inverse_temperature * (Vₜ - 0.5))
    return ModelOutput((; choice = Pₜ), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(;
        parameters = (:learning_rate, :inverse_temperature, :initial_value),
        states = :expected_reward,
        inputs = :reward,
        outputs = :choice,
    )
end

CognitiveModeling.default_parameters(model::RescorlaWagner) = (; initial_value = 0.5)

#The data of one session, where the third choice wasn't recorded, prepared once
session_info = SessionInfo(
    RescorlaWagner(),
    (; reward = [1.0, 0.0, 1.0, 1.0]),
    (; choice = [true, false, MissingValue(), true]);
    who_starts = EnvironmentStarts(),
    cognitive_save_history = SaveHistory(; states = :expected_reward),
)

#Priors on the parameters, and the session as a submodel
@model function fit_one_session(session_info)
    learning_rate ~ Beta(2, 2)
    inverse_temperature ~ LogNormal(0, 1)
    session ~ to_submodel(
        prefix(
            turing_behavioral_session(session_info, (; learning_rate, inverse_temperature)),
            @varname(session),
        ),
        false,
    )
    return session
end

chain = sample(fit_one_session(session_info), NUTS(), 1000)

#The expected rewards on each timestep, for each sample
trajectories = returned(fit_one_session(session_info), chain)

CognitiveModeling.turing_catch_invalid_parameters — Function
turing_catch_invalid_parameters(model)

Create a Turing.jl model which runs model, any Turing.jl model, inside a try block: an InvalidParametersError thrown by a cognitive model or an environment model then gives the parameters a log density of -Inf, so that a sampler rejects the sample instead of stopping, and the model returns nothing for that sample. Otherwise it returns what model returns. This needs Turing.jl to be loaded.

It goes around the part of a model that can throw, with the parameters sampled outside it, as in

@model function fit_one_session(session_info)
    learning_rate ~ Beta(2, 2)
    session ~ to_submodel(
        turing_catch_invalid_parameters(
            turing_behavioral_session(session_info, (; learning_rate)),
        ),
        false,
    )
end

and turing_full_model does this with catch_invalid_parameters = true. The variables sampled inside the try block are lost when it catches an error, so around a whole model a sampler can't start when its first draw is rejected. Nothing in the package catches the error unless this is used, so a sampler stops with it otherwise. Not every automatic differentiation backend can differentiate a model with it, as the page on automatic differentiation says.

CognitiveModeling.turing_full_model — Function
turing_full_model(cognitive_parameters_model, sessions_info::MultipleSessionsInfo;
                  environment_parameters_model=NoSessionParameters(),
                  downstream_model=NoDownstreamModel(),
                  fixed_cognitive_parameters=(;), fixed_environment_parameters=(;),
                  catch_invalid_parameters=false, parallelization=SerialSessions(),
                  include_submodel_prefixes=false)

Create the Turing.jl model which fits a cognitive model to several sessions, in three parts: cognitive_parameters_model gives or samples the cognitive parameters of every session, and environment_parameters_model those of the environment model, the sessions in sessions_info run with them as turing_multiple_behavioral_sessions, and downstream_model can do something with the trajectories they saved, such as a regression of a measurement on a state. This needs Turing.jl to be loaded.

Arguments

  • cognitive_parameters_model: the session parameter model of the cognitive model, which gives or estimates its parameters for every session: a subtype of AbstractSessionParametersModel, such as IndependentSessionParameters with a prior for each parameter.
  • sessions_info::MultipleSessionsInfo: the sessions, prepared once with MultipleSessionsInfo.
  • environment_parameters_model=NoSessionParameters(): the session parameter model of the environment model of the sessions, when they have one. By default the environment's parameters take its default values, and FixedSessionParameters gives others. When they are estimated, every session includes its environment, also those with nothing to impute, so that the observations in the data inform them, which is an error for a session prepared with include_environment = false. Sessions without an environment take no parameters.
  • downstream_model=NoDownstreamModel(): a final submodel which is run after the sessions, such as for correlations with other kinds of data: a subtype of AbstractDownstreamModel. The default samples nothing.
  • fixed_cognitive_parameters::NamedTuple=(;) and fixed_environment_parameters::NamedTuple=(;): values which every session gets for the parameters they name, such as (; initial_value = 0.3), while the session parameter models give the others. A parameter is either fixed here or given by its session parameter model, and a fixed parameter must be one in the model's attributes.
  • catch_invalid_parameters::Bool=false: whether an InvalidParametersError in a session rejects the sample instead of stopping the sampler, by running the sessions inside turing_catch_invalid_parameters. If the first draw is rejected and the downstream model has variables of its own, give the sampler valid initial_params.
  • parallelization=SerialSessions(): whether the sessions run over the threads Julia was started with, with ParallelSessions(). The model must then be marked with setthreadsafe(model, true) from DynamicPPL before it is sampled: without the mark, a threaded model has a wrong log density with no error, so the sessions throw an error instead.
  • include_submodel_prefixes::Bool=false: whether the variables of the two session parameter models and of the downstream model are named under cognitive_parameters_model, environment_parameters_model and downstream_model. Without the prefixes, the names are shorter, but a variable of the same name in two of them is one variable, which sample refuses with an error, and which a log density gives one value with both priors counted. A warning says so when the model is made, when the cognitive model and the environment model have a parameter of the same name and both session parameter models sample.

The variables of a session parameter model are named as it names them, or under the session parameter model's name with include_submodel_prefixes = true. With IndependentSessionParameters, each parameter is a vector with a value for each session, such as learning_rate.session, so the learning rate of the third session is learning_rate.session[3]. With GroupedHierarchicalSessionParameters, each parameter of a group-level distribution is named after its prior, such as learning_rate.mean.group and learning_rate.sd.group, which is one value without groups, and otherwise has the value of each group under the group's symbol name, such as learning_rate.mean.group.clinical. The values of the sessions before the transformation are learning_rate.standardized, or learning_rate.session for a parameter that is centered. With HierarchicalRegressionSessionParameters, the coefficients of the intercept, the predictors and the interactions of a parameter are one variable, learning_rate.coef, with each under its name, such as learning_rate.coef.intercept, learning_rate.coef.age, learning_rate.coef.diagnosis_clinical for a level of a categorical predictor, and learning_rate.coef.age_by_diagnosis_clinical for an interaction. Varying effects have the variables of each of their coefficients under their name and the coefficient's: the standard deviation, learning_rate.participant.intercept.sd, which has the value of each group under the group's symbol name when the levels are grouped, such as learning_rate.participant.intercept.sd.clinical, and a standardized value for each level, learning_rate.participant.intercept.standardized, or the deviation of each level, learning_rate.participant.intercept.deviation, when they are centered. A part of a CompositeSessionParameters that is given with a name has its variables under that name, such as noise.bias.session. The variables of the sessions are under session[i], and those of the downstream model as it names them, or under downstream_model with the prefixes.

The model returns a NamedTuple with cognitive_parameters, environment_parameters, saved_behavioral_trajectories and downstream_values: the cognitive parameters and the environment parameters of every session as the session parameter models gave them, the trajectories each session saved, as a vector of what turing_behavioral_session returns, and what the downstream model returned. returned(model, chain) gives them for each sample, so a fitted state is read from the chain without simulating again.

Saving states adds a cost to gradient calculations. Without a downstream model that needs them, a fit is fastest with sessions that save nothing, and the trajectories are then read from the chain afterwards with session_trajectories_chain, or with returned on the model of a copy of the sessions that saves them, MultipleSessionsInfo(sessions_info; cognitive_save_history = SaveHistory(; states = :expected_reward)), since the two models have the same variables. A warning says so when the sessions save anything and there is no downstream model.

Examples

using CognitiveModeling
using Turing

#The data of two sessions, as a table with one vector for each column
table = (;
    id = ["S1", "S1", "S1", "S2", "S2", "S2"],
    reward = [1.0, 0.0, 1.0, 0.0, 0.0, 1.0],
    choice = [true, false, true, false, missing, true],
)

#The sessions, with the RescorlaWagner model of turing_behavioral_session
sessions_info = MultipleSessionsInfo(
    RescorlaWagner(),
    table;
    observation_columns = :reward,
    action_columns = :choice,
    session_columns = :id,
    who_starts = EnvironmentStarts(),
    cognitive_save_history = SaveHistory(; states = :expected_reward),
)

#Each session has its own parameters, from the same priors
cognitive_parameters_model = IndependentSessionParameters((;
    learning_rate = Beta(2, 2),
    inverse_temperature = LogNormal(0, 1),
))

model = turing_full_model(cognitive_parameters_model, sessions_info)
chain = sample(model, NUTS(), 1000)

#The parameters and the expected rewards of every session, for each sample
results = returned(model, chain)
results[1].cognitive_parameters.learning_rate
results[1].saved_behavioral_trajectories[2].states

#The same fit without saving, and the states read from the chain afterwards
sessions_without_saving = MultipleSessionsInfo(
    sessions_info; cognitive_save_history = SaveHistory(),
)
unsaved = turing_full_model(cognitive_parameters_model, sessions_without_saving)
chain = sample(unsaved, NUTS(), 1000)
results = returned(model, chain)

CognitiveModeling.session_trajectories_chain — Function
session_trajectories_chain(results, sessions_info::MultipleSessionsInfo;
                           iter_indices=1:size(results, 1),
                           chain_indices=1:size(results, 2))
session_trajectories_chain(results; iter_indices=1:size(results, 1),
                           chain_indices=1:size(results, 2))
session_trajectories_chain(model, chain; cognitive_save_history=SaveHistory(),
                           environment_save_history=SaveHistory())

Return the trajectories that fitted sessions saved, for every sample, as a FlexiChain from FlexiChains.jl with the same samples as the fit, so that they can be summarized and plotted like the chain itself. The trajectories of a session are what changes over its timesteps: the states, the observations and the actions of its models, and the distributions they gave. This needs FlexiChains.jl to be loaded, which Turing.jl loads. The names of the entries are the VarNames that FlexiChains.jl uses, written as @varname(P1.expected_value) with FlexiChains.jl 0.6, which Turing.jl uses, and as @vn(P1.expected_value) with 0.7.

results is a matrix with one element for each sample, iterations down and chains across, as returned(model, chain) gives it in Turing.jl. Its elements are what one of three models returns:

  • turing_full_model, given with its MultipleSessionsInfo. The entries of each session are named after its symbol name, such as P1.expected_value. The parameters of the sessions are a chain of their own, see session_parameters_chain, and what a downstream model returned isn't included.
  • turing_multiple_behavioral_sessions, given with its MultipleSessionsInfo, named in the same way.
  • turing_behavioral_session, given without a session info, with no symbol name of a session in the names, such as expected_value.

In a model of one's own around these, that model must return what they return, for returned to give it.

The trajectories each session saved, as its SaveHistorys selected, are one entry for each name, with the session's symbol name first. The cognitive model's values are named after the attribute alone, since a model uses a name for one attribute only: a state as P1.expected_value, an observation as P1.reward and an action as P1.choice. An action distribution is named like its action, so it is under its kind, as P1.action_distributions.choice. The environment's values are under environment, in the same way: P1.environment.level for a state, P1.environment.reward for an observation it gave, P1.environment.choice for an action it received and P1.environment.observation_distributions.reward. Each entry holds a vector over the timesteps for every sample, which starts with timestep 0 when the initial timestep values are saved, so that element t + 1 is timestep t, as everywhere in the package. The observations, the actions and the distributions of timestep 0 are BeforeFirstTimestep, so a summary of those entries needs timestep 0 left out. The symbol name of a session with several session columns joins the name and the value of each column, as in id_S1__block_2, as CognitiveModeling.session_id_to_symbol gives it. iter_indices and chain_indices number the samples as the chain that was fitted does.

The third form, in the Turing extension, takes a model made by one of the three functions, or such a model inside turing_catch_invalid_parameters, and a chain sampled from it. It makes a copy of the model whose sessions save what the two save histories select, gives it to returned, and makes the chain of the results, numbered as chain is. A fit is fastest when its sessions save nothing, and their trajectories are then read afterwards in this way. Selecting anything in environment_save_history makes every session run its environment, see SessionInfo.

Examples

chain = sample(model, NUTS(), 1000)
session_trajectories = session_trajectories_chain(model, chain; cognitive_save_history = SaveHistory(; states = :expected_value))

#The expected values of participant P2 over the timesteps, for every sample
session_trajectories[@varname(P2.expected_value)]

#The parameters of the sessions, in the same chain
everything = merge(session_trajectories, session_parameters_chain(model, chain))

Functions that a model can implement for Turing.jl

A model can add methods of these to change how it runs when it is fitted with Turing.jl, and must when it samples anything of its own, within a timestep or when it starts. They are public, but not exported.

CognitiveModeling.turing_apply_timestep_model — Function
turing_apply_timestep_model(model::AbstractTimestepModel, context::ModelContext)

Create a Turing.jl model for a single timestep of model, a cognitive model or an environment model, to be used as a submodel, which returns a ModelOutput. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls apply_timestep_model. A model which samples within a timestep needs to add a method, however; or if any other changes are desired within Turing. It must sample with ~ instead of from context.rng. Otherwise the model has a different log density each time it is evaluated, with no error. The same holds for an environment model, which fitting uses to fill in observations that are MissingValue in the data: what it samples itself, such as a change of its state, must be sampled with ~, while fitting samples the observations from what it returns.

Examples

using CognitiveModeling
using Turing

struct NoisyRescorlaWagner <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_apply_timestep_model(
        model::NoisyRescorlaWagner,
        context::ModelContext,
    )

    ## Unpack the context ##
    #Reward observed on this timestep
    r = context.input.reward
    #Expected reward from the previous state
    V₋₁ = context.previous_state.expected_reward
    #Learning rate parameter
    α = context.parameters.learning_rate

    ## Update state ##
    #Sample the noise in the update
    ϵ ~ Normal(0, context.parameters.noise)
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁) + ϵ

    return ModelOutput((; choice = BernoulliLogit(Vₜ - 0.5)), (; expected_reward = Vₜ))
end

CognitiveModeling.turing_initialize_state — Function
turing_initialize_state(model::AbstractTimestepModel, parameters)

Create a Turing.jl model which gives the state of model, a cognitive model or an environment model, before the first timestep, to be used as a submodel, as initialize_state does. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls initialize_state, which is enough for most models, since a starting state that is fitted is simply one that is copied from a parameter there: a fitted session runs it with the parameters of each evaluation, so a prior on the parameter is a prior on the starting state. A model which samples something of its own when it initializes needs to add a method, and sample it with ~, as for turing_apply_timestep_model. Its variables are named under initial_cognitive_state, or initial_environment_state for an environment model.

Examples

using CognitiveModeling
using Turing

struct UncertainStart <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_initialize_state(
        model::UncertainStart,
        parameters,
    )

    #Sample where the expected reward starts, around the parameter for it
    V₀ ~ Normal(parameters.initial_value, parameters.initial_noise)

    return (; expected_reward = V₀)
end

Fitting several sessions

These are what the parts of turing_full_model are written with, beside the types and functions on the page Fitting. They are public, but not exported. In a Turing.jl model of several sessions, session i of CognitiveModeling.session_index has its variables under session[i].

CognitiveModeling.turing_session_parameters_model — Function
turing_session_parameters_model(parameters_model, sessions_info::MultipleSessionsInfo)

Create the Turing.jl model of parameters_model, a session parameter model, which gives or samples the parameters of every session in sessions_info, for the cognitive model or the environment model of a turing_full_model. This needs Turing.jl to be loaded.

The model must return a NamedTuple with one entry for each parameter, named as the model names it, and a vector in each with one value for every session, in the order of the sessions. Each subtype of AbstractSessionParametersModel that comes with CognitiveModeling.jl has a method.

Implementation

A session parameter model of another kind, such as a regression, is a subtype of AbstractSessionParametersModel with a method of this function. It can read n_sessions and the identifiers of the sessions from sessions_info, the columns of the table that the sessions were split from, when there is one, with CognitiveModeling.session_column_values, such as the covariates of a regression, and anything else from its own fields. What it reads from the table is best read once, in a method of CognitiveModeling.prepare_parameters_model. The full model treats it as one that samples, so that with it the environment of every session runs, and the observations in the data inform the environment's parameters.

CognitiveModeling.turing_downstream_model — Function
turing_downstream_model(downstream_model, saved_behavioral_trajectories,
                        cognitive_parameters, sessions_info::MultipleSessionsInfo)

Create the Turing.jl model of downstream_model, the final submodel of a turing_full_model, which is run after the sessions, with the trajectories the sessions saved, the cognitive parameters of every session as the session parameter model returned them, and the sessions' sessions_info. This needs Turing.jl to be loaded.

The model can return anything, which the full model returns as its downstream_values. NoDownstreamModel is the default, with a method which samples nothing and returns nothing.

Implementation

A downstream model is a subtype of AbstractDownstreamModel with a method of this function, which can ignore any of the arguments. A regression of some measurement on a state of the cognitive model, for instance, reads the state from saved_behavioral_trajectories, a vector with the saved trajectories of each session as turing_behavioral_session returns them, so the cognitive_save_history of the sessions must select that state.
