CognitiveModeling.TuringBackend — Type
TuringBackend()

Marker of Turing.jl as the inference backend, which full_model takes to make the Turing.jl model of a full model. This needs Turing.jl to be loaded.

CognitiveModeling.full_model — Method
full_model(::TuringBackend, cognitive_parameters_model,
           sessions_info::MultipleSessionsInfo;
           environment_parameters_model=NoParameters(),
           downstream_model=NoDownstreamModel(), fixed_cognitive_parameters=(;),
           fixed_environment_parameters=(;), catch_invalid_parameters=false,
           parallelization=SerialSessions(), include_submodel_prefixes=false)

Create the Turing.jl model which fits a cognitive model to several sessions, in three parts: cognitive_parameters_model gives or samples the cognitive parameters of every session, and environment_parameters_model those of the environment model, the sessions in sessions_info run with them as turing_multiple_behavioral_sessions, and downstream_model can do something with the trajectories they saved, such as a regression of a measurement on a state. The parts are prepared with prepare_full_model, and the model is turing_full_model of the prepared parts. This needs Turing.jl to be loaded.

Arguments

  • cognitive_parameters_model: the parameter model of the cognitive model, which gives or estimates its parameters for every session: a subtype of AbstractParametersModel, such as IndependentParameters with a prior for each parameter. A tuple of parameter models, or a NamedTuple of them, is made into a CompositeParameters of them, with each part of a NamedTuple under its name. So is a tuple or a NamedTuple given as environment_parameters_model.
  • sessions_info::MultipleSessionsInfo: the sessions, prepared once with MultipleSessionsInfo.
  • environment_parameters_model=NoParameters(): the parameter model of the environment model of the sessions, when they have one. By default the environment's parameters take its default values, and FixedParameters gives others. When they are estimated, every session includes its environment, also those with nothing to impute, so that the observations in the data inform them, which is an error for a session prepared with include_environment = false. Sessions without an environment take no parameters.
  • downstream_model=NoDownstreamModel(): a final submodel which is run after the sessions, such as for correlations with other kinds of data: a subtype of AbstractDownstreamModel. The default samples nothing.
  • fixed_cognitive_parameters::NamedTuple=(;) and fixed_environment_parameters::NamedTuple=(;): values which every session gets for the parameters they name, such as (; initial_value = 0.3), while the parameter models give the others. A parameter is either fixed here or given by its parameter model, and a fixed parameter must be one in the model's attributes.
  • catch_invalid_parameters::Bool=false: whether an InvalidParametersError in a session rejects the sample instead of stopping the sampler, by running the sessions inside turing_catch_invalid_parameters, which gives the parameters a log density of -Inf. If the first draw is rejected and the downstream model has variables of its own, give the sampler valid initial_params. A ParameterDomainError isn't caught, and stops the sampler.
  • parallelization=SerialSessions(): whether the sessions run over the threads Julia was started with, with ParallelSessions(). The model must then be marked with setthreadsafe(model, true) from DynamicPPL before it is sampled: without the mark, a threaded model has a wrong log density with no error, so the sessions throw an error instead.
  • include_submodel_prefixes::Bool=false: whether the variables of the two parameter models and of the downstream model are named under cognitive_parameters_model, environment_parameters_model and downstream_model. Without the prefixes, the names are shorter, but a variable of the same name in two of them is one variable, which sample refuses with an error, and which a log density gives one value with both priors counted. A warning says so when the model is made, when the cognitive model and the environment model have a parameter of the same name and both parameter models sample.

The variables of a parameter model are named after the parameters, such as learning_rate.session with IndependentParameters, where learning_rate.session[3] is the learning rate of the third session, or under the parameter model's name with include_submodel_prefixes = true. A part of a CompositeParameters that is given with a name has its variables under that name. The variables of the sessions are under session[i], and those of the downstream model as it names them, or under downstream_model with the prefixes. rand(model) shows every variable's name.

The model returns a NamedTuple with cognitive_parameters, environment_parameters, saved_trajectories and downstream_values: the cognitive parameters and the environment parameters of every session as the parameter models gave them, the trajectories each session saved, as turing_multiple_behavioral_sessions returns them, and what the downstream model returned. returned(model, chain) gives them for each sample, so a fitted state is read from the chain without simulating again.

Saving states adds a cost to gradient calculations. Without a downstream model that needs them, a fit is fastest with sessions that save nothing, and the trajectories are then read from the chain afterwards with get_session_trajectories, or with returned on the model of a copy of the sessions that saves them, MultipleSessionsInfo(sessions_info; cognitive_save_history = SaveHistory(; states = :expected_reward)), since the two models have the same variables. A warning says so when the sessions save anything and there is no downstream model.

Examples

using CognitiveModeling
using Turing

#The data of two sessions, as a table with one vector for each column
table = (;
    id = ["S1", "S1", "S1", "S2", "S2", "S2"],
    reward = [1.0, 0.0, 1.0, 0.0, 0.0, 1.0],
    choice = [true, false, true, false, missing, true],
)

#The sessions, with the RescorlaWagner model of turing_behavioral_session
sessions_info = MultipleSessionsInfo(
    RescorlaWagner(),
    table;
    observation_columns = :reward,
    action_columns = :choice,
    session_columns = :id,
    who_starts = EnvironmentStarts(),
    cognitive_save_history = SaveHistory(; states = :expected_reward),
)

#Each session has its own parameters, from the same priors
cognitive_parameters_model = IndependentParameters((;
    learning_rate = Beta(2, 2),
    inverse_temperature = LogNormal(0, 1),
))

model = full_model(TuringBackend(), cognitive_parameters_model, sessions_info)
chain = sample(model, NUTS(), 1000)

#The parameters and the expected rewards of every session, for each sample
returned_values = returned(model, chain)
returned_values[1].cognitive_parameters.learning_rate
returned_values[1].saved_trajectories[2].states

#The same fit without saving, and the states read from the chain afterwards
sessions_without_saving = MultipleSessionsInfo(
    sessions_info; cognitive_save_history = SaveHistory(),
)
unsaved = full_model(TuringBackend(), cognitive_parameters_model, sessions_without_saving)
chain = sample(unsaved, NUTS(), 1000)
returned_values = returned(model, chain)

CognitiveModeling.turing_behavioral_session — Function
turing_behavioral_session(session_info::SessionInfo, cognitive_parameters)
turing_behavioral_session(session_info::SessionInfo, cognitive_parameters,
                          environment_parameters=(;))

Create a Turing.jl model of one session: the cognitive model in session_info goes through the timesteps of its data with cognitive_parameters, and the actions in the data are scored against the action distributions it gives. The second form is for a session with an environment model, which takes its parameters too. This needs Turing.jl to be loaded.

The model is a building block for a Turing.jl model which samples the parameters, as a submodel with its own prefix: to_submodel(prefix(turing_behavioral_session(...), @varname(session)), false). turing_multiple_behavioral_sessions runs one for each of several sessions, and turing_full_model samples their parameters too.

Arguments

  • session_info::SessionInfo: the data, the models and the settings of the session, prepared once with SessionInfo.
  • cognitive_parameters::NamedTuple: the parameters of the cognitive model, usually the random variables of the model around this one. Those it doesn't have take the values in default_parameters, if the model provides defaults for them.
  • environment_parameters::NamedTuple=(;): the parameters of the environment model, with its default values for those that aren't given, if it provides any. A session without an environment takes none.

What it does

In outline, the model of a session without an environment looks like this. It is not the actual code, which also checks the names and the parameters, and saves what is selected:

#The state where the session starts, which a model can sample
state ~ to_submodel(turing_initialize_state(cognitive_model, cognitive_parameters))

for t in 1:n_timesteps

    #The cognitive model gives a distribution for each action, under the prefix timestep[t]
    output ~ to_submodel(turing_run_timestep(cognitive_model, context))

    #An action that is missing in the data is a latent variable with that distribution
    choice.imputed ~ output.output_distribution.choice
end

#The actions in the data are scored once, against the distributions of their timesteps
actions_to_condition_on ~ product_distribution(action_distributions)

#The parameters as they were given, and the trajectories over the timesteps that the save histories select
return (; cognitive_parameters, environment_parameters, saved_trajectories)

A session which includes its environment runs the environment model in the same way on each timestep, before the cognitive model when the environment starts and after it when the agent starts, and scores the observations in the data like the actions.

The states where the session starts come from turing_initialize_state of each model with the parameters, so that a starting state which is a parameter is fitted like any other, and a model can sample its start. Both models are treated the same way on each timestep: turing_run_timestep of the cognitive model runs as a submodel with the prefix timestep[t], so a model which samples within a timestep has its own variables for each timestep, such as timestep[3].noise, and an environment model runs with the prefix timestep[t].environment. The outputs of each, the actions and the observations, are then taken from the data where they are recorded, and where the data has MissingValue they are imputed from what the model gave: as a latent variable with that distribution, named timestep[3].choice.imputed or timestep[3].environment.reward.imputed, or as the value itself if it is a Deterministic. Where the data has UnimputedMissingValue, or a marker for nothing happening, the models receive the marker as it is, and nothing is sampled or scored for it. The actions in the data are scored at the end as observed values, in one product_distribution over every action and timestep, against the distributions the cognitive model gave for them. The observations in the data are scored the same way against the distributions the environment gave, so that they inform the missing values and the environment's parameters. A Deterministic is scored as a point mass, with a log density of 0 for its value and -Inf for any other, and only a number or a Bool can be, so a value in the data that the model gives as another kind of Deterministic is an error, and so is one where the model gave nothing, NoValue. When the session doesn't include its environment, as the include_environment of session_info decides, which by default is when nothing in the data is MissingValue() and the environment's history isn't saved, the session is the same as one without an environment, with the same variables. The stopping_criterion of the models is checked as the check_stopping_criterion of session_info says: by default only after the last timestep with data, so that a fit runs every timestep and a session from prepare_for_prediction can end early.

What it returns

A NamedTuple with cognitive_parameters and environment_parameters, the parameters as they were given, without the default values of the models, and saved_trajectories, the trajectories that the save histories of session_info select, which returned(model, chain) gives for each sample. The trajectories are a NamedTuple with the same entries as simulate returns: states, observations, actions and action_distributions of the cognitive model, environment with the states, observations, actions and observation_distributions of the environment when the session has one, which are empty when it didn't run, and timestep_sizes. Each is a vector with one element for timestep 0, before the first timestep, and one for each timestep that ran. Timestep 0 has the previous observation and action, which are BeforeFirstTimestep unless others are given, BeforeFirstTimestep() for every distribution, and the initial states, which can depend on the parameters. Element t + 1 is then timestep t, and a SaveHistory with save_initial_timestep_values = false leaves timestep 0 out. The returned actions and observations are those the models received, with the imputed values. timestep_sizes has the size of each timestep, after BeforeFirstTimestep() for timestep 0 when it is there, when anything is selected, and is empty otherwise. Any latent variable in a session, imputed or from a model which samples within a timestep, greatly increases the amount of estimated variables, which will generally make fitting the model much slower.

Examples

using CognitiveModeling
using Turing

#The model to fit, a Rescorla-Wagner model with a softmax choice
struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = parameters.initial_value)
end

function CognitiveModeling.run_timestep(model::RescorlaWagner, context::ModelContext)
    V₋₁ = context.previous_state.expected_reward
    Vₜ = V₋₁ + context.parameters.learning_rate * (context.input.reward - V₋₁)
    Pₜ = BernoulliLogit(context.parameters.inverse_temperature * (Vₜ - 0.5))
    return ModelOutput((; choice = Pₜ), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(;
        parameters = (:learning_rate, :inverse_temperature, :initial_value),
        states = :expected_reward,
        inputs = :reward,
        outputs = :choice,
    )
end

CognitiveModeling.default_parameters(model::RescorlaWagner) = (; initial_value = 0.5)

#The data of one session, where the third choice wasn't recorded, prepared once
session_info = SessionInfo(
    RescorlaWagner(),
    (; reward = [1.0, 0.0, 1.0, 1.0]),
    (; choice = [true, false, MissingValue(), true]);
    who_starts = EnvironmentStarts(),
    cognitive_save_history = SaveHistory(; states = :expected_reward),
)

#Priors on the parameters, and the session as a submodel
@model function fit_one_session(session_info)
    learning_rate ~ Beta(2, 2)
    inverse_temperature ~ LogNormal(0, 1)
    session ~ to_submodel(
        prefix(
            turing_behavioral_session(session_info, (; learning_rate, inverse_temperature)),
            @varname(session),
        ),
        false,
    )
    return session
end

chain = sample(fit_one_session(session_info), NUTS(), 1000)

#The parameters and the expected rewards on each timestep, for each sample
returned_values = returned(fit_one_session(session_info), chain)
returned_values[1].saved_trajectories.states

#The same as chains, which merge into one
parameters = get_session_parameters(returned_values)
trajectories = get_session_trajectories(returned_values)
merge(parameters, trajectories)

CognitiveModeling.turing_catch_invalid_parameters — Function
turing_catch_invalid_parameters(model)

Create a Turing.jl model which runs model, any Turing.jl model, inside a try block: an InvalidParametersError thrown by a cognitive model or an environment model then gives the parameters a log density of -Inf, so that a sampler rejects the sample instead of stopping, and the model returns nothing for that sample. Otherwise it returns what model returns. Any other error is thrown as it is, also a ParameterDomainError for a parameter outside its domain. This needs Turing.jl to be loaded.

It goes around the part of a model that can throw, with the parameters sampled outside it, as in

@model function fit_one_session(session_info)
    learning_rate ~ Beta(2, 2)
    session ~ to_submodel(
        turing_catch_invalid_parameters(
            turing_behavioral_session(session_info, (; learning_rate)),
        ),
        false,
    )
end

and turing_full_model does this with catch_invalid_parameters = true. The variables sampled inside the try block are lost when it catches an error, so around a whole model a sampler can't start when its first draw is rejected. Nothing in the package catches the error unless this is used, so a sampler stops with it otherwise. Not every automatic differentiation backend can differentiate a model with it, as the page on automatic differentiation says.

CognitiveModeling.turing_multiple_behavioral_sessions — Function
turing_multiple_behavioral_sessions(sessions_info::MultipleSessionsInfo,
                                    cognitive_parameters, environment_parameters=(;),
                                    parallelization=SerialSessions())

Create a Turing.jl model which runs turing_behavioral_session for every session in sessions_info, each with its own cognitive parameters, as a submodel with the prefix session[i], so that a latent variable of the third session is named like session[3].timestep[2].choice.imputed. Which session i is stands in sessions_info.session_ids[i], and session_index gives i for a data identifier. Environment parameters can only be given when the sessions have an environment model. With ParallelSessions() as parallelization, after the environment parameters, which are (;) for sessions without an environment, the sessions run over the threads Julia was started with. The model that is evaluated, which is the outermost one, must then be marked with setthreadsafe(model, true) from DynamicPPL, since the log density of a threaded model that isn't is wrong with no error; the sessions throw an error when it isn't marked. See parallelization in full_model with TuringBackend(). This needs Turing.jl to be loaded.

cognitive_parameters is a NamedTuple with one vector for each parameter, with one value for every session in the order of sessions_info, which is what a parameter model returns, see turing_parameters_model, and environment_parameters is in the same form. It returns a NamedTuple with cognitive_parameters and environment_parameters as they were given, and saved_trajectories, a vector with the trajectories each session saved, in the same order, as turing_behavioral_session returns them. The model is a building block for a Turing.jl model which samples the parameters of the sessions in some way of its own, as a submodel without a prefix: to_submodel(turing_multiple_behavioral_sessions(sessions_info, parameters), false). turing_full_model does this with parameter models. A model of one's own can return the same NamedTuple, and get_session_trajectories and get_session_parameters then read what it returns too, also when it transforms its variables into the parameters.

Postprocessing

With Turing.jl loaded, which loads FlexiChains.jl, get_session_trajectories and get_session_parameters take a model made by full_model with TuringBackend(), turing_multiple_behavioral_sessions or turing_behavioral_session, or such a model inside turing_catch_invalid_parameters, and the FlexiChain that sample gives for it. A model of one's own around the sessions gives them the values that returned(model, chain) gives instead, with the MultipleSessionsInfo of several sessions.

chain = sample(model, NUTS(), 1000)
session_trajectories = get_session_trajectories(model, chain; cognitive_save_history = SaveHistory(; states = :expected_value))
parameters = get_session_parameters(model, chain)

#The same from a model of one's own around the sessions, which returns what they return
parameters = get_session_parameters(returned(own_model, chain), sessions_info)

Predictive checks

With Turing.jl loaded, predict_session_trajectories takes a model made by full_model with TuringBackend(), turing_multiple_behavioral_sessions or turing_behavioral_session, or such a model inside turing_catch_invalid_parameters, and a chain sampled from it. It returns the simulated trajectories as a FlexiChain, as get_session_trajectories makes it. For a prior predictive check, give a chain sampled from the prior, such as sample(model, Prior(), 1000).

chain = sample(model, NUTS(), 1000)
simulated = predict_session_trajectories(model, chain; cognitive_save_history = SaveHistory(; outputs = :choice))

#The simulated choices of participant P1, for every sample
simulated[@varname(P1.choice)]

Functions that a model can implement for Turing.jl

A model can add methods of these to change how it runs when it is fitted with Turing.jl, and must when it samples anything of its own, within a timestep or when it starts. They are public, but not exported.

CognitiveModeling.turing_run_timestep — Function
turing_run_timestep(model::AbstractTimestepModel, context::ModelContext)

Create a Turing.jl model for a single timestep of model, a cognitive model or an environment model, to be used as a submodel, which returns a ModelOutput. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls run_timestep. A model which samples within a timestep needs to add a method, however; or if any other changes are desired within Turing. It must sample with ~ instead of from context.rng. Otherwise the model has a different log density each time it is evaluated, with no error. The same holds for an environment model, which fitting uses to fill in observations that are MissingValue in the data: what it samples itself, such as a change of its state, must be sampled with ~, while fitting samples the observations from what it returns.

Examples

using CognitiveModeling
using Turing

struct NoisyRescorlaWagner <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_run_timestep(
        model::NoisyRescorlaWagner,
        context::ModelContext,
    )

    ## Unpack the context ##
    #Reward observed on this timestep
    r = context.input.reward
    #Expected reward from the previous state
    V₋₁ = context.previous_state.expected_reward
    #Learning rate parameter
    α = context.parameters.learning_rate

    ## Update state ##
    #Sample the noise in the update
    ϵ ~ Normal(0, context.parameters.noise)
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁) + ϵ

    return ModelOutput((; choice = BernoulliLogit(Vₜ - 0.5)), (; expected_reward = Vₜ))
end

CognitiveModeling.turing_initialize_state — Function
turing_initialize_state(model::AbstractTimestepModel, parameters)

Create a Turing.jl model which gives the state of model, a cognitive model or an environment model, before the first timestep, to be used as a submodel, as initialize_state does. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls initialize_state, which is enough for most models, since a starting state that is fitted is simply one that is copied from a parameter there: a fitted session runs it with the parameters of each evaluation, so a prior on the parameter is a prior on the starting state. A model which samples something of its own when it initializes needs to add a method, and sample it with ~, as for turing_run_timestep. Its variables are named under initial_cognitive_state, or initial_environment_state for an environment model.

Examples

using CognitiveModeling
using Turing

struct UncertainStart <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_initialize_state(
        model::UncertainStart,
        parameters,
    )

    #Sample where the expected reward starts, around the parameter for it
    V₀ ~ Normal(parameters.initial_value, parameters.initial_noise)

    return (; expected_reward = V₀)
end

Fitting several sessions

These are what the parts of turing_full_model are written with, beside the types and functions on the pages Fitting and Parameter models. They are public, but not exported. In a Turing.jl model of several sessions, session i of CognitiveModeling.session_index has its variables under session[i].

CognitiveModeling.turing_parameters_model — Function
turing_parameters_model(parameters_model, sessions_info::MultipleSessionsInfo)

Create the Turing.jl model of parameters_model, a parameter model, which gives or samples the parameters of every session in sessions_info, for the cognitive model or the environment model of a turing_full_model. This needs Turing.jl to be loaded.

The model must return a NamedTuple with one entry for each parameter, named as the model names it, and a vector in each with one value for every session, in the order of the sessions. Each subtype of AbstractParametersModel that comes with CognitiveModeling.jl has a method.

Implementation

A parameter model of another kind, such as a regression, is a subtype of AbstractParametersModel with a method of this function. It can read n_sessions and the data identifiers of the sessions from sessions_info, the columns of the table that the sessions were split from, when there is one, with CognitiveModeling.session_column_values, such as the covariates of a regression, and anything else from its own fields. What it reads from the table is best read once, in a method of CognitiveModeling.prepare_parameters_model. The full model treats it as one that samples, so that with it the environment of every session runs, and the observations in the data inform the environment's parameters.

CognitiveModeling.turing_downstream_model — Function
turing_downstream_model(downstream_model, saved_trajectories,
                        cognitive_parameters, sessions_info::MultipleSessionsInfo)

Create the Turing.jl model of downstream_model, the final submodel of a turing_full_model, which is run after the sessions, with the trajectories the sessions saved, the cognitive parameters of every session as the parameter model returned them, and the sessions' sessions_info. This needs Turing.jl to be loaded.

The model can return anything, which the full model returns as its downstream_values. NoDownstreamModel is the default, with a method which samples nothing and returns nothing.

Implementation

A downstream model is a subtype of AbstractDownstreamModel with a method of this function, which can ignore any of the arguments. A regression of some measurement on a state of the cognitive model, for instance, reads the state from saved_trajectories, a vector with the saved trajectories of each session as turing_behavioral_session returns them, so the cognitive_save_history of the sessions must select that state.
