Fitting

The sessions to fit, with their data, models and settings, and what runs after them, which are the same for every inference backend. A backend fits several sessions with a full model in three parts: a parameter model gives or samples the parameters of every session, for the cognitive model and for the environment model, as on the page Parameter models, the sessions run with them, and a downstream model can use the trajectories the sessions saved. Each backend has a page of its own, with the models it makes and what a model can add for it: Fitting with Turing.jl.

Sessions and settings

CognitiveModeling.AbstractDownstreamModel — Type
AbstractDownstreamModel

Supertype for downstream models: the final submodel of a full model, which is run after the sessions with the trajectories they saved, such as for correlations with other kinds of data, or a regression of a measurement on a state. NoDownstreamModel is the default.

Implementation

Create a subtype, and for each inference backend it is used with, add a method of that backend's function for downstream models, as the backend's documentation describes.

source
CognitiveModeling.MissingValue — Type
MissingValue()

Stand-in for an action or an observation that happened on a timestep but isn't in the data, and which fitting imputes, as one entry of a column or a NamedTuple, such as (; choice = MissingValue()). Whether it is an action or an observation is given by where it is.

Fitting imputes a missing action by sampling it from the model's action distribution on that timestep. It imputes a missing observation from what an environment model gives for the observation on that timestep: as a latent variable with that distribution, or as the value of a Deterministic. A value that isn't in the data and isn't to be imputed is UnimputedMissingValue instead. NoValue is different: it says that nothing was done or observed on the timestep. Unlike missing, arithmetic on it is an error. By default, a SessionInfo replaces missing in the data by it.

CognitiveModeling.MultipleSessionsInfo — Type
MultipleSessionsInfo(cognitive_model, table; observation_columns, action_columns,
                     session_columns, <keyword arguments>)
MultipleSessionsInfo(sessions, session_ids; table=nothing, session_rows=nothing)

Multiple behavioral sessions in a generative model that are fitted together, as a vector of SessionInfo with a data identifier for each, which an inference backend's models of several sessions take.

The first form splits a table into sessions. table is a NamedTuple with one vector for each column, or any other table that Tables.jl can read, such as a DataFrame or a CSV.File, whose columns are read when Tables.jl is loaded, as it is with DataFrames.jl and CSV.jl. The values of a column that stand for a missing observation or action become MissingValue, as for SessionInfo: by default those that are missing. As for SessionInfo, a session includes its environment where an observation or an action is MissingValue(), where environment_save_history saves anything or where check_stopping_criterion is true, and in an inference backend's full model that estimates the environment's parameters, unless include_environment says otherwise. The table is kept in the field table, without being copied, with the rows of each session in session_rows, so that a parameter model can read the columns it needs, such as those that a HierarchicalGroupedParameters groups the sessions by, and the predictors of a HierarchicalRegressionParameters.

MultipleSessionsInfo(sessions_info; cognitive_save_history, environment_save_history)

The same sessions with other save histories for every one, see SessionInfo.

Arguments

  • cognitive_model::AbstractTimestepModel: the cognitive model, usually an AbstractCognitiveModel.
  • table: the data of every session, in columns with one entry for each timestep, such as (; id = ["S1", "S1", "S2", "S2"], reward = [1.0, 0.0, 1.0, 1.0], choice = [true, false, true, true]), or a DataFrame with those columns.

Keyword arguments

  • observation_columns: the columns with the observations. When the model has only one kind of observation in its attributes, a single name, such as :outcome, is its column, whatever the observation is called. Several observations are given in a tuple, each as the name in the model's attributes when the column is named the same, or as a pair from the column's name to the model's, as in a NameMap, such as (:outcome => :reward, :cue), so that one model fits tables with other names. A single name among the actions in the model's attributes is an error, since the two keyword arguments may then be swapped. An observation or action whose value is composed from several columns is specified by how to build it from the columns, followed by the model's name: a Tuple of column names for a Tuple in each row, (:choicecol, :rtcol) => :ssm_action, a NamedTuple of column names for a NamedTuple, (; choice = :choicecol, rt = :rtcol) => :ssm_action, or a Tuple of column names and a function of their values, which needs parentheses around it, (:choicecol, :rtcol) => ((choice, rt) -> [choice, rt]) => :ssm_action. When the model has only one kind of them in its attributes, the name can be left out of the last two, as in (; choice = :choicecol, rt = :rtcol). A missing value in any of the columns makes the whole value missing.
  • action_columns: the columns with the actions, in the same forms.
  • session_columns: the column or columns which separate sessions, such as :id or (:id, :block). A session is every row with one combination of their values, in the order of the first row of each. The data identifier of a session is its value in a single column, or a NamedTuple of its values in several.
  • timestep_sizes=1: how much time each timestep covers, as one size for all, or the name of a column with the size of each timestep.
  • missing_observation_values=(missing,), missing_action_values=(missing,), impute_missing_observations=true and impute_missing_actions=true: the values in the columns which stand for a missing observation or action, and whether those are imputed, as for SessionInfo. They are marked in the whole table before it is split, so that the columns of every session have the same element types, and the values are checked against the domains of the model's inputs and outputs there, so that a value outside its domain is an ArgumentError that names its row of the table.
  • The other keyword arguments of SessionInfo, which every session gets.

The second form takes sessions that are already prepared. They have no table, unless it is given as table, with the rows of each session in it as session_rows, a vector of vectors of row numbers. Each argument is kept in a field of the same name.

Each session is identified in three ways: by its order, its index in sessions, which the models of several sessions number it by and CognitiveModeling.session_index finds; by its data identifier, the value of its session column, or a NamedTuple of the values when there are several, as in session_ids; and by its symbol name, a Symbol made from the data identifier by CognitiveModeling.session_id_to_symbol, such as S1 or id_S1__block_2, which the chains of a fit name its entries after.

In the REPL, the sessions show a summary on one line each: how many there are, and the models and the names in the data of the first.

Examples

julia> struct Counter <: AbstractCognitiveModel end

julia> CognitiveModeling.attribute_names(::Counter) = ModelAttributes(; parameters = :probability, states = :n_timesteps, inputs = :reward, outputs = :choice);

julia> table = (; id = ["S1", "S1", "S2", "S2", "S2"], outcome = [1.0, 0.0, 1.0, 1.0, 0.0], choice = [true, false, true, missing, false]);

julia> sessions_info = MultipleSessionsInfo(Counter(), table; observation_columns = :outcome => :reward, action_columns = :choice, session_columns = :id, who_starts = EnvironmentStarts())
MultipleSessionsInfo
Sessions: 2
Cognitive model: Counter
Environment: none
Observations: reward
Actions: choice

julia> sessions_info.session_ids
2-element Vector{String}:
 "S1"
 "S2"

julia> sessions_info.sessions[2].actions
(choice = Union{MissingValue, Bool}[true, MissingValue(), false],)

A DataFrame is given in the same way:

julia> using DataFrames

julia> data = DataFrame(id = ["S1", "S1", "S2", "S2"], reward = [1.0, 0.0, 1.0, 1.0], choice = [true, missing, false, true]);

julia> sessions_info = MultipleSessionsInfo(Counter(), data; observation_columns = :reward, action_columns = :choice, session_columns = :id, who_starts = EnvironmentStarts());

julia> sessions_info.sessions[1].actions
(choice = Union{MissingValue, Bool}[true, MissingValue()],)

CognitiveModeling.SessionInfo — Type
SessionInfo(cognitive_model, observations, actions; who_starts, <keyword arguments>)

Everything about one behavioral session that is fixed within a generative model to be fitted: the data, the models and the settings, checked and prepared once. An inference backend's model of the session takes it together with the parameters, which are what changes between evaluations. MultipleSessionsInfo makes one for each session in a table.

Arguments

  • cognitive_model::AbstractTimestepModel: the cognitive model, usually an AbstractCognitiveModel.
  • observations: the observations in the data, as a NamedTuple with one vector for each name and one entry for each timestep, such as (; reward = [1.0, 0.0, 1.0]). The data must have every observation in the model's attributes, from attribute_names, and can have more. When the model has only one kind of observation in its attributes, a single vector, [1.0, 0.0, 1.0], is the data of that observation, whatever its name. An observation that wasn't recorded is MissingValue, which environment imputes unless impute_missing_observations is false, and one that wasn't made is NoValue.
  • actions: the actions in the data, in the same forms, with exactly the actions in the model's attributes. An action that was taken but not recorded is MissingValue(), which is imputed unless impute_missing_actions is false, and an action that wasn't taken is NoValue(). Neither is scored. The observations are checked against the domains of the cognitive model's inputs, in input_domains, and the actions against those of its outputs, in output_domains, and a value outside its domain is an ArgumentError that names its timestep.

Keyword arguments

  • who_starts::Union{AgentStarts, EnvironmentStarts}: whether the model acts on the observation of the same timestep, EnvironmentStarts(), or on the observation of the timestep before, AgentStarts(), as in simulate. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • environment::Union{NoEnvironment, AbstractTimestepModel}=NoEnvironment(): an environment model, usually an AbstractEnvironmentModel, which imputes the observations that are MissingValue(), and against whose distributions the observations in the data are scored. Its outputs must be the inputs of cognitive_model and the other way round, directly or through observation_map and action_map. Without it, the data can't have observations that are MissingValue(). Whether the session includes it is decided by include_environment, and it is kept in the session either way.
  • include_environment::Union{Nothing, Bool}=nothing: whether the session includes environment, so that it runs on every timestep. By default, with nothing, it is included where an observation or an action is MissingValue(), where environment_save_history saves anything, or where check_stopping_criterion is true: the scored observations then inform what is imputed, such as which arm of a bandit a missing choice was, from the reward that followed. It is also included in every session of an inference backend's full model that estimates the environment's parameters, so that the observations inform them. Otherwise it is left out, since the scores of its observations would be the same for every value of the parameters, and the session has none of its variables. With true it is always included, such as for a model of one's own which estimates its parameters. With false it never is: an observation that is MissingValue(), a selection in environment_save_history and check_stopping_criterion = true are then errors, and an action that is MissingValue() is imputed without the observations informing it.
  • observation_map::Union{Nothing, NameMap}=nothing and action_map::Union{Nothing, NameMap}=nothing: which observations of environment the cognitive model receives, and which of its actions the environment receives, and under which names, as NameMaps, as for simulate. The data is in the cognitive model's names, and is scored against the environment's distributions as the map passes them on. An output of the environment that the map doesn't pass on isn't in the data, so it is imputed on every timestep. Each model's history is in its own names.
  • timestep_sizes=1: how much time each timestep covers, as in simulate.
  • cognitive_save_history::SaveHistory=SaveHistory(): which states, inputs, outputs and output distributions of cognitive_model a fitted session returns, by name, and whether timestep 0 is, as a SaveHistory in the model's own names. Nothing is selected by default. What is returned names them by their role, as states, observations, actions and action_distributions, as simulate does.
  • environment_save_history::SaveHistory=SaveHistory(): the same for environment, whose inputs are the actions and whose outputs are the observations, returned under environment. Selecting anything makes the environment run in the session, also when nothing is missing, which adds its scores of the observations to the log density; with fixed environment parameters they are the same for every value of the cognitive parameters, so the posterior is unchanged. Whether timestep 0 is saved follows cognitive_save_history.
  • check_stopping_criterion::Union{Nothing, Bool}=nothing: when the stopping_criterion of the two models is checked before a timestep, so that the session ends there, with what it saved up to it. With nothing, it is checked on the timesteps after the last one with data. With true, it is checked before every timestep, and a criterion that is met while the data continues is an error. With false, it is never checked. The extended help says why.
  • check_parameter_domains::Bool=true: whether the parameters of the two models are checked against their domains in parameter_domains each time the session runs, where a value outside its domain throws a ParameterDomainError, which stops a fit.
  • missing_observation_values=(missing,) and missing_action_values=(missing,): the values in the data which stand for a missing observation or action, as one value, such as -1, or several in a tuple or a vector, such as (missing, -1). Each is replaced by MissingValue(). A value is compared to them with isequal, and () keeps every value as it is, missing too. A function among them is called on each value instead, which is then missing when it returns true, such as value -> value isa AbstractVector && any(ismissing, value) for a vector with a missing element. MissingValue() can also be put in the data directly. The arrays in the values that are kept are narrowed to the types they hold, such as a Vector{Float64} for a Vector{Union{Missing,Float64}} without a missing element.
  • impute_missing_observations::Bool=true and impute_missing_actions::Bool=true: whether the observations and the actions that are MissingValue() are imputed, as latent variables. With false, nothing is sampled for them, and they are replaced by UnimputedMissingValue here, which the models receive as it is.
  • previous_observation and previous_action: what the first timestep receives as the observation and the action before it, in the cognitive model's names, with BeforeFirstTimestep for each name by default, as in simulate. The environment starts from the same observation in its own names, with BeforeFirstTimestep() for an output that observation_map doesn't pass on. The states where the session starts are not given here, since they come from initialize_state with the parameters that are fitted.

Each argument is kept in a field of the same name, except the values that stand for a missing one and whether they are imputed, whose work is done in the data here. The other fields are includes_environment, whether the session includes the environment, as include_environment decides it, environment_observations, the data of the environment's outputs in its own names, previous_environment_observation, the observation the environment starts from in its own names, actions_to_condition_on and observations_to_condition_on, the values in the data of each name, which fitting conditions on, with the observations in the environment's names, n_timesteps, saved_timestep_sizes, the sizes a fitted session returns with what it saves, and first_timestep_to_check_stopping, the first timestep before which the stopping criterion is checked, as check_stopping_criterion decides it.

SessionInfo(session_info; cognitive_save_history, environment_save_history)

Update a session to have other save histories, which returns a new SessionInfo. This is for after a fit: a session is fitted fastest when it saves nothing, and its states, or anything else it can save, are read afterwards from the updated session, by evaluating its model with each sample of the fit. The two models have the same variables, so every sample fits both. The documentation of each inference backend describes how.

In the REPL, a session shows a summary on one line each: its models, its number of timesteps, the names of the observations and the actions in its data, which are the cognitive model's names, and who starts.

julia> CognitiveModeling.attribute_names(::Counter) = ModelAttributes(; parameters = :probability, states = :n_timesteps, inputs = :reward, outputs = :choice);

julia> session_info = SessionInfo(Counter(), (; reward = [1.0, 0.0, missing]), (; choice = [true, missing, false]); who_starts = EnvironmentStarts(), impute_missing_observations = false)

Observations: reward

(UnimputedMissingValue(), MissingValue())

julia> session_info.actions_to_condition_on
(choice = Bool[1, 0],)

Extended help

When the stopping criterion is checked follows from the data. The last timestep with data is the last one where an observation or an action isn't MissingValue(). With check_stopping_criterion = nothing, the criterion is only checked after it, so that a fit, where every timestep has data, never checks it, and a session prepared by prepare_for_prediction, whose data is all MissingValue(), ends as a simulation does. With true, the session includes its environment, whose criterion is checked too. A criterion that is met while the data continues is then an error, since the values in the data after that timestep couldn't be scored, which checks that the models agree with the length of the data.

CognitiveModeling.UnimputedMissingValue — Type
UnimputedMissingValue()

Stand-in for an action or an observation that happened on a timestep but isn't in the data, and which fitting doesn't impute, as one entry of a column or a NamedTuple, such as (; reward = UnimputedMissingValue()).

Nothing is sampled or scored for it, and the models receive it as it is: a cognitive model as its observation, or as its previous action on the next timestep, and an environment model as the action it responds to. A model which is fitted to such data must handle it, as it does the other subtypes of AbstractNoValue. Useful for a session without an environment model whose data lacks some observations, and for missing actions which shouldn't become latent variables. A SessionInfo puts it in place of the missing observations with impute_missing_observations = false, and of the missing actions with impute_missing_actions = false.

Preparing a full model

This is what an inference backend calls before it makes its full model. It is public, but not exported.

CognitiveModeling.prepare_full_model — Method
prepare_full_model(cognitive_parameters_model, sessions_info::MultipleSessionsInfo;
                   environment_parameters_model=NoParameters(),
                   downstream_model=NoDownstreamModel(),
                   fixed_cognitive_parameters=(;),
                   fixed_environment_parameters=(;))

Prepare the parts of a full model once, before an inference backend makes its model of them, and return them in a NamedTuple with cognitive_parameters_model, environment_parameters_model, downstream_model and sessions_info. Useful for an inference backend, whose full model calls it, so that what doesn't change between the evaluations of the model is worked out once.

A parameter model can be given as a tuple of parameter models, or a NamedTuple of them, which is made into a CompositeParameters of them by as_parameters_model, with each part of a NamedTuple under its name. It checks that the two parameter models and the downstream model are of the right kind. The values in fixed_cognitive_parameters and fixed_environment_parameters, such as (; initial_value = 0.3), are given to every session for the parameters they name: each parameter model is combined with them in a CompositeParameters, so a parameter is either fixed or given by its parameter model, and a fixed parameter must be one in the model's attributes. It checks the parameters that each parameter model gives, when CognitiveModeling.parameter_names knows them, against those of the cognitive model and of the environment model: a parameter that isn't in the model's attributes is an error, and so is one in its attributes which is neither given nor has a default value, unless it is a parameter of an environment that no session runs. It prepares each parameter model for the sessions with CognitiveModeling.prepare_parameters_model. When environment_parameters_model estimates parameters, every session with an environment includes it in the returned sessions_info. It warns when the sessions save anything and there is no downstream model to use what they save.

Reading the sessions

A session is identified in three ways: by its order among the sessions, by its data identifier, which is the value of its session column, or a NamedTuple of the values of several, and by its symbol name, a Symbol made from the data identifier, which the chains of a fit name its entries after. These functions are public, but not exported.

n_sessions(sessions_info)

Return how many sessions a MultipleSessionsInfo has, which a parameter model gives the parameters of. Used by the parameter models of the inference backends, such as those of IndependentParameters.

source
CognitiveModeling.session_index — Function
session_index(sessions_info, session_id)

Return the index i of the session with the data identifier session_id in a MultipleSessionsInfo, which is how the models of several sessions number it: its parameters are element i of each vector a parameter model gives, and its saved trajectories are element i of what the sessions return. The data identifier is the value in the session column, or a NamedTuple of the values when there are several, as in sessions_info.session_ids. Used by users reading the results of a fit, not by the models.

source
CognitiveModeling.session_id_to_symbol — Function
session_id_to_symbol(session_id)

Return the symbol name of a session, a Symbol made from its data identifier: the value of a single session column, as in S1, and the name and the value of each of several columns, joined by _ within a column and by __ between columns, as in id_S1__block_2. The chains of a fit name the entries of a session after it, such as S1.learning_rate, and SessionwiseFixedParameters can find the values of a session by it. After using CognitiveModeling: session_id_to_symbol, the learning rate of a session is chain[@varname($(session_id_to_symbol(session_id)).learning_rate)].

Workflow and postprocessing

What is done with the sessions and with an inference backend's model around a fit. prepare_for_prediction is the same for every backend, while each backend adds the methods of get_session_trajectories, get_session_parameters and predict_session_trajectories for its own models, and its page describes which models they take.

CognitiveModeling.get_session_parameters — Function
get_session_parameters(returned_values, sessions_info::MultipleSessionsInfo;
                       iter_indices=1:size(returned_values, 1),
                       chain_indices=1:size(returned_values, 2))
get_session_parameters(returned_values; iter_indices=1:size(returned_values, 1),
                       chain_indices=1:size(returned_values, 2))
get_session_parameters(model, chain)

Return the parameters of every fitted session, for every sample, as a FlexiChain with the same samples as the fit, named after the session: P1.learning_rate for a parameter of the cognitive model, and P1.environment.mean_reward for one of the environment model. This needs FlexiChains.jl to be loaded.

returned_values is a matrix with one element for each sample, with what one of three models returned for it, as for get_session_trajectories: the full model or the model of several sessions, given with their MultipleSessionsInfo, or the model of a single session, given without a session info, whose parameters are named without a session, as learning_rate and environment.mean_reward. The parameters are those each session was given, without the default values of its models. With a full model, they are those the parameter models gave each session, so a parameter model other than IndependentParameters gives parameters that aren't in the chain itself, such as one value for every session from IdenticalParameters, and values from FixedParameters that were never sampled. A model of one's own around the model of several sessions or of a single session gives the parameters it passed to the sessions, such as transformations of its variables, when it returns what they return. The third form takes one of the three models and a chain sampled from it, a FlexiChain, and numbers the samples as the chain does, with a method of each inference backend for its own models. It merges with the chain of get_session_trajectories, which has the same samples, with merge.

get_session_trajectories(model, chain; cognitive_save_history=SaveHistory(),

Return the trajectories that fitted sessions saved, for every sample, as a FlexiChain from FlexiChains.jl with the same samples as the fit, so that they can be summarized and plotted like the chain itself. The trajectories of a session are what changes over its timesteps: the states, the observations and the actions of its models, and the distributions they gave. This needs FlexiChains.jl to be loaded. The names of the entries are the VarNames that FlexiChains.jl uses, written as @varname(P1.expected_value) with FlexiChains.jl 0.6, and as @vn(P1.expected_value) with 0.7.

returned_values is a matrix with one element for each sample, iterations down and chains across, with what an inference backend's model of the fitted sessions returned for that sample. Its elements are what one of three models returns:

  • The full model, given with its MultipleSessionsInfo. The entries of each session are named after its symbol name, such as P1.expected_value. The parameters of the sessions are a chain of their own, see get_session_parameters, and what a downstream model returned isn't included.
  • The model of several sessions, given with its MultipleSessionsInfo, named in the same way.
  • The model of a single session, given without a session info, with no symbol name of a session in the names, such as expected_value.

A model of one's own around the model of several sessions or of a single session can return what they return, and its returned values are then read in the same way.

The trajectories each session saved, as its SaveHistorys selected, are one entry for each name, with the session's symbol name first. The cognitive model's values are named after the attribute alone, since a model uses a name for one attribute only: a state as P1.expected_value, an observation as P1.reward and an action as P1.choice. An action distribution is named like its action, so it is under its kind, as P1.action_distributions.choice. The environment's values are under environment, in the same way: P1.environment.level for a state, P1.environment.reward for an observation it gave, P1.environment.choice for an action it received and P1.environment.observation_distributions.reward. Each entry holds a vector over the timesteps for every sample, which starts with timestep 0 when the initial timestep values are saved, so that element t + 1 is timestep t, as everywhere in the package. The observations, the actions and the distributions of timestep 0 are BeforeFirstTimestep, so a summary of those entries needs timestep 0 left out. The symbol name of a session with several session columns joins the name and the value of each column, as in id_S1__block_2, as CognitiveModeling.session_id_to_symbol gives it. iter_indices and chain_indices number the samples as the chain that was fitted does.

The third form takes one of the three models and a chain sampled from it, a FlexiChain. It runs a copy of the model whose sessions save what the two save histories select on every sample, and makes the chain of the returned values, numbered as chain is. A fit is fastest when its sessions save nothing, and their trajectories are then read afterwards in this way. Selecting anything in environment_save_history makes every session run its environment, see SessionInfo. Each inference backend has a method of this form for its own models, which needs its package to be loaded, and its documentation says which models it takes.

CognitiveModeling.predict_session_trajectories — Function
predict_session_trajectories([rng,] model, chain;
                             cognitive_save_history=SaveHistory(),
                             environment_save_history=SaveHistory())

Simulate the sessions of model, an inference backend's model of fitted sessions, again with the parameters of every sample in chain, and return the trajectories they saved for every sample. This can be used for prior and posterior predictive checks.

The sessions are prepared with prepare_for_prediction, so that every action is simulated, and every observation too when the sessions have an environment, and they save what the two save histories select. The model of those sessions then runs once for each sample, with the sample's parameters, and any start that a model samples, and with every variable within the timesteps drawn again, as data is in a predictive check: an action imputed in the fit is simulated like the others. The trajectories the sessions return are kept. The sessions have at most the number of timesteps of their data, and fewer when a stopping_criterion of a model is met, since no timestep of a predictive session has data. For a prior predictive check, give a chain sampled from the prior.

Each inference backend has methods for its own models and chains, which need its package to be loaded. Which models they take, and the form of the chain they return, are described in the documentation of the inference backend.

CognitiveModeling.prepare_for_prediction — Method
prepare_for_prediction(session_info; check_stopping_criterion=nothing)
prepare_for_prediction(sessions_info; check_stopping_criterion=nothing)

Return a copy of a SessionInfo, or of every session in a MultipleSessionsInfo, where every action is MissingValue, and every observation too when the session has an environment model that it can include, so that an inference backend's model of the copy simulates them instead of fitting to them. This can be used for predictive checks: evaluating the model of the copy with the samples of a fit to the sessions, or sampling it from its prior, simulates each session again, with the same number of timesteps at most, the same settings and the same environment. The observations of a session without an environment stay those in the data, as for an experiment whose observations are fixed in advance. Every action is simulated, whatever it was in the data, also one that was UnimputedMissingValue or NoValue. The copy checks the stopping_criterion of the models as check_stopping_criterion says, as for SessionInfo, whatever the session was prepared with: by default after the last timestep with data, which in a session with an environment is before every timestep, so that the copy can end before the data did, as a simulation does.
