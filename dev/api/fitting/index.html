Fitting

The sessions to fit, with their data, models and settings, how the parameters of several sessions are given, and what runs after them, which are the same for every inference backend. A backend fits several sessions with a full model in three parts: a session parameter model gives or samples the parameters of every session, for the cognitive model and for the environment model, the sessions run with them, and a downstream model can use the trajectories the sessions saved. Each backend has a page of its own, with the models it makes and what a model can add for it: Fitting with Turing.jl.

Sessions and settings

CognitiveModeling.AbstractDownstreamModel — Type
AbstractDownstreamModel

Supertype for downstream models: the final submodel of a full model, which is run after the sessions with the trajectories they saved, such as for correlations with other kinds of data, or a regression of a measurement on a state. NoDownstreamModel is the default.

Implementation

Create a subtype, and for each inference backend it is used with, add a method of that backend's function for downstream models, as the backend's documentation describes.

source
CognitiveModeling.MissingValue — Type
MissingValue()

Stand-in for an action or an observation that happened on a timestep but isn't in the data, and which fitting imputes, as one entry of a column or a NamedTuple, such as (; choice = MissingValue()). Whether it is an action or an observation is given by where it is.

Fitting imputes a missing action by sampling it from the model's action distribution on that timestep. It imputes a missing observation from what an environment model gives for the observation on that timestep: as a latent variable with that distribution, or as the value of a Deterministic. A value that isn't in the data and isn't to be imputed is UnimputedMissingValue instead. NoValue is different: it says that nothing was done or observed on the timestep. Unlike missing, arithmetic on it is an error. By default, a SessionInfo replaces missing in the data by it.

CognitiveModeling.MultipleSessionsInfo — Type
MultipleSessionsInfo(cognitive_model, table; observation_columns, action_columns,
                     session_columns, <keyword arguments>)
MultipleSessionsInfo(sessions, session_ids; table=nothing, session_rows=nothing)

Multiple behavioral sessions in a generative model that are fitted together, as a vector of SessionInfo with an identifier for each, which an inference backend's models of several sessions take.

The first form splits a table into sessions. table is a NamedTuple with one vector for each column, or any other table that Tables.jl can read, such as a DataFrame or a CSV.File, whose columns are read when Tables.jl is loaded, as it is with DataFrames.jl and CSV.jl. The values of a column that stand for a missing observation or action become MissingValue, as for SessionInfo: by default those that are missing. Every session must come out with the same type, which they do when they share the models and the settings, since the timesteps of different sessions are then compiled once. As for SessionInfo, a session includes its environment where an observation or an action is MissingValue(), where environment_save_history saves anything or where check_stopping_criterion is true, and in an inference backend's full model that estimates the environment's parameters, unless include_environment says otherwise. The table is kept in the field table, without being copied, with the rows of each session in session_rows, so that a session parameter model can read the columns it needs, such as those that a GroupedHierarchicalSessionParameters groups the sessions by.

MultipleSessionsInfo(sessions_info; cognitive_save_history, environment_save_history)

The same sessions with other save histories for every one, see SessionInfo.

Arguments

  • cognitive_model::AbstractTimestepModel: the cognitive model, usually an AbstractCognitiveModel.
  • table: the data of every session, in columns with one entry for each timestep, such as (; id = ["S1", "S1", "S2", "S2"], reward = [1.0, 0.0, 1.0, 1.0], choice = [true, false, true, true]), or a DataFrame with those columns.

Keyword arguments

  • observation_columns: the columns with the observations. When the model has only one kind of observation in its attributes, a single name, such as :outcome, is its column, whatever the observation is called. Several observations are given in a tuple, each as the name the model lists in attribute_names when the column is named the same, or as a pair from the column's name to the model's, as in a NameMap, such as (:outcome => :reward, :cue), so that one model fits tables with other names. A single name that the model lists as one of its actions is an error, since the two keyword arguments may then be swapped. An observation or action whose value is composed from several columns is specified by how to build it from the columns, followed by the model's name: a Tuple of column names for a Tuple in each row, (:choicecol, :rtcol) => :ssm_action, a NamedTuple of column names for a NamedTuple, (; choice = :choicecol, rt = :rtcol) => :ssm_action, or a Tuple of column names and a function of their values, which needs parentheses around it, (:choicecol, :rtcol) => ((choice, rt) -> [choice, rt]) => :ssm_action. When the model has only one kind of them in its attributes, the name can be left out of the last two, as in (; choice = :choicecol, rt = :rtcol). A missing value in any of the columns makes the whole value missing.
  • action_columns: the columns with the actions, in the same forms.
  • session_columns: the column or columns which separate sessions, such as :id or (:id, :block). A session is every row with one combination of their values, in the order of the first row of each. The identifier of a session is its value in a single column, or a NamedTuple of its values in several.
  • timestep_sizes=1: how much time each timestep covers, as one size for all, or the name of a column with the size of each timestep.
  • missing_observation_values=(missing,), missing_action_values=(missing,), impute_missing_observations=true and impute_missing_actions=true: the values in the columns which stand for a missing observation or action, and whether those are imputed, as for SessionInfo. They are marked in the whole table before it is split, so that the columns of every session have the same element types.
  • The other keyword arguments of SessionInfo, which every session gets.

The second form takes sessions that are already prepared. They have no table, unless it is given as table, with the rows of each session in it as session_rows, a vector of vectors of row numbers. Each argument is kept in a field of the same name.

In the REPL, the sessions show a summary on one line each: how many there are, and the models and the names in the data of the first.

Examples

julia> struct Counter <: AbstractCognitiveModel end

julia> CognitiveModeling.attribute_names(::Counter) = ModelAttributes(; parameters = :probability, states = :n_timesteps, inputs = :reward, outputs = :choice);

julia> table = (; id = ["S1", "S1", "S2", "S2", "S2"], outcome = [1.0, 0.0, 1.0, 1.0, 0.0], choice = [true, false, true, missing, false]);

julia> sessions_info = MultipleSessionsInfo(Counter(), table; observation_columns = :outcome => :reward, action_columns = :choice, session_columns = :id, who_starts = EnvironmentStarts())
MultipleSessionsInfo
Sessions: 2
Cognitive model: Counter
Environment: none
Observations: reward
Actions: choice

julia> sessions_info.session_ids
2-element Vector{String}:
 "S1"
 "S2"

julia> sessions_info.sessions[2].actions
(choice = Union{MissingValue, Bool}[true, MissingValue(), false],)

A DataFrame is given in the same way:

julia> using DataFrames

julia> data = DataFrame(id = ["S1", "S1", "S2", "S2"], reward = [1.0, 0.0, 1.0, 1.0], choice = [true, missing, false, true]);

julia> sessions_info = MultipleSessionsInfo(Counter(), data; observation_columns = :reward, action_columns = :choice, session_columns = :id, who_starts = EnvironmentStarts());

julia> sessions_info.sessions[1].actions
(choice = Union{MissingValue, Bool}[true, MissingValue()],)

CognitiveModeling.SessionInfo — Type
SessionInfo(cognitive_model, observations, actions; who_starts, <keyword arguments>)

Everything about one behavioral session that is fixed within a generative model to be fitted: the data, the models and the settings, checked and prepared once. An inference backend's model of the session takes it together with the parameters, which are what changes between evaluations. MultipleSessionsInfo makes one for each session in a table.

Arguments

  • cognitive_model::AbstractTimestepModel: the cognitive model, usually an AbstractCognitiveModel.
  • observations: the observations in the data, as a NamedTuple with one vector for each name and one entry for each timestep, such as (; reward = [1.0, 0.0, 1.0]). The data must have every observation the model lists in attribute_names, and can have more. When the model has only one kind of observation in its attributes, a single vector, [1.0, 0.0, 1.0], is the data of that observation, whatever its name. An observation that wasn't recorded is MissingValue, which environment imputes unless impute_missing_observations is false, and one that wasn't made is NoValue.
  • actions: the actions in the data, in the same forms, with exactly the actions the model lists. An action that was taken but not recorded is MissingValue(), which is imputed unless impute_missing_actions is false, and an action that wasn't taken is NoValue(). Neither is scored.

Keyword arguments

  • who_starts::Union{AgentStarts, EnvironmentStarts}: whether the model acts on the observation of the same timestep, EnvironmentStarts(), or on the observation of the timestep before, AgentStarts(), as in simulate. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • environment::Union{NoEnvironment, AbstractTimestepModel}=NoEnvironment(): an environment model, usually an AbstractEnvironmentModel, which imputes the observations that are MissingValue(), and against whose distributions the observations in the data are scored. Its outputs must be the inputs of cognitive_model and the other way round, directly or through observation_map and action_map. Without it, the data can't have observations that are MissingValue(). Whether the session includes it is decided by include_environment, and it is kept in the session either way.
  • include_environment::Union{Nothing, Bool}=nothing: whether the session includes environment, so that it runs on every timestep. By default, with nothing, it is included where an observation or an action is MissingValue(), where environment_save_history saves anything, or where check_stopping_criterion is true: the scored observations then inform what is imputed, such as which arm of a bandit a missing choice was, from the reward that followed. It is also included in every session of an inference backend's full model that estimates the environment's parameters, so that the observations inform them. Otherwise it is left out, since the scores of its observations would be the same for every value of the parameters, and the session has none of its variables. With true it is always included, such as for a model of one's own which estimates its parameters. With false it never is: an observation that is MissingValue(), a selection in environment_save_history and check_stopping_criterion = true are then errors, and an action that is MissingValue() is imputed without the observations informing it.
  • observation_map::Union{Nothing, NameMap}=nothing and action_map::Union{Nothing, NameMap}=nothing: which observations of environment the cognitive model receives, and which of its actions the environment receives, and under which names, as NameMaps, as for simulate. The data is in the cognitive model's names, and is scored against the environment's distributions as the map passes them on. An output of the environment that the map doesn't pass on isn't in the data, so it is imputed on every timestep. Each model's history is in its own names.
  • timestep_sizes=1: how much time each timestep covers, as in simulate.
  • cognitive_save_history::SaveHistory=SaveHistory(): which states, inputs, outputs and output distributions of cognitive_model a fitted session returns, by name, and whether timestep 0 is, as a SaveHistory in the model's own names. Nothing is selected by default. What is returned names them by their role, as states, observations, actions and action_distributions, as simulate does.
  • environment_save_history::SaveHistory=SaveHistory(): the same for environment, whose inputs are the actions and whose outputs are the observations, returned under environment. Selecting anything makes the environment run in the session, also when nothing is missing, which adds its scores of the observations to the log density; with fixed environment parameters they are the same for every value of the cognitive parameters, so the posterior is unchanged. Whether timestep 0 is saved follows cognitive_save_history.
  • check_stopping_criterion::Union{Nothing, Bool}=nothing: when the stopping_criterion of the two models is checked before a timestep, so that the session ends there, with what it saved up to it. With nothing, it is checked on the timesteps after the last one with data. With true, it is checked before every timestep, and a criterion that is met while the data continues is an error. With false, it is never checked. The extended help says why.
  • missing_observation_values=(missing,) and missing_action_values=(missing,): the values in the data which stand for a missing observation or action, in a tuple or a vector, such as (missing, -1). Each is replaced by MissingValue(). A value is compared to them with isequal, and () keeps every value as it is, missing too. MissingValue() can also be put in the data directly.
  • impute_missing_observations::Bool=true and impute_missing_actions::Bool=true: whether the observations and the actions that are MissingValue() are imputed, as latent variables. With false, nothing is sampled for them, and they are replaced by UnimputedMissingValue here, which the models receive as it is.
  • previous_observation and previous_action: what the first timestep receives as the observation and the action before it, in the cognitive model's names, with BeforeFirstTimestep for each name by default, as in simulate. The environment starts from the same observation in its own names, with BeforeFirstTimestep() for an output that observation_map doesn't pass on. The states where the session starts are not given here, since they come from initialize_state with the parameters that are fitted.

Each argument is kept in a field of the same name, except the values that stand for a missing one and whether they are imputed, whose work is done in the data here. The other fields are includes_environment, whether the session includes the environment, as include_environment decides it, environment_observations, the data of the environment's outputs in its own names, previous_environment_observation, the observation the environment starts from in its own names, recorded_actions and recorded_observations, the recorded values of each name which are scored, the observations in the environment's names, n_timesteps, saved_timestep_sizes, the sizes a fitted session returns with what it saves, and first_timestep_to_check_stopping, the first timestep before which the stopping criterion is checked, as check_stopping_criterion decides it.

SessionInfo(session_info; cognitive_save_history, environment_save_history)

Update a session to have other save histories, which returns a new SessionInfo. This is for after a fit: a session is fitted fastest when it saves nothing, and its states, or anything else it can save, are read afterwards from the updated session, by evaluating its model with each sample of the fit. The two models have the same variables, so every sample fits both. The documentation of each inference backend describes how.

In the REPL, a session shows a summary on one line each: its models, its number of timesteps, the names of the observations and the actions in its data, which are the cognitive model's names, and who starts.

Examples

julia> struct Counter <: AbstractCognitiveModel end

julia> CognitiveModeling.attribute_names(::Counter) = ModelAttributes(; parameters = :probability, states = :n_timesteps, inputs = :reward, outputs = :choice);

julia> session_info = SessionInfo(Counter(), (; reward = [1.0, 0.0, missing]), (; choice = [true, missing, false]); who_starts = EnvironmentStarts(), impute_missing_observations = false)
SessionInfo
Cognitive model: Counter
Environment: none
Timesteps: 3
Observations: reward
Actions: choice
Who starts: environment

julia> session_info.observations.reward[3], session_info.actions.choice[2]
(UnimputedMissingValue(), MissingValue())

julia> session_info.recorded_actions
(choice = Bool[1, 0],)

Extended help

When the stopping criterion is checked follows from the data. The last timestep with data is the last one where an observation or an action isn't MissingValue(). With check_stopping_criterion = nothing, the criterion is only checked after it, so that a fit, where every timestep has data, never checks it, and a session prepared by prepare_for_prediction, whose data is all MissingValue(), ends as a simulation does. With true, the session includes its environment, whose criterion is checked too. A criterion that is met while the data continues is then an error, since the recorded values after that timestep couldn't be scored, which checks that the models agree with the length of the data.

CognitiveModeling.UnimputedMissingValue — Type
UnimputedMissingValue()

Stand-in for an action or an observation that happened on a timestep but isn't in the data, and which fitting doesn't impute, as one entry of a column or a NamedTuple, such as (; reward = UnimputedMissingValue()).

Nothing is sampled or scored for it, and the models receive it as it is: a cognitive model as its observation, or as its previous action on the next timestep, and an environment model as the action it responds to. A model which is fitted to such data must handle it, as it does the other subtypes of AbstractNoValue. Useful for a session without an environment model whose data lacks some observations, and for missing actions which shouldn't become latent variables. A SessionInfo puts it in place of the missing observations with impute_missing_observations = false, and of the missing actions with impute_missing_actions = false.

CognitiveModeling.prepare_for_prediction — Method
prepare_for_prediction(session_info; check_stopping_criterion=nothing)
prepare_for_prediction(sessions_info; check_stopping_criterion=nothing)

Return a copy of a SessionInfo, or of every session in a MultipleSessionsInfo, where every action is MissingValue, and every observation too when the session has an environment model that it can include, so that an inference backend's model of the copy simulates them instead of fitting to them. This can be used for predictive checks: evaluating the model of the copy with the samples of a fit to the sessions, or sampling it from its prior, simulates each session again, with the same number of timesteps at most, the same settings and the same environment. The observations of a session without an environment stay those in the data, as for an experiment whose observations are fixed in advance. Every action is simulated, whatever it was in the data, also one that was UnimputedMissingValue or NoValue. The copy checks the stopping_criterion of the models as check_stopping_criterion says, as for SessionInfo, whatever the session was prepared with: by default after the last timestep with data, which in a session with an environment is before every timestep, so that the copy can end before the data did, as a simulation does.

Examples

julia> struct Counter <: AbstractCognitiveModel end

julia> CognitiveModeling.attribute_names(::Counter) = ModelAttributes(; parameters = :probability, states = :n_timesteps, inputs = :reward, outputs = :choice);

julia> session_info = SessionInfo(Counter(), [1.0, 0.0, 1.0], [true, false, true]; who_starts = EnvironmentStarts());

julia> prepare_for_prediction(session_info).actions
(choice = [MissingValue(), MissingValue(), MissingValue()],)

Session parameter models

CognitiveModeling.AbstractSessionParametersModel — Type
AbstractSessionParametersModel

Supertype for session parameter models: the part of a full model, the model that an inference backend fits to several sessions, which gives or estimates the parameters of every session, for the cognitive model and for the environment model alike. The package comes with NoParameters, FixedSessionParameters, FixedParametersBySession, IdenticalSessionParameters, IndependentSessionParameters and GroupedHierarchicalSessionParameters, and CompositeSessionParameters combines several, each giving some of the parameters.

Implementation

Create a subtype, and for each inference backend it is used with, add a method of that backend's function for session parameter models, as the backend's documentation describes. A method of CognitiveModeling.parameter_names lets the parameters it gives be checked before a fit, and a method of CognitiveModeling.prepare_parameters_model lets it work out once, before the backend's model is made, what doesn't change between evaluations. A model which only gives values, and estimates nothing, adds a method of CognitiveModeling.estimates_parameters.

source

CognitiveModeling.FixedParametersBySession — Type
FixedParametersBySession(parameters_by_session)

The session parameter model of a full model which gives each session values of its own, with nothing sampled. parameters_by_session holds the values of each session, either in a NamedTuple with an entry for each session, named by the session's name as CognitiveModeling.session_name gives it, such as (; S1 = (; scale = 2.0), S2 = (; scale = 3.0)), or in a dictionary from each session's identifier to its values, such as Dict("S1" => (; scale = 2.0), "S2" => (; scale = 3.0)). An identifier from several session columns is the NamedTuple of their values, so its entry is named like id_S1__block_2, and its key is like (; id = "S1", block = 2). Every session must have values for the same parameters. The values can also be given in the order of the sessions, as a NamedTuple with one vector for each parameter, such as (; scale = [2.0, 3.0]), which is what a full model makes of the other two forms once, before it is made, so that no session is looked up when it runs. The values are kept in the field parameters_by_session.

CognitiveModeling.IdenticalSessionParameters — Type
IdenticalSessionParameters(priors)

The session parameter model of a full model which samples each parameter once, from its prior, and gives every session that value. priors is a NamedTuple with the name of each parameter that is fitted and the distribution it is sampled from, such as (; learning_rate = Beta(2, 2)). The priors are kept in the field priors.

CognitiveModeling.IndependentSessionParameters — Type
IndependentSessionParameters(priors)

The session parameter model of a full model which samples each parameter for every session from the same prior, with nothing shared between the sessions. priors is a NamedTuple with the name of each parameter that is fitted and the distribution it is sampled from, such as (; learning_rate = Beta(2, 2), inverse_temperature = LogNormal(0, 1)). The priors are kept in the field priors.

source
CognitiveModeling.GroupedHierarchicalSessionParameters — Type
GroupedHierarchicalSessionParameters(parameters)

The session parameter model of a full model which samples each parameter of every session from a group-level distribution, whose own parameters are sampled from priors, once for each group of sessions. parameters is a NamedTuple with a HierarchicalParameter for each parameter that is fitted, which has its priors, its group-level distribution, its transformation and the columns that group the sessions, so the parameters can be grouped by different columns. It is kept in the field parameters.

A full model finds the group of every session once, before it is made, from the table that MultipleSessionsInfo keeps, so sessions that were prepared one at a time can only be in one group. The field groups is nothing until then, and afterwards has, for each parameter, the group of every session, group_of_each_session, the number of groups, n_groups, and the name of each group, group_names.

Examples

using Turing
using LogExpFunctions: logistic

session_parameter_model = GroupedHierarchicalSessionParameters((;
    learning_rate = HierarchicalParameter(
        (; mean = Normal(0, 1), sd = Exponential(1));
        transformation = logistic,
        group_by = :diagnosis,
    ),
    inverse_temperature = HierarchicalParameter(
        (; mean = Normal(0, 1), sd = Exponential(1)); transformation = exp
    ),
))

CognitiveModeling.HierarchicalParameter — Type
HierarchicalParameter(priors; distribution=nothing, transformation=identity,
                      group_by=nothing, centered=nothing)

How one parameter of a GroupedHierarchicalSessionParameters is sampled for every session: from a group-level distribution, whose own parameters are sampled from priors, once for each group of sessions.

Arguments

  • priors::NamedTuple: the priors of the parameters of the group-level distribution, in the order in which the distribution takes them, such as (; mean = Normal(0, 1), sd = Exponential(1)). Their names name the variables of the group-level parameters.

Keyword arguments

  • distribution=nothing: the group-level distribution, as a function of its parameters, such as Normal or (location, scale) -> Laplace(location, scale). nothing is a normal distribution, whose two priors are those of its mean and its standard deviation.
  • transformation=identity: a function applied to the value of each session after it is sampled, such as exp for a parameter that must be positive or logistic for one between 0 and 1, as an inverse link function does in a regression.
  • group_by=nothing: a column of the table that the sessions were split from, or a tuple of columns, whose values group the sessions, so that each group has a group-level distribution of its own, such as :diagnosis for a clinical and a non-clinical group. Each session must have one value of each of the columns. Groups are numbered in the order of their first session. With nothing, every session is in one group.
  • centered=nothing: for the default normal distribution, whether the value of each session is sampled from the distribution of its group, with true, or as a standardized value which the group's mean shifts and its standard deviation scales, with false, which is the default, since it usually samples better when the data of a session informs its parameters little. Any other distribution is always sampled from directly, and giving centered with one is an error.

Each argument is kept in a field of the same name, with group_by as a tuple of column names, which is empty for one group, centered as true or false, and a distribution that is given as a type inside a function which makes it.

Examples

julia> using Distributions: Normal, Exponential

julia> learning_rate = HierarchicalParameter((; mean = Normal(0, 1), sd = Exponential(1)); transformation = exp, group_by = :diagnosis);

julia> learning_rate.group_by, learning_rate.centered
((:diagnosis,), false)

CognitiveModeling.CompositeSessionParameters — Type
CompositeSessionParameters(parts...)

The session parameter model of a full model which gives some of the parameters with each of parts, which are session parameter models, such as a GroupedHierarchicalSessionParameters for the learning rate, an IndependentSessionParameters for the inverse temperature and a FixedSessionParameters for a bias. What the parts give is merged, and the variables of each part are named as that part names them. No two parts can give the same parameter: this is checked when it is made, for the parts whose CognitiveModeling.parameter_names are known, and when it runs, for the others. It samples when any part does. The parts are kept in the field parts, as a tuple.

Examples

using Turing

session_parameter_model = CompositeSessionParameters(
    IndependentSessionParameters((; learning_rate = Beta(2, 2))),
    FixedSessionParameters((; inverse_temperature = 2.0)),
)

Functions that a session parameter model can implement

A session parameter model of one's own can add methods of these. They are public, but not exported.

CognitiveModeling.parameter_names — Function
parameter_names(parameters_model)

Return the names of the parameters that parameters_model gives every session, as a tuple of Symbols, or nothing when they aren't known before it runs. prepare_full_model checks them against the parameters of the cognitive model and of the environment model, and CompositeSessionParameters checks that no two of its parts give the same one.

Implementation

A session parameter model of one's own can add a method of this function. The default returns nothing, so that nothing is checked before a fit.

Examples

julia> CognitiveModeling.parameter_names(FixedSessionParameters((; scale = 2.0, offset = 0.0)))
(:scale, :offset)

CognitiveModeling.estimates_parameters — Function
estimates_parameters(parameters_model)

Return whether parameters_model, a session parameter model, estimates the parameters it gives from the data, instead of being given their values: false for NoParameters, FixedSessionParameters and FixedParametersBySession, whether any part does for a CompositeSessionParameters, and true for every other kind. When the environment's parameters are estimated, a full model includes the environment in every session, so that the observations in the data inform them, and it warns when the parameters of the two models can have the same variables.

Implementation

A session parameter model of one's own can add a method of this function. The default returns true, and a model which only gives values returns false.

Examples

julia> CognitiveModeling.estimates_parameters(FixedSessionParameters((; scale = 2.0)))
false

CognitiveModeling.prepare_parameters_model — Function
prepare_parameters_model(parameters_model, sessions_info)

Return parameters_model prepared for the sessions in sessions_info, with what doesn't change between the evaluations of an inference backend's model worked out once, before the model is made. A FixedParametersBySession has the values of every session looked up, a GroupedHierarchicalSessionParameters has the group of every session found, and a CompositeSessionParameters has each of its parts prepared. Used by prepare_full_model.

Implementation

A session parameter model of one's own can add a method of this function, which returns a session parameter model that the inference backends have methods for. The default returns parameters_model as it is.

Preparing a full model

This is what an inference backend calls before it makes its full model. It is public, but not exported.

CognitiveModeling.prepare_full_model — Method
prepare_full_model(cognitive_parameters_model, sessions_info::MultipleSessionsInfo;
                   environment_parameters_model=NoParameters(),
                   downstream_model=NoDownstreamModel(),
                   fixed_cognitive_parameters=(;),
                   fixed_environment_parameters=(;))

Prepare the parts of a full model once, before an inference backend makes its model of them, and return them in a NamedTuple with cognitive_parameters_model, environment_parameters_model, downstream_model and sessions_info. Useful for an inference backend, whose full model calls it, so that what doesn't change between the evaluations of the model is worked out once.

It checks that the two session parameter models and the downstream model are of the right kind. The values in fixed_cognitive_parameters and fixed_environment_parameters, such as (; initial_value = 0.3), are given to every session for the parameters they name: each session parameter model is combined with them in a CompositeSessionParameters, so a parameter is either fixed or given by its session parameter model, and a fixed parameter must be one that the model lists. It checks the parameters that each session parameter model gives, when CognitiveModeling.parameter_names knows them, against those of the cognitive model and of the environment model: a parameter that the model doesn't list is an error, and so is one that the model lists which is neither given nor has a default value, unless it is a parameter of an environment that no session runs. It prepares each session parameter model for the sessions with CognitiveModeling.prepare_parameters_model. When the environment's parameters are sampled, every session with an environment runs it, so that the observations in the data inform them.

CognitiveModeling.session_index — Function
session_index(sessions_info, session_id)

Return the index i of the session with the identifier session_id in a MultipleSessionsInfo, which is how the models of several sessions number it: its parameters are element i of each vector a session parameter model gives, and its saved trajectories are element i of what the sessions return. The identifier is the value in the session column, or a NamedTuple of the values when there are several, as in sessions_info.session_ids. Used by users reading the results of a fit, not by the models.

CognitiveModeling.session_name — Function
session_name(session_id)

Return the name of a session, as a Symbol, from its identifier: the value of a single session column, as in S1, and the name and the value of each of several columns, joined by _ within a column and by __ between columns, as in id_S1__block_2. The chains of a fit name the entries of a session after it, such as S1.learning_rate, and FixedParametersBySession can find the values of a session by it.

A name that isn't a valid Julia identifier, such as that of the identifier 1 or "sub-01", can't be typed into a VarName, but interpolation puts in any name: after using CognitiveModeling: session_name, the learning rate of a session is chain[@varname($(session_name(session_id)).learning_rate)].

Examples

julia> CognitiveModeling.session_name("S1")
:S1

julia> CognitiveModeling.session_name((; id = "S1", block = 2))
:id_S1__block_2

CognitiveModeling.session_column_values — Function
session_column_values(sessions_info, column)

Return the values of column in the table that the sessions in sessions_info were split from, as one vector for each session, of its rows in the table. It is an error when the sessions were given already prepared, without a table, and when the table has no such column. Useful for a session parameter model that reads a column, such as one to group the sessions by, or the covariate of a regression. Used by group_sessions.
