CognitiveModeling.AgentStarts — Type
AgentStarts()

Make the agent move first on each timestep of a simulation or a fitted session.

On a timestep, the cognitive model updates and acts on the previous observation, and the environment then responds to its action. On the first timestep, the cognitive model receives an observation with every entry BeforeFirstTimestep. Both models receive it as the who_starts of their ModelContext, so that a cognitive model can act before it updates when that is what it means.

See also EnvironmentStarts, UnknownWhoStarts, simulate and SessionInfo.

CognitiveModeling.BeforeFirstTimestep — Type
BeforeFirstTimestep()

Stand-in for an observation or an action from before the first timestep, when there is none yet, as one entry of a NamedTuple, such as (; choice = BeforeFirstTimestep()).

A model receives it for every previous output on its first timestep, and for every input too when the other side hasn't moved yet: a cognitive model when the agent starts, and an environment model when the environment starts. NoObservation and NoAction are different: they say that nothing was observed or done on a timestep that did run.

Before the first timestep is timestep 0, which a simulation, a history and a fitted session start with when their SaveHistory saves the initial values, as it does by default. Its observation and action are this marker unless others are given, and so is its size.

CognitiveModeling.Deterministic — Type
Deterministic(value)

An action or an observation that is always value, for a cognitive model or an environment model which gives it without any randomness, as in (; reward = Deterministic(1.0)).

A simulation samples every action and every observation with rand, and sampling from a Deterministic gives value itself. The value is kept in the field value.

A simulation throws an error for a number, a string or a symbol that isn't wrapped, since none of them is something to sample from. A vector, a tuple or a range that isn't wrapped is sampled from as it is, which is rarely what is meant: rand picks one of its elements, with no error.

Examples

julia> using Random: Xoshiro

julia> rand(Xoshiro(1), Deterministic(1.0))
1.0

julia> ModelOutput((; choice = Deterministic(true))).output_distribution.choice.value
true

InvalidParametersError(message)
InvalidParametersError()

An error for a model to throw from apply_model or initialize_state when its parameters aren't valid, as in throw(InvalidParametersError()).

The default message says that the parameters are not valid, possibly dependent on the observations, actions and states, and a model can give a more specific one. A simulation stops with it as with any other error, and fitting can catch it to give the parameters a probability of zero, so a model should throw this rather than an ordinary error when the parameters are the problem.

CognitiveModeling.ModelContext — Type
ModelContext(input, previous_state, previous_output, parameters, timestep_size=1,
             rng=default_rng(), who_starts=UnknownWhoStarts())

Everything a model needs to run a single timestep, which apply_model receives.

Each argument is kept in a field of the same name, such as context.input. For a cognitive model the input is its observation and the output its action, and for an environment model the input is the action of the cognitive model and the output the observation it gives.

Arguments

  • input: what the model receives on this timestep, in a NamedTuple with the names the other side gave the entries, as in context.input.reward. An entry that isn't there on this timestep is NoObservation or NoAction. On the first timestep, when the other side hasn't moved yet, every entry is BeforeFirstTimestep.
  • previous_state: the state of the model after the previous timestep. On the first timestep, this is the output of initialize_state.
  • previous_output: what the model gave on the previous timestep, in a NamedTuple with the names the model gave the entries, as in context.previous_output.choice. On the first timestep, each of them is BeforeFirstTimestep.
  • parameters: the parameters of the model, in a NamedTuple.
  • timestep_size=1: how much time this timestep covers.
  • rng=default_rng(): the random number generator to sample from if anything in the model is random, so that a simulation can be reproduced.
  • who_starts=UnknownWhoStarts(): who moves first on the timestep, AgentStarts or EnvironmentStarts as the simulation or the fitted session was told, or UnknownWhoStarts when neither is known. A model which can update before it acts or act before it updates can choose by it: for a cognitive model, with EnvironmentStarts() the input is this timestep's observation, and with AgentStarts() the previous timestep's. It is kept in the type, so that choosing costs nothing.

Examples

julia> input = (; reward = 1.0);

julia> state = (; expected_reward = 0.5);

julia> parameters = (; learning_rate = 0.1);

julia> previous_output = (; choice = BeforeFirstTimestep());

julia> ModelContext(input, state, previous_output, parameters).timestep_size
1

julia> ModelContext(input, state, previous_output, parameters, 0.5).timestep_size
0.5

julia> ModelContext(input, state, previous_output, parameters).who_starts
UnknownWhoStarts()

CognitiveModeling.ModelOutput — Type
ModelOutput(output_distribution, new_state=(;))

The outputs of a model for a single timestep, which apply_model returns.

Each argument is kept in a field of the same name, such as output.new_state.

Arguments

  • output_distribution::NamedTuple: what the model's outputs on this timestep are sampled from, in a NamedTuple with one entry for each output, such as (; choice = Bernoulli(0.7)) for the action of a cognitive model, or (; reward = Bernoulli(0.8)) for the observation an environment model gives. Each entry can be anything that works with rand, such as a distribution from Distributions.jl, or a Deterministic for an output that isn't random, and the sampled outputs keep the names. An output that isn't given on this timestep is NoAction for a cognitive model and NoObservation for an environment model, and a model without outputs gives an empty NamedTuple, (;).

CognitiveModeling.CommonRLEnvironment — Type
CommonRLEnvironment(rl_env; action_name)

An environment model around rl_env, an environment from CommonRLInterface.jl, which needs CommonRLInterface.jl to be loaded. action_name is the name of the cognitive model's action that act! receives, such as :arm.

Environments from POMDPs.jl and ReinforcementLearning.jl can be used through it, with convert(CommonRLInterface.AbstractEnv, x), which POMDPTools.jl defines for a POMDP or MDP and ReinforcementLearningBase.jl for its environments.

rl_env itself is the state: initialize_state resets it with CommonRLInterface.jl's reset! and returns it, every timestep changes it in place with act! and passes it on as the new state, and prepare_state_for_saving copies it, with clone if it provides it and with deepcopy otherwise. A method of prepare_state_for_saving for a CommonRLEnvironment with a specific type of rl_env can save something lighter. The parameters aren't used, and neither is the random number generator, since an environment of CommonRLInterface.jl has its own randomness.

Each observation is a NamedTuple (; observation, reward, terminated): what observe gives, the reward that act! returned, and whether the episode has ended. They are given as they are, each in a Deterministic, so nothing more is sampled. Before the first action, when the action is BeforeFirstTimestep, the environment is at its initial observation, so the reward is NoObservation and nothing is done with the action. The same goes for a timestep where the model takes no action, NoAction: the environment stays where it is. Its attribute_names are these three observations, the one action, no parameters and no states, since rl_env isn't a NamedTuple. Use EnvironmentStarts, so that the model observes before it acts.

A simulation stops by itself when the episode ends, since the stopping_criterion of the environment is terminated of rl_env, so n_steps is the most timesteps it can take. An episode that has ended isn't started again, and an action given to it throws an error. A new call of simulate starts a new episode, and so does reset! of an InstantiatedModel, since both reset rl_env through initialize_state.

Examples

using CognitiveModeling
using CommonRLInterface

#A two-armed bandit where the first arm always pays, in episodes of two pulls
mutable struct Bandit <: CommonRLInterface.AbstractEnv
    pulls::Int
end
CommonRLInterface.reset!(rl_env::Bandit) = (rl_env.pulls = 0; nothing)
CommonRLInterface.actions(rl_env::Bandit) = 1:2
CommonRLInterface.observe(rl_env::Bandit) = rl_env.pulls
CommonRLInterface.act!(rl_env::Bandit, arm) = (rl_env.pulls += 1; arm == 1 ? 1.0 : 0.0)
CommonRLInterface.terminated(rl_env::Bandit) = rl_env.pulls == 2

#A model which always pulls the first arm
struct PullsFirstArm <: AbstractCognitiveModel end
CognitiveModeling.initialize_state(model::PullsFirstArm, parameters) = (;)
CognitiveModeling.apply_model(model::PullsFirstArm, context::ModelContext) = ModelOutput((; arm = Deterministic(1)))
CognitiveModeling.attribute_names(model::PullsFirstArm) = ModelAttributes(; parameters = (), states = (), inputs = (:observation, :reward, :terminated), outputs = :arm)

#The simulation stops when the episode ends, before it has run all of n_steps
simulation = simulate(
    PullsFirstArm(),
    CommonRLEnvironment(Bandit(0); action_name = :arm);
    who_starts = EnvironmentStarts(),
    n_steps = 10,
    cognitive_parameters = (;),
    environment_parameters = (;),
    cognitive_save_history = SaveHistory(SaveEverything()),
)

#Timestep 0, before the first timestep, and then what the environment gave on each timestep
foreach(println, simulation.observations)

# output

(observation = BeforeFirstTimestep(), reward = BeforeFirstTimestep(), terminated = BeforeFirstTimestep())
(observation = 0, reward = NoObservation(), terminated = false)
(observation = 1, reward = 1.0, terminated = false)
(observation = 2, reward = 1.0, terminated = true)

CognitiveModeling.SaveHistory — Type
SaveHistory(; states=(), inputs=(), outputs=(), output_distributions=(),
            save_initial_values=true)
SaveHistory(SaveEverything(); save_initial_values=true)

Which states, inputs, outputs and output distributions of a model a simulation or a fitted session saves, by name, and whether it saves them from before the first timestep too.

states, inputs, outputs and output_distributions are each the names of that kind to save, in a Tuple of Symbols, a single Symbol or a Vector of them, or SaveEverything for all of them. The names are the model's own, as attribute_names lists them: for a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it receives and the outputs the observations it gives. The output distributions are what the model gave its outputs to be sampled from, named like the outputs. A kind that isn't given saves nothing, so SaveHistory() saves nothing, which is the default everywhere, and SaveHistory(SaveEverything()) saves everything. The selections are kept in the type, so that selecting costs nothing in a simulation, and are read as properties, such as save_history.states.

save_initial_values is whether what is saved starts with timestep 0, before the first timestep: the initial states, and the previous input and output, which are BeforeFirstTimestep unless others are given. It is true by default, which matters when the initial state depends on parameters that are fitted. Since Julia counts from 1, element t + 1 of what is saved is then timestep t, and with false, element t is.

Saving some names of a kind gives a NamedTuple with those names on each timestep, which only works when the value is a NamedTuple, and saving none gives an empty one, (;), for any value. Before the first timestep there is no output distribution, so timestep 0 has BeforeFirstTimestep() for each name that is saved.

Each model of a simulation has one: simulate and SessionInfo take cognitive_save_history and environment_save_history, and an InstantiatedModel takes save_history. What a simulation or a session returns names the saved values by their role: the cognitive model's inputs as observations and outputs as actions, and the environment's inputs as actions and outputs as observations under environment, as simulate describes.

Examples

julia> save_history = SaveHistory(; outputs = :choice, states = (:expected_reward, :surprise))
SaveHistory
States: expected_reward, surprise
Inputs: none
Outputs: choice
Output distributions: none
Initial values: saved

julia> save_history.states
(:expected_reward, :surprise)

julia> SaveHistory(SaveEverything()).inputs
SaveEverything()

julia> SaveHistory(SaveEverything(); save_initial_values = false).save_initial_values
false

CognitiveModeling.InstantiatedModel — Type
InstantiatedModel(model, parameters; save_history=SaveHistory())
InstantiatedModel(model, parameters, state, previous_output; save_history=SaveHistory())

A cognitive model or an environment model with its parameters, current state and previous output, which simulate! can update iteratively.

Each argument is kept in a field of the same name, such as agent.state. Parameters that aren't given take the values in default_parameters, if the model provides defaults for them. The state defaults to the output of initialize_state with the full parameters, and the previous output to every output being BeforeFirstTimestep. The model must have a method of attribute_names, and the names of the parameters, of the previous output, and of the state when it is a NamedTuple, must be those it lists, or an error is thrown.

agent.history holds a ModelHistory with where the model started, which is timestep 0, and everything that happens to it, as selected by save_history, a SaveHistory. By default nothing is selected and the vectors in agent.history stay empty, and SaveHistory(SaveEverything()) saves everything. Inputs and outputs can only be selected by name among those the model lists, since the history starts from those names.

The same type serves as the agent and as the environment of a simulation, since both are models. See also simulate! and reset!.

CognitiveModeling.ModelHistory — Type
ModelHistory(states, inputs, outputs, output_distributions, timestep_sizes)

What has happened to an InstantiatedModel, which simulate! adds to.

Each argument is kept in a field of the same name, such as history.states. The names are the model's own: for a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it received and the outputs the observations it gave. The model's SaveHistory selects what is kept of each kind, and when it selects nothing at all, the vectors stay empty. Each vector starts with timestep 0, where the model started, when the SaveHistory saves the initial values, which it does by default, so that element t + 1 is timestep t.

Arguments

  • states::Vector{Any}: the states of the model, starting at timestep 0 with its initial state. Later states are those after each timestep. All of them are as returned by prepare_state_for_saving.
  • inputs::Vector{Any}: what the model received on each timestep, starting at timestep 0 with every input the model lists as BeforeFirstTimestep, since it has received nothing before the simulation.
  • outputs::Vector{Any}: what the model gave on each timestep, starting at timestep 0 with its previous output, which by default has every output as BeforeFirstTimestep().
  • output_distributions::Vector{Any}: what the model gave each output to be sampled from, starting at timestep 0 with BeforeFirstTimestep() for every output, since nothing was given yet.
  • timestep_sizes::Vector{Any}: how much time each timestep covered, starting with BeforeFirstTimestep() for timestep 0, so that it has an entry for each entry of the other vectors.

CognitiveModeling.NameMap — Type
NameMap(names...)

Which outputs of one side of a simulation the other side receives, and under which names.

Each argument is :given => :received, for an output which the receiver lists under another name, or a single Symbol, for one which keeps its name. Outputs that aren't in the map aren't passed on, and each name can only be there once. The names are kept in the type, so that a map costs nothing in a simulation.

simulate and simulate! take one as observation_map, from the observations the environment model gives to those the cognitive model lists, and one as action_map, from the actions the cognitive model gives to those the environment model lists. A cognitive model and an environment which name things differently, or where one gives something the other doesn't list, can then be used together, and the map says which outputs the receiver gets: it must give exactly the names the receiver lists in attribute_names. NameMap() passes nothing on, for a receiver which lists nothing. Without a map, the two must list the same names.

CognitiveModeling.reset! — Method
reset!(instantiated_model::InstantiatedModel)

Put instantiated_model back to where a new one starts, and return it.

The state becomes the output of initialize_state with the parameters it has, and the previous output has every output as BeforeFirstTimestep again. The history is a new one which starts from there, as timestep 0 when the SaveHistory saves the initial values, so a history that was read before the reset, as in history = agent.history, is kept as it was. The model, the parameters and the SaveHistory stay the same.

An instantiated model that was created with a state or a previous output of its own doesn't return to those. Create a new one for that.

Examples

using CognitiveModeling
using Distributions: Bernoulli

struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = 0.5)
end

function CognitiveModeling.apply_model(model::RescorlaWagner, context::ModelContext)
    V₋₁ = context.previous_state.expected_reward
    Vₜ = V₋₁ + context.parameters.learning_rate * (context.input.reward - V₋₁)
    return ModelOutput((; choice = Bernoulli(Vₜ)), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(; parameters = :learning_rate, states = :expected_reward, inputs = :reward, outputs = :choice)
end

agent = InstantiatedModel(RescorlaWagner(), (; learning_rate = 0.5); save_history = SaveHistory(SaveEverything()))

simulate!(agent, (; reward = 1.0))
simulate!(agent, (; reward = 1.0))
reset!(agent)

agent.state, agent.previous_output, agent.history.states

((expected_reward = 0.5,), (choice = BeforeFirstTimestep(),), Any[(expected_reward = 0.5,)])

CognitiveModeling.simulate! — Method
simulate!(instantiated_model::InstantiatedModel, input; timestep_size=1,

The output is in a NamedTuple with the names the model gave it, as in output.choice, as for simulate. The input must be a NamedTuple with every input the model lists in attribute_names, or an ArgumentError is thrown.

CognitiveModeling.simulate! — Method
simulate!(agent::InstantiatedModel, environment::InstantiatedModel; <keyword arguments>)

Simulate agent interacting with environment from where they are, update them both, and return the same NamedTuple as simulate, without timestep 0: what agent.save_history selects of the states, observations, actions and action distributions on each timestep of this call, what environment.save_history selects of the environment's under environment, and the sizes of the timesteps. What the two select is also added to agent.history and environment.history, in each model's own names, together with the sizes of the timesteps, unless a selection is empty. A history has timestep 0 from where the model started, when its SaveHistory saves the initial values.

The two models must fit together, as for simulate, directly or through observation_map and action_map. The agent's history holds the observations as its model received them, and the environment's history the actions as its model did.

The simulation ends before n_steps timesteps if stopping_criterion of either model is met, unless check_stopping_criterion is false. A model where it is met already can't be simulated further, and throws an error until it is reset!.

Reading the untyped fields of the instantiated models costs a dynamic dispatch on each call, which makes the return type unknown to the compiler. The loop inside is still fully typed. Use simulate if the return type matters, or if most calls are for a single timestep.

Arguments

  • who_starts::Union{AgentStarts, EnvironmentStarts}: who moves first on each timestep.
  • n_steps::Int: the number of timesteps to simulate, which must be at least 1. It is the most timesteps there can be when a model has a stopping_criterion.
  • timestep_sizes=1: how much time each timestep covers. A value that isn't a vector, such as a single number, is the size of every timestep of this call. A vector has one size for each timestep of this call, so its length must be n_steps.
  • rng::AbstractRNG=default_rng(): the random number generator to sample from.
  • observation_map::Union{Nothing, NameMap}=nothing: which observations of the environment the agent receives, and under which names, as for simulate.
  • action_map::Union{Nothing, NameMap}=nothing: which actions of the agent the environment receives, and under which names, as for simulate.
  • check_stopping_criterion::Bool=true: whether stopping_criterion of the two models is checked before each timestep, as for simulate.

CognitiveModeling.simulate — Method
simulate(model, input; <keyword arguments>)

Run a single timestep of model, a cognitive model or an environment model, on input, without the other side of a simulation, and return the sampled output and the new state of the model.

Nothing is kept between calls, so pass the returned state and output on as previous_state and previous_output to run the next timestep. simulate! on a single input does the same for an InstantiatedModel, which keeps them. The compiler knows the types here, which it doesn't for an instantiated model, so this is the faster of the two.

The output is in a NamedTuple with the names the model gave it, as in output.choice. The input must be a NamedTuple with every input the model lists in attribute_names, or an ArgumentError is thrown. Parameters that aren't given take the values in default_parameters, if model provides defaults for them, and the names of the parameters, the state and the previous output are checked as in a full simulation.

Arguments

  • model::AbstractModel: the model.
  • input::NamedTuple: what the model receives on this timestep, such as (; reward = 1.0) for a cognitive model. An entry that isn't there is NoObservation or NoAction.
  • parameters::NamedTuple: the parameters of model, with its default values for those that aren't given, if it provides any.
  • timestep_size=1: how much time this timestep covers.
  • rng::AbstractRNG=default_rng(): the random number generator to sample from.
  • previous_state=initialize_state(model, ...): the state of model before this timestep, by default its initial state from the full parameters. A state that model changes in place will be changed.
  • previous_output=initial_output(model): the output before this timestep. By default every output is BeforeFirstTimestep.

CognitiveModeling.simulate — Method
simulate(cognitive_model, environment; <keyword arguments>)

Simulate cognitive_model interacting with environment, and return what was saved in a NamedTuple: states, observations, actions and action_distributions of the cognitive model, environment with the states, observations, actions and observation_distributions of the environment, and timestep_sizes. Each is a vector with one element for timestep 0, before the first timestep, and one for each timestep after it.

Each element is what happened on that timestep, and the states are those after it. The observations are those the cognitive model received, and the actions those it gave, and under environment the observations are those the environment gave and the actions those it received, which differ from the cognitive model's when a NameMap selects or renames them. The action distributions are what the cognitive model gave its actions to be sampled from, and the observation distributions what the environment gave its observations to be sampled from. The element for timestep 0 has the previous observation and action, which are BeforeFirstTimestep unless others are given, BeforeFirstTimestep() for every distribution, and the states before the first timestep. Since Julia counts from 1, element t + 1 is timestep t.

cognitive_save_history and environment_save_history select what is kept of each element of each model, which is nothing by default: give SaveHistory(SaveEverything()) to keep everything, and SaveHistory(SaveEverything(); save_initial_values = false) to leave out timestep 0, so that element t is timestep t. The vectors of both models have the same length, which cognitive_save_history decides. The sizes of the timesteps are returned as they were given: a single size as it is, and a vector of sizes with the sizes of the timesteps that ran, after BeforeFirstTimestep() for timestep 0 when it is there.

Parameters that aren't given take the values in default_parameters, if cognitive_model or environment provides defaults for them. The names of the parameters, the states, the previous action and the previous observation must be those in attribute_names, and the outputs of each model must be the inputs of the other, or an ArgumentError is thrown before the first timestep. When the two name things differently, or one gives something the other doesn't list, observation_map and action_map say which outputs of one the other receives, and under which names.

The simulation ends before n_steps timesteps if stopping_criterion of either model is met, unless check_stopping_criterion is false, and everything returned then has the timesteps that ran.

Arguments

  • cognitive_model::AbstractModel: the cognitive model, usually an AbstractCognitiveModel.
  • environment::AbstractModel: the environment model, usually an AbstractEnvironmentModel. A cognitive model can serve as the environment of another when its outputs are what the other lists as its inputs, and the other way round.
  • who_starts::Union{AgentStarts, EnvironmentStarts}: who moves first on each timestep. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • n_steps::Int: the number of timesteps to simulate, which must be at least 1. It is the most timesteps there can be when a model has a stopping_criterion.
  • timestep_sizes=1: how much time each timestep covers, which both cognitive_model and environment receive. A value that isn't a vector, such as a single number, is the size of every timestep. A vector has one size for each timestep, so its length must be n_steps.
  • cognitive_parameters::NamedTuple: the parameters of cognitive_model, with its default values for those that aren't given, if it provides any.
  • environment_parameters::NamedTuple: the parameters of environment, with its default values for those that aren't given, if it provides any.
  • rng::AbstractRNG=default_rng(): the random number generator to sample actions and observations from, which cognitive_model and environment also receive in their contexts.
  • previous_cognitive_state=initialize_state(cognitive_model, ...): the state of cognitive_model before the first timestep, by default its initial state from the full parameters. A state that cognitive_model changes in place will be changed.
  • previous_action=initial_output(cognitive_model): the action before the first timestep. By default every action is BeforeFirstTimestep, with the names from attribute_names.
  • previous_environment_state=initialize_state(environment, ...): the state of environment before the first timestep, by default its initial state from the full parameters.
  • previous_observation=initial_output(environment): the observation before the first timestep. By default every observation is BeforeFirstTimestep(), with the names from attribute_names of environment.
  • cognitive_save_history::SaveHistory=SaveHistory(): which states, inputs, outputs and output distributions of cognitive_model are saved, by name, and whether timestep 0 is. Nothing is saved by default, and SaveHistory(SaveEverything()) saves everything. See SaveHistory.
  • environment_save_history::SaveHistory=SaveHistory(): the same for environment, whose inputs are the actions it receives and whose outputs are the observations it gives. Whether timestep 0 is saved follows cognitive_save_history, so that the vectors of both models have the same length.
  • observation_map::Union{Nothing, NameMap}=nothing: which observations of environment are passed on to cognitive_model, and under which names, as a NameMap from the names environment gives to exactly those cognitive_model lists. Without one, the two must list the same observations, which cognitive_model receives under the same names.
  • action_map::Union{Nothing, NameMap}=nothing: which actions of cognitive_model are passed on to environment, and under which names, as a NameMap from the names cognitive_model gives to exactly those environment lists. Without one, the two must list the same actions, which environment receives under the same names.
  • check_stopping_criterion::Bool=true: whether stopping_criterion of the two models is checked before each timestep. With false, all of n_steps timesteps run.

See also simulate!, which continues from where the last simulation ended.

Extended help

The return type is concrete as long as the types of the outputs don't change between timesteps. If they do, like an observation with an entry that is sometimes NoObservation, the vector for that output holds a Union of the types, and the simulation is a little slower. The same goes for timestep 0 when it has other types than the timesteps after it, which the observations and actions usually do, since they are BeforeFirstTimestep() there.

Nothing is copied when outputs are saved. A model or environment which changes an object in its state in place, instead of returning a new one, must add a method of prepare_state_for_saving, or all the saved states show the final values, with no error. Observations and actions have no such function, so they must be new objects on each timestep.

CognitiveModeling.MissingValue — Type
MissingValue()

Stand-in for an action or an observation that happened on a timestep but isn't in the data, as one entry of a column or a NamedTuple, such as (; choice = MissingValue()). Whether it is an action or an observation is given by where it is.

Fitting imputes a missing action by sampling it from the model's action distribution on that timestep, or passes it on as NoAction when it is told not to impute. It imputes a missing observation from what an environment model gives for the observation on that timestep: as a latent variable with that distribution, or as the value of a Deterministic. NoAction and NoObservation are different: they say that nothing was done or observed on the timestep. Unlike missing, arithmetic on it is an error. A SessionInfo replaces missing in the data by it.

CognitiveModeling.MultipleSessionsInfo — Type
MultipleSessionsInfo(cognitive_model, table; observation_columns, action_columns,
                     session_columns, <keyword arguments>)
MultipleSessionsInfo(sessions, session_ids)

The sessions that a cognitive model is fitted to together, as a vector of SessionInfo with an identifier for each, which turing_multiple_behavioural_sessions and turing_full_model take.

The first form splits a table into sessions. table is a NamedTuple with one vector for each column, which is what Tables.columntable gives for a DataFrame or any other table. A missing in a column becomes MissingValue, or the marker for nothing happening, as the keyword arguments missing_observations and missing_actions of SessionInfo say. Every session must come out with the same type, which they do when they share the models and the settings, since the timesteps of different sessions are then compiled once. An environment runs only in the sessions where an observation or an action is missing, as for SessionInfo.

MultipleSessionsInfo(sessions_info; cognitive_save_history, environment_save_history)

The same sessions with other save histories for every one, see SessionInfo.

Arguments

  • cognitive_model::AbstractModel: the cognitive model, usually an AbstractCognitiveModel.
  • table::NamedTuple: the data of every session, with one vector for each column and one entry for each timestep, such as (; id = ["S1", "S1", "S2", "S2"], reward = [1.0, 0.0, 1.0, 1.0], choice = [true, false, true, true]).

Keyword arguments

  • observation_columns: the columns with the observations. When the model lists one observation, a single name, such as :outcome, is its column, whatever the observation is called. Several observations are given as the names the model lists in attribute_names when the columns are named the same, such as (:reward, :cue), or as a NamedTuple from the model's name to the column's, such as (; reward = :outcome, cue = :stimulus), so that one model fits tables with other names. A single name that the model lists as one of its actions is an error, since the two keyword arguments may then be swapped. An attribute whose value is made of several columns is specified by how to build it from them: a NamedTuple of column names for a NamedTuple in each row, (; ssm_action = (; choice = :choicecol, rt = :rtcol)), a Tuple of column names for a Tuple, (; ssm_action = (:choicecol, :rtcol)), or a Tuple of column names and a function of their values, (; ssm_action = (:choicecol, :rtcol) => (choice, rt) -> [choice, rt]). A missing in any of the columns makes the value missing.
  • action_columns: the columns with the actions, in the same forms.
  • session_columns: the column or columns which identify a session, such as :id or (:id, :block). A session is every row with one combination of their values, in the order of the first row of each. The identifier of a session is its value in a single column, or a NamedTuple of its values in several.
  • timestep_sizes=1: how much time each timestep covers, as one size for all, or the name of a column with the size of each timestep.
  • The other keyword arguments of SessionInfo, which every session gets.

The second form takes sessions that are already prepared. Each argument is kept in a field of the same name.

CognitiveModeling.ParallelSessions — Type
ParallelSessions()

Given as parallelisation to turing_multiple_behavioural_sessions or turing_full_model, it spreads the sessions over the threads Julia was started with, as Threads.@threads does. The model that is evaluated, which is the outermost one, must then be marked with DynamicPPL's setthreadsafe(model, true), and the sessions throw an error if it isn't, since the log density is silently wrong otherwise. CognitiveModeling.SessionInfo — Type
SessionInfo(cognitive_model, observations, actions; who_starts, <keyword arguments>)

Everything about one session that is fixed while a cognitive model is fitted to it: the data, the models and the settings, checked and prepared once. A Turing.jl model of the session, turing_behavioural_session, takes it together with the parameters, which are what changes between evaluations. MultipleSessionsInfo makes one for each session in a table.

Arguments

  • cognitive_model::AbstractModel: the cognitive model, usually an AbstractCognitiveModel.
  • observations: the observations in the data, as a NamedTuple with one vector for each name and one entry for each timestep, such as (; reward = [1.0, 0.0, 1.0]). The data must have every observation the model lists in attribute_names, and can have more. When the model lists one observation, a single vector, [1.0, 0.0, 1.0], is the data of that observation, whatever its name. An observation that wasn't recorded is MissingValue, which environment fills in, and one that wasn't made is NoObservation.
  • actions: the actions in the data, in the same forms, with exactly the actions the model lists. An action that was taken but not recorded is MissingValue(), and is imputed unless impute_missing_actions is false. An action that wasn't taken is NoAction, and isn't scored.

Keyword arguments

  • who_starts::Union{AgentStarts, EnvironmentStarts}: whether the model acts on the observation of the same timestep, EnvironmentStarts(), or on the observation of the timestep before, AgentStarts(), as in simulate. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • environment::Union{NoEnvironment, AbstractModel}=NoEnvironment(): an environment model, usually an AbstractEnvironmentModel, which fills in the observations that are MissingValue(), and against whose distributions the observations in the data are scored. Its outputs must be the inputs of cognitive_model and the other way round, since a session takes no maps of names. Without it, the data can't have missing observations. It runs in a session where an observation or an action is missing, where environment_save_history saves anything, or where check_stopping_criterion is true: the scored observations then inform what is missing, such as which arm of a bandit a missing choice was, from the reward that followed. A session with nothing missing runs without it, since the scores of its observations would then be the same for every value of the parameters, unless the environment's parameters are sampled, see turing_full_model. The session then has none of the environment's variables either. The environment is kept in the session all the same.
  • timestep_sizes=1: how much time each timestep covers, as in simulate.
  • impute_missing_actions::Bool=true: whether an action that is MissingValue() is imputed, as a latent variable. When it is false, nothing is sampled for it, and it is replaced by NoAction() here: cognitive_model receives NoAction() as that previous action on the next timestep, and environment as the action it responds to.
  • cognitive_save_history::SaveHistory=SaveHistory(): which states, inputs, outputs and output distributions of cognitive_model a fitted session returns, by name, and whether timestep 0 is, as a SaveHistory in the model's own names. Nothing is selected by default. What is returned names them by their role, as states, observations, actions and action_distributions, see turing_behavioural_session.
  • environment_save_history::SaveHistory=SaveHistory(): the same for environment, whose inputs are the actions and whose outputs are the observations, returned under environment. Selecting anything makes the environment run in the session, also when nothing is missing, which adds its scores of the observations to the log density; with fixed environment parameters they are the same for every value of the cognitive parameters, so the posterior is unchanged. Whether timestep 0 is saved follows cognitive_save_history.
  • check_stopping_criterion::Union{Nothing, Bool}=nothing: when stopping_criterion of the two models is checked before a timestep, so that the session ends there, with what it saved up to it. By default it is checked only on the timesteps after the last one with data, where a value is neither MissingValue() nor a marker for nothing happening, so that a fit never checks it and a session made by predictive_sessions, whose data is all missing, ends as a simulation does. With true it is checked before every timestep, which makes the environment run, and a model whose criterion is met while the data continues is an error, since the recorded values after that timestep couldn't be scored: this checks that the models agree with the length of the data. With false it is never checked.
  • missing_observations::Union{MissingValue, NoObservation}=MissingValue() and missing_actions::Union{MissingValue, NoAction}=MissingValue(): what a missing in the data becomes, since a table marks every gap the same way: a value that wasn't recorded, or nothing happening on that timestep. The two markers can also be put in the data directly.
  • previous_observation and previous_action: what the first timestep receives as the observation and the action before it, with BeforeFirstTimestep for each name by default, as in simulate. The states where the session starts are not given here, since they come from initialize_state with the parameters that are fitted.

Each argument is kept in a field of the same name, with the two replacements made in the data, except impute_missing_actions, whose work is done here. There are five fields more: runs_environment, whether the environment runs, recorded_actions and recorded_observations, the recorded values of each name which are scored, n_timesteps, saved_timestep_sizes, the sizes a fitted session returns with what it saves, and first_timestep_to_check_stopping, the first timestep before which the stopping criterion is checked, as check_stopping_criterion decides it.

CognitiveModeling.turing_behavioural_session — Function
turing_behavioural_session(session_info::SessionInfo, cognitive_parameters)
turing_behavioural_session(session_info::SessionInfo, cognitive_parameters,
                           environment_parameters=(;))

Create a Turing.jl model of one session: the cognitive model in session_info goes through the timesteps of its data with cognitive_parameters, and the recorded actions are scored against the action distributions it gives. The second form is for a session with an environment model, which takes its parameters too. This needs Turing.jl to be loaded.

The model is a building block for a Turing.jl model which samples the parameters, as a submodel with its own prefix: to_submodel(prefix(turing_behavioural_session(...), @varname(session)), false). turing_multiple_behavioural_sessions runs one for each of several sessions, and turing_full_model samples their parameters too.

Arguments

  • session_info::SessionInfo: the data, the models and the settings of the session, prepared once with SessionInfo.
  • cognitive_parameters::NamedTuple: the parameters of the cognitive model, usually the random variables of the model around this one. Those it doesn't have take the values in default_parameters, if the model provides defaults for them.
  • environment_parameters::NamedTuple=(;): the parameters of the environment model, with its default values for those that aren't given, if it provides any. A session without an environment takes none.

What it does

The states where the session starts come from turing_initialize_state of each model with the parameters, so that a starting state which is a parameter is fitted like any other, and a model can sample its start. Both models are treated the same way on each timestep: turing_apply_model of the cognitive model runs as a submodel with the prefix timestep[t], so a model which samples within a timestep has its own variables for each timestep, such as timestep[3].noise, and an environment model runs with the prefix timestep[t].environment. The outputs of each, the actions and the observations, are then taken from the data where they are recorded, and where the data has MissingValue they are imputed from what the model gave: as a latent variable with that distribution, named timestep[3].choice.imputed or timestep[3].environment.reward.imputed, or as the value itself if it is a Deterministic. The sampler must handle the type of a latent variable: a continuous value can be sampled with NUTS, a discrete one needs a sampler for discrete variables. The recorded actions are scored at the end as observed values, in one product_distribution over every action and timestep, against the distributions the cognitive model gave for them, which is several times faster than scoring each timestep on its own. The recorded observations are scored the same way against the distributions the environment gave, so that they inform the missing values and the environment's parameters. A Deterministic is scored as a point mass, with a log density of 0 for its value and -Inf for any other, and only a number or a Bool can be, so a recorded value the model gives as another kind of Deterministic is an error. A recorded value where the model gave nothing, NoAction or NoObservation, is an error too. When nothing in the data is missing and the environment's history isn't saved, the environment doesn't run, and the session is the same as one without an environment, with the same variables. The stopping_criterion of the models is checked as the check_stopping_criterion of session_info says: by default only after the last timestep with data, so that a fit runs every timestep and a session from predictive_sessions can end early.

What it returns

What the save histories of session_info select, in a NamedTuple with the same entries as simulate returns: states, observations, actions and action_distributions of the cognitive model, environment with the states, observations, actions and observation_distributions of the environment when the session has one, which are empty when it didn't run, and timestep_sizes. Each is a vector with one element for timestep 0, before the first timestep, and one for each timestep that ran, which returned(model, chain) gives for each sample. Timestep 0 has the previous observation and action, which are BeforeFirstTimestep unless others are given, BeforeFirstTimestep() for every distribution, and the initial states, which can depend on the parameters. Element t + 1 is then timestep t, and a SaveHistory with save_initial_values = false leaves timestep 0 out. The returned actions and observations are those the models received, with the imputed values. timestep_sizes has the size of each timestep, after BeforeFirstTimestep() for timestep 0 when it is there, when anything is selected, and is empty otherwise. Any latent variable in a session, imputed or from a model which samples within a timestep, makes evaluating the model much slower in the current version of DynamicPPL.jl.

CognitiveModeling.turing_full_model — Function
turing_full_model(cognitive_parameters_model, sessions_info::MultipleSessionsInfo;
                  environment_parameters_model=NoParameters(),
                  downstream_model=NoDownstreamModel(), catch_invalid_parameters=false,
                  parallelisation=NoParallelisation(), include_submodel_prefixes=false)

Create the Turing.jl model which fits a cognitive model to several sessions, in three parts: cognitive_parameters_model gives or samples the cognitive parameters of every session, and environment_parameters_model those of the environment model, the sessions in sessions_info run with them as turing_multiple_behavioural_sessions, and downstream_model can do something with what they saved, such as a regression of a measurement on a state. This needs Turing.jl to be loaded.

Arguments

  • cognitive_parameters_model: a description of how the cognitive parameters of the sessions are given or sampled, a subtype of AbstractSessionParametersModel such as IndependentSessionParameters with a prior for each parameter, which turing_session_parameters_model has a method for.
  • sessions_info::MultipleSessionsInfo: the sessions, prepared once with MultipleSessionsInfo.
  • environment_parameters_model=NoParameters(): the same for the parameters of the environment model of the sessions, when they have one. By default the environment's parameters take its default values, and FixedSessionParameters gives others. When they are sampled, every session runs its environment, also those with nothing missing, so that the observations in the data inform them. Sessions without an environment take no parameters.
  • downstream_model=NoDownstreamModel(): a description of what runs after the sessions, which turing_downstream_model has a method for. The default samples nothing.
  • catch_invalid_parameters::Bool=false: whether the sessions run inside turing_catch_invalid_parameters, so that an InvalidParametersError rejects the sample instead of stopping the sampler. The parameters models run outside it, so that a rejected first draw keeps its parameters and the sampler can start, and the model returns nothing for a rejected sample, without running the downstream model. A downstream model with variables of its own then lacks them in a rejected draw, so a sampler can't start from one: give it valid initial_params in that case.
  • parallelisation=NoParallelisation(): whether the sessions run over the threads Julia was started with, with ParallelSessions(). The model must then be marked with setthreadsafe(model, true) from DynamicPPL before it is sampled: without the mark, a threaded model has a wrong log density with no error, so the sessions throw an error instead. The gradient is right with ForwardDiff and ReverseDiff, and Mooncake and Enzyme throw. See ParallelSessions.
  • include_submodel_prefixes::Bool=false: whether the variables of the two parameters models and of the downstream model are named under cognitive_parameters_model, environment_parameters_model and downstream_model. Without the prefixes, the names are shorter, but a variable of the same name in two of them is one variable, which sample refuses with an error, and which a log density gives one value with both priors counted. A warning says so when the model is made, when the cognitive model and the environment model have a parameter of the same name and both parameters models sample.

The variables of a parameters model are named as it names them, such as learning_rate.session, a vector with a value for each session, for IndependentSessionParameters, and learning_rate.shared for IdenticalSessionParameters, or under the parameters model's name with include_submodel_prefixes = true. Those of the sessions are under session[i], and those of the downstream model as it names them, or under downstream_model with the prefixes. The model returns (; cognitive_parameters, environment_parameters, saved_behavioural_values, downstream_values): the cognitive parameters and the environment parameters of every session as the parameters models gave them, what each session saved, as a vector of what turing_behavioural_session returns, and what the downstream model returned. returned(model, chain) gives all three for each sample, so a fitted state is read from the chain without simulating again.

Saving states costs about 5 % of a gradient. Without a downstream model that needs them, a fit is fastest with sessions that save nothing, and the saved values are then read from the chain afterwards with session_values_chain, or with returned on the model of a copy of the sessions that saves them, MultipleSessionsInfo(sessions_info; cognitive_save_history = SaveHistory(; states = :expected_reward)), since the two models have the same variables. CognitiveModeling.apply_model — Function

Run a single timestep of model: update its state, and return what its outputs are sampled from. For a cognitive model the outputs are its actions, and for an environment model the observations it gives.

Implementation

Every model must add a method of this function, which throws an error otherwise.     #Reward observed on this timestep
    r = context.input.reward
    #Expected reward from the previous state
    V₋₁ = context.previous_state.expected_reward

    #Softmax function, instantiated as a Bernoulli logit distribution

CognitiveModeling.stopping_criterion — Function
stopping_criterion(model::AbstractModel, state, parameters)

Return whether model, a cognitive model or an environment model, has ended, with state as its state after a timestep and its parameters, so that a simulation stops there instead of running all of n_steps.

simulate and simulate! check it for both models before each timestep, with the states that the timestep before left, unless they are given check_stopping_criterion = false. When it returns true for either, no further timestep runs, and what is returned and added to the histories has the timesteps that ran. When the environment starts, the cognitive model has then made its last observation and acted on it, and the environment doesn't receive that action. A model whose criterion is already met before the first timestep can't be simulated, and throws an error: a new simulation starts from the initial state, and reset! puts an InstantiatedModel back there. A fitted session checks it as SessionInfo describes.

Implementation

A model can add a method of this function. The default returns false, so a simulation runs all of its timesteps, and the check then costs nothing.

CognitiveModeling.turing_apply_model — Function
turing_apply_model(model::AbstractModel, context::ModelContext)

Create a Turing.jl model for a single timestep of model, a cognitive model or an environment model, to be used as a submodel, which returns a ModelOutput. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls apply_model. A model which samples within a timestep needs to add a method, however; or if any other changes are desired within Turing. It must sample with ~ instead of from context.rng. Otherwise the model has a different log density each time it is evaluated, with no error. The same holds for an environment model, which fitting uses to fill in observations that are MissingValue in the data: what it samples itself, such as a change of its state, must be sampled with ~, while fitting samples the observations from what it returns.

Examples

using CognitiveModeling
using Turing

struct NoisyRescorlaWagner <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_apply_model(
        model::NoisyRescorlaWagner,
        context::ModelContext,
    )

    ## Unpack the context ##
    #Reward observed on this timestep
    r = context.input.reward
    #Expected reward from the previous state
    V₋₁ = context.previous_state.expected_reward
    #Learning rate parameter
    α = context.parameters.learning_rate

    ## Update state ##
    #Sample the noise in the update
    ϵ ~ Normal(0, context.parameters.noise)
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁) + ϵ

    return ModelOutput((; choice = BernoulliLogit(Vₜ - 0.5)), (; expected_reward = Vₜ))
end

Create a Turing.jl model which gives the state of model, a cognitive model or an environment model, before the first timestep, to be used as a submodel, as initialize_state does. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls initialize_state, which is enough for most models, since a starting state that is fitted is simply one that is copied from a parameter there: a fitted session runs it with the parameters of each evaluation, so a prior on the parameter is a prior on the starting state.
