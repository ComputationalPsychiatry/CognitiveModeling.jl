CognitiveModeling.InvalidParametersError — Type
InvalidParametersError(message)
InvalidParametersError()

An error for a model to throw from apply_model or initialize_state when its parameters aren't valid, as in throw(InvalidParametersError()).

The default message says that the parameters are not valid, possibly dependent on the observations, actions and states, and a model can give a more specific one. A simulation stops with it as with any other error, and fitting can catch it to give the parameters a probability of zero, so a model should throw this rather than an ordinary error when the parameters are the problem.

Examples

julia> try
           throw(InvalidParametersError())
       catch error
           sprint(showerror, error)
       end
"InvalidParametersError: Model parameters are not valid, possibly dependent on observations, actions and states."

julia> sprint(showerror, InvalidParametersError("The learning rate must be between 0 and 1."))
"InvalidParametersError: The learning rate must be between 0 and 1."

CognitiveModeling.ModelAttributes — Type
ModelAttributes(; parameters, states, observations, actions)

The names of the attributes of a model, which attribute_names returns.

An environment model returns one too, where the observations are those it gives and the actions those it receives, the other way round from a cognitive model.

Each argument is a Tuple of Symbols, which is kept in the type, so that the names are known at compile time, and read as a property of the same name, such as attributes.parameters. A single Symbol is put in a tuple, and a Vector of them is made into one. All four must be given, and () means that the model has none of that kind.

Examples

julia> attributes = ModelAttributes(;
           parameters = (:learning_rate, :inverse_temperature),
           states = :expected_reward,
           observations = [:reward],
           actions = (),
       )
ModelAttributes
Parameters: learning_rate, inverse_temperature
States: expected_reward
Observations: reward
Actions: none

julia> attributes.states
(:expected_reward,)

CognitiveModeling.ModelInput — Type
ModelInput(observation, previous_state, previous_action, parameters, timestep_size=1,
           rng=default_rng())

Everything a model needs to run a single timestep, which apply_model receives.

Each argument is kept in a field of the same name, such as input.observation.

Arguments

  • observation: what the model observes on this timestep, in a NamedTuple with the names the environment gave them, as in input.observation.reward. An observation that isn't made on this timestep is NoObservation, which every observation is on the first timestep when the agent starts.
  • previous_state: the state of the model after the previous timestep. On the first timestep, this is the output of initialize_state.
  • previous_action: the actions from the previous timestep, in a NamedTuple with the names the model gave them, as in input.previous_action.choice. Before the first timestep, each of them is NoAction.
  • parameters: the cognitive parameters of the model. Will generally be a NamedTuple.
  • timestep_size=1: how much time this timestep covers.
  • rng=default_rng(): the random number generator to sample from if anything in the model is random, so that a simulation can be reproduced.

Examples

julia> observation = (; reward = 1.0);

julia> state = (; expected_reward = 0.5);

julia> parameters = (; learning_rate = 0.1);

julia> previous_action = (; choice = NoAction());

julia> ModelInput(observation, state, previous_action, parameters).timestep_size
1

julia> ModelInput(observation, state, previous_action, parameters, 0.5).timestep_size
0.5

CognitiveModeling.ModelOutput — Type
ModelOutput(action_distribution, new_state=(;))

The outputs of a model for a single timestep, which apply_model returns.

Each argument is kept in a field of the same name, such as output.new_state.

Arguments

  • action_distribution::NamedTuple: what the actions on this timestep are sampled from, in a NamedTuple with one entry for each action, such as (; choice = Bernoulli(0.7)). Each entry can be anything that works with rand, such as a distribution from Distributions.jl, and the sampled actions keep the names. An action that isn't taken on this timestep is NoAction, and a model without actions gives an empty NamedTuple, (;).
  • new_state=(;): the cognitive state of the model after this timestep, which is the previous_state of the next one.

Examples

julia> using Distributions: Bernoulli

julia> ModelOutput((; choice = Bernoulli(0.7)), (; expected_reward = 0.5)).new_state
(expected_reward = 0.5,)

julia> ModelOutput((; choice = Bernoulli(0.7))).new_state
NamedTuple()

julia> ModelOutput((; choice = NoAction(), bet = Bernoulli(0.2))).action_distribution.choice
NoAction()

CognitiveModeling.CommonRLEnvironment — Type
CommonRLEnvironment(env; action_name)

An environment model around an environment from CommonRLInterface.jl, which needs CommonRLInterface.jl to be loaded. action_name is the name of the cognitive model's action that act! receives, such as :arm.

Environments from POMDPs.jl and ReinforcementLearning.jl can be used through it, with convert(CommonRLInterface.AbstractEnv, x), which POMDPTools.jl defines for a POMDP or MDP and ReinforcementLearningBase.jl for its environments.

The environment object is the state: initialize_state resets it with reset! and returns it, every timestep changes it in place with act! and passes it on as the new state, and prepare_state_for_saving copies it, with clone if the environment provides it and with deepcopy otherwise. A method of prepare_state_for_saving for a CommonRLEnvironment with a specific environment type can save something lighter. The parameters aren't used, and neither is the random number generator, since an environment of CommonRLInterface.jl has its own randomness.

Each observation is a NamedTuple (; observation, reward, terminated): what observe gives, the reward that act! returned, and whether the episode has ended. Before the first action, when the action is NoAction, and on the timestep after an episode ended, the environment is at its initial observation, with reset! in the second case, so the reward is NoObservation and nothing is done with the action. Its attribute_names are these three observations, the one action, no parameters and no states, since the environment object isn't a NamedTuple. Use EnvironmentStarts, so that the model observes before it acts.

Examples

using CognitiveModeling
using CommonRLInterface
using Random: AbstractRNG

#A two-armed bandit where the first arm always pays, in episodes of two pulls
mutable struct Bandit <: CommonRLInterface.AbstractEnv
    pulls::Int
end
CommonRLInterface.reset!(env::Bandit) = (env.pulls = 0; nothing)
CommonRLInterface.actions(env::Bandit) = 1:2
CommonRLInterface.observe(env::Bandit) = env.pulls
CommonRLInterface.act!(env::Bandit, arm) = (env.pulls += 1; arm == 1 ? 1.0 : 0.0)
CommonRLInterface.terminated(env::Bandit) = env.pulls == 2

#An action that is always the same
struct Always{T}
    value::T
end
Base.rand(rng::AbstractRNG, action::Always) = action.value

#A model which always pulls the first arm
struct PullsFirstArm <: AbstractCognitiveModel end
CognitiveModeling.initialize_state(model::PullsFirstArm, parameters) = (;)
CognitiveModeling.apply_model(model::PullsFirstArm, input::ModelInput) = ModelOutput((; arm = Always(1)))
CognitiveModeling.attribute_names(model::PullsFirstArm) = ModelAttributes(; parameters = (), states = (), observations = (:observation, :reward, :terminated), actions = :arm)

observations, actions, _, _ = simulate(
    PullsFirstArm(),
    CommonRLEnvironment(Bandit(0); action_name = :arm);
    who_starts = EnvironmentStarts(),
    n_steps = 4,
    cognitive_parameters = (;),
    environment_parameters = (;),
    save_history = SaveHistory(SaveEverything()),
)

foreach(println, observations)

# output

(observation = 0, reward = NoObservation(), terminated = false)
(observation = 1, reward = 1.0, terminated = false)
(observation = 2, reward = 1.0, terminated = true)
(observation = 0, reward = NoObservation(), terminated = false)

What has happened to a CognitiveAgent, which simulate! adds to.

CognitiveModeling.CognitiveAgent — Type
CognitiveAgent(model, parameters; save_history=SaveHistory())
CognitiveAgent(model, parameters, state, previous_action; save_history=SaveHistory())

An instantiated cognitive model with its parameters and current state, which simulate! can update iteratively.

Parameters that aren't given take the values in default_parameters. The state defaults to the output of initialize_state with the full parameters, and the previous action to every action being NoAction. The model must have a method of attribute_names, and the names of the parameters, of the previous action, and of the state when it is a NamedTuple, must be those it lists, or an error is thrown.

agent.history holds an AgentHistory with where the agent started and everything that happens to it, as selected by save_history, a SaveHistory. By default nothing is selected and the vectors in agent.history stay empty, and SaveHistory(SaveEverything()) saves everything. Observations and actions can only be selected by name among those the model lists, since the history starts from those names.

See also Environment.

CognitiveModeling.SaveHistory — Type
SaveHistory(; observations=(), actions=(), states=())
SaveHistory(SaveEverything())

Which observations, actions and states a simulation saves, by name.

Each argument is the names of that kind to save, in a Tuple of Symbols, a single Symbol or a Vector of them, or SaveEverything for all of them. A kind that isn't given saves nothing, so SaveHistory() saves nothing, which is the default everywhere, and SaveHistory(SaveEverything()) saves everything. The selections are kept in the type, so that selecting costs nothing in a simulation, and are read as properties, such as save_history.states.

Saving some names of a kind gives a NamedTuple with those names on each timestep, which only works when the value is a NamedTuple, and saving none gives an empty one, (;), for any value. For an environment, the states are its own, and the observations and actions are the same as the agent's, which simulate! adds to the environment's history too, while simulate only uses its states.

See also CognitiveAgent, Environment and simulate, which take one.

Examples

julia> save_history = SaveHistory(; actions = :choice, states = (:expected_reward, :surprise))
SaveHistory
Observations: none
Actions: choice
States: expected_reward, surprise

julia> save_history.states
(:expected_reward, :surprise)

julia> SaveHistory(SaveEverything()).observations
SaveEverything()

CognitiveModeling.simulate! — Method
simulate!(agent::CognitiveAgent, observation; timestep_size=1, rng=default_rng())

Run a single timestep of agent on observation, update it, and return the sampled action. What agent.save_history selects of the observation, the action and the state is added to agent.history.

The action is in a NamedTuple with the name the model gave it, as in action.choice, as for simulate. The observation must be a NamedTuple with every observation the model lists in attribute_names, or an ArgumentError is thrown.

Arguments

  • agent::CognitiveAgent: the agent to update.
  • observation::NamedTuple: what the agent observes on this timestep, such as (; reward = 1.0). An observation that isn't made is NoObservation.
  • timestep_size=1: how much time this timestep covers.
  • rng::AbstractRNG=default_rng(): the random number generator to sample from.

Examples

using CognitiveModeling
using Distributions: Bernoulli

struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = 0.5)
end

function CognitiveModeling.apply_model(model::RescorlaWagner, input::ModelInput)
    V₋₁ = input.previous_state.expected_reward
    Vₜ = V₋₁ + input.parameters.learning_rate * (input.observation.reward - V₋₁)
    return ModelOutput((; choice = Bernoulli(Vₜ)), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(; parameters = :learning_rate, states = :expected_reward, observations = :reward, actions = :choice)
end

agent = CognitiveAgent(RescorlaWagner(), (; learning_rate = 0.5); save_history = SaveHistory(SaveEverything()))

simulate!(agent, (; reward = 1.0))
simulate!(agent, (; reward = 1.0))

agent.history.states

 (expected_reward = 0.5,)

CognitiveModeling.simulate! — Method
simulate!(agent::CognitiveAgent, environment::Environment; <keyword arguments>)

Simulate agent interacting with environment from where they are, update them both, and return the same vectors as simulate, with what agent.save_history selects of the observations, actions and states, and what environment.save_history selects of the environment's states. What the two select is also added to agent.history and environment.history, unless a selection is empty.

Use the same who_starts on each call, so that each simulation continues the last one. The agent's model and the environment's must fit together, as for simulate.

Reading the agent's untyped fields costs a dynamic dispatch on each call, which makes the return type unknown to the compiler. The loop inside is still fully typed. Use simulate if the return type matters, or if most calls are for a single timestep.

Arguments

  • who_starts::Union{AgentStarts, EnvironmentStarts}: who moves first on each timestep.
  • n_steps::Int: the number of timesteps to simulate, which must be at least 1.
  • timestep_sizes=1: how much time each timestep covers. A vector has one size for each timestep of this call, so its length must be n_steps.
  • rng::AbstractRNG=default_rng(): the random number generator to sample from.

Examples

using CognitiveModeling
using Distributions: Bernoulli

struct RandomChoices <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RandomChoices, parameters)
    return (;)
end

function CognitiveModeling.apply_model(model::RandomChoices, input::ModelInput)
    return ModelOutput((; choice = Bernoulli(0.5)))
end

function CognitiveModeling.attribute_names(model::RandomChoices)
    return ModelAttributes(; parameters = (), states = (), observations = :n_timesteps, actions = :choice)
end

struct TimestepCounter <: AbstractEnvironmentModel end

function CognitiveModeling.initialize_state(model::TimestepCounter, parameters)
    return (; n_timesteps = 0)

    return EnvironmentOutput((; n_timesteps), (; n_timesteps))
end

function CognitiveModeling.attribute_names(model::TimestepCounter)
    return ModelAttributes(; parameters = (), states = :n_timesteps, observations = :n_timesteps, actions = ())
end

agent = CognitiveAgent(RandomChoices(), (;))
environment = Environment(TimestepCounter(), (;))

simulate!(agent, environment; who_starts = EnvironmentStarts(), n_steps = 2)
simulate!(agent, environment; who_starts = EnvironmentStarts(), n_steps = 3)

CognitiveModeling.simulate — Method
simulate(model, environment; <keyword arguments>)

Simulate model interacting with environment, and return the vectors observations, actions, cognitive_states and environment_states, with one element for each timestep.

Each element is what happened on that timestep, and the states are those after it. save_history and save_environment_history select what is kept of each element, which is nothing by default: give SaveHistory(SaveEverything()) to keep everything.

Parameters that aren't given take the values in default_parameters. The names of the parameters, the states, the previous action and the previous observation must be those in attribute_names, and environment must give every observation model lists and model every action environment lists, or an ArgumentError is thrown before the first timestep.

Arguments

  • model::AbstractCognitiveModel: the cognitive model.
  • environment::AbstractEnvironmentModel: the environment model.
  • who_starts::Union{AgentStarts, EnvironmentStarts}: who moves first on each timestep. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • n_steps::Int: the number of timesteps to simulate, which must be at least 1.
  • timestep_sizes=1: how much time each timestep covers, which both model and environment receive. A vector has one size for each timestep, so its length must be n_steps. Anything else is the size of every timestep.
  • cognitive_parameters::NamedTuple: the parameters of model, with its default values for those that aren't given.
  • environment_parameters::NamedTuple: the parameters of environment, with its default values for those that aren't given.
  • rng::AbstractRNG=default_rng(): the random number generator to sample actions from, which model and environment also receive in their inputs.
  • previous_state=initialize_state(model, ...): the state of model before the first timestep, by default its initial state from the full parameters. A state that model changes in place will be changed.
  • previous_action=initial_action(model): the action before the first timestep. By default every action is NoAction, with the names from attribute_names.
  • previous_environment_state=initialize_state(environment, ...): the state of environment before the first timestep, by default its initial state from the full parameters.
  • previous_observation=initial_observation(environment): the observation before the first timestep. By default every observation is NoObservation, with the names from attribute_names of environment.
  • save_history::SaveHistory=SaveHistory(): which observations, actions and states of model are saved, by name. Nothing is saved by default, and SaveHistory(SaveEverything()) saves everything. See SaveHistory.
  • save_environment_history::SaveHistory=SaveHistory(): which states of environment are saved. Only its states is used here, since the observations and actions are returned once, as save_history selects them.

See also simulate!, which continues from where the last simulation ended.

Examples

using CognitiveModeling
using Distributions: BernoulliLogit

#A cognitive model which learns the expected reward
struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = 0.5)
end

function CognitiveModeling.apply_model(model::RescorlaWagner, input::ModelInput)
    V₋₁ = input.previous_state.expected_reward
    Vₜ = V₋₁ + input.parameters.learning_rate * (input.observation.reward - V₋₁)
    return ModelOutput((; choice = BernoulliLogit(Vₜ - 0.5)), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(; parameters = :learning_rate, states = :expected_reward, observations = :reward, actions = :choice)
end

#An environment which gives a reward with a fixed probability, whatever the agent does
struct BernoulliRewards <: AbstractEnvironmentModel end

function CognitiveModeling.initialize_state(environment::BernoulliRewards, parameters)
    return (;)
end

function CognitiveModeling.apply_model(environment::BernoulliRewards, input::EnvironmentInput)
    reward = float(rand(input.rng) < input.parameters.reward_probability)
    return EnvironmentOutput((; reward))
end

function CognitiveModeling.attribute_names(environment::BernoulliRewards)
    return ModelAttributes(; parameters = :reward_probability, states = (), observations = :reward, actions = ())
end

observations, actions, cognitive_states, environment_states = simulate(
    RescorlaWagner(),
    BernoulliRewards();
    who_starts = EnvironmentStarts(),
    n_steps = 3,
    cognitive_parameters = (; learning_rate = 0.5),
    environment_parameters = (; reward_probability = 1.0),
    save_history = SaveHistory(SaveEverything()),
)

cognitive_states

Extended help

The return type is concrete as long as the types of the outputs don't change between timesteps. If they do, like an observation with an entry that is sometimes NoObservation, the vector for that output holds a Union of the types, and the simulation is a little slower.

Nothing is copied when outputs are saved. A model or environment which changes an object in its state in place, instead of returning a new one, must add a method of prepare_state_for_saving, or all the saved states show the final values, with no error. Observations and actions have no such function, so they must be new objects on each timestep.

Short simulations can be compiled with Reactant, if the action distributions work with traced numbers, which those from Distributions.jl don't. Compile a function that takes a Reactant.ReactantRNG() as a positional argument and passes it on as rng, because @jit doesn't trace keyword arguments and the default generator repeats its numbers on every run. Compile times grow quickly with n_steps, so this is for a few hundred timesteps at most.

CognitiveModeling.turing_single_session — Function
turing_single_session(model, parameters, observations, actions; <keyword arguments>)

Create a Turing.jl model of one session: model with parameters goes through the timesteps of the data, and the recorded actions are scored against the action distributions it gives. This needs Turing.jl to be loaded.

The model is a building block for a Turing.jl model which samples the parameters, as a submodel with its own prefix: to_submodel(prefix(turing_single_session(...), @varname(session)), false). It returns what save_history selects of the observations, the actions and the states of the session, as a NamedTuple of three vectors with one element for each timestep, which returned(model, chain) gives for each sample. Nothing is selected by default.

On each timestep, turing_apply_model of model runs as a submodel with the prefix timestep[t], so a model which samples within a timestep has its own variables for each timestep, such as timestep[3].noise. The recorded actions are scored together at the end, in one product_distribution over every action and timestep, which is several times faster than scoring each timestep on its own.

Arguments

  • model::AbstractCognitiveModel: the cognitive model.
  • parameters::NamedTuple: its parameters, usually the random variables of the model around this one. Those it doesn't have take the values in default_parameters.
  • observations::NamedTuple: the observations in the data, with one vector for each name and one entry for each timestep, such as (; reward = [1.0, 0.0, 1.0]). The data must have every observation the model lists in attribute_names, and can have more. An observation that wasn't recorded is MissingObservation, which environment fills in.
  • actions::NamedTuple: the actions in the data, in the same form, with exactly the actions the model lists. An action that was taken but not recorded is MissingAction, and is imputed. An action that wasn't taken is NoAction, and isn't scored.
  • who_starts::Union{AgentStarts, EnvironmentStarts}: whether the model acts on the observation of the same timestep, EnvironmentStarts(), or on the observation of the timestep before, AgentStarts(), as in simulate. It has no default, because a wrong choice shifts the model by a timestep without any error.
  • environment::Union{Nothing, AbstractEnvironmentModel}=nothing: an environment model which fills in the observations that are MissingObservation(). When it is given, it runs on every timestep as a submodel with the prefix environment[t], and its turing_apply_model must sample with ~ if it is random. The observations it gives are only used where the data has none. Without it, the data can't have missing observations.
  • environment_parameters::NamedTuple=(;): the parameters of environment.
  • timestep_sizes=1: how much time each timestep covers, as in simulate.
  • save_history::SaveHistory=SaveHistory(): which observations, actions and states are returned, by name. The returned actions and observations are those the model received, with the imputed and filled in values.
  • catch_invalid_parameters::Bool=false: whether an InvalidParametersError from the model gives the parameters a log density of -Inf, so that a sampler rejects them, instead of stopping the sampler. It is off by default because the try block it needs can't be differentiated with Mooncake, and a compiled ReverseDiff tape doesn't see the error, so the parameters get a finite log density with no warning. It works with ForwardDiff and Enzyme.
  • previous_state, previous_action, previous_observation, previous_environment_state: where the session starts, with the same defaults as in simulate.

An action that is MissingAction() is a latent variable named after its timestep and action, such as timestep[3].choice.imputed, with the model's action distribution on that timestep as its distribution. The sampler must handle its type: a continuous action can be sampled with NUTS, a discrete one needs a sampler for discrete variables. Any latent variable in a session, imputed or from a model which samples within a timestep, makes evaluating the model much slower in the current version of DynamicPPL.jl.

Examples

using CognitiveModeling
using Turing

#The model to fit, a Rescorla-Wagner model with a softmax choice
struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward = 0.5)
end

function CognitiveModeling.apply_model(model::RescorlaWagner, input::ModelInput)
    V₋₁ = input.previous_state.expected_reward
    Vₜ = V₋₁ + input.parameters.learning_rate * (input.observation.reward - V₋₁)
    Pₜ = BernoulliLogit(input.parameters.inverse_temperature * (Vₜ - 0.5))
    return ModelOutput((; choice = Pₜ), (; expected_reward = Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(;
        parameters = (:learning_rate, :inverse_temperature),
        states = :expected_reward,
        observations = :reward,
        actions = :choice,
    )
end

#The data of one session, where the third choice wasn't recorded
observations = (; reward = [1.0, 0.0, 1.0, 1.0])
actions = (; choice = [true, false, MissingAction(), true])

#Priors on the parameters, and the session as a submodel
@model function fit_one_session(observations, actions)
    learning_rate ~ Beta(2, 2)
    inverse_temperature ~ LogNormal(0, 1)
    session ~ to_submodel(
        prefix(
            turing_single_session(
                RescorlaWagner(),
                (; learning_rate, inverse_temperature),
                observations,
                actions;
                who_starts = EnvironmentStarts(),
                save_history = SaveHistory(; states = :expected_reward),
            ),
            @varname(session),
        ),
        false,
    )
    return session
end

chain = sample(fit_one_session(observations, actions), NUTS(), 1000)

#The expected rewards on each timestep, for each sample
trajectories = returned(fit_one_session(observations, actions), chain)

CognitiveModeling.apply_model — Method
apply_model(model::AbstractCognitiveModel, input::ModelInput)::ModelOutput

Run a single timestep of model. Usually this involves updating cognitive states and returning an object from which the action is sampled.

Implementation

Every model must add a method of this function, which throws an error otherwise. Anything random should be sampled from input.rng, so that a simulation can be reproduced. If states are mutated in place, a preparestatefor_saving method must be added. For use within PPLs, there may be special constraints - see the documentation for the specific PPL for details.

Examples

using CognitiveModeling
using Distributions: BernoulliLogit

struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.apply_model(model::RescorlaWagner, input::ModelInput)

    ## Unpack input ##
    #Reward observed on this timestep
    r = input.observation.reward
    #Expected reward from the previous state
    V₋₁ = input.previous_state.expected_reward
    #Learning rate parameter
    α = input.parameters.learning_rate
    #Inverse temperature parameter
    β = input.parameters.inverse_temperature

    ## Update state ##
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁)

    ## Compute action probabilities ##
    #Softmax function, instantiated as a Bernoulli logit distribution
    Pₜ = BernoulliLogit(β * (Vₜ - 0.5))

    return ModelOutput((; choice = Pₜ), (; expected_reward = Vₜ))
end

parameters = (; learning_rate = 0.1, inverse_temperature = 2.0)
input = ModelInput((; reward = 1.0), (; expected_reward = 0.5), (; choice = NoAction()), parameters)

CognitiveModeling.apply_model(RescorlaWagner(), input).new_state

# output

(expected_reward = 0.55,)

CognitiveModeling.turing_apply_model — Function
turing_apply_model(model::AbstractCognitiveModel, input::ModelInput)
turing_apply_model(environment::AbstractEnvironmentModel, input::EnvironmentInput)

Create a Turing.jl model for a single timestep of model, to be used as a submodel, which returns a ModelOutput, or of environment, which returns an EnvironmentOutput. This needs Turing.jl to be loaded.

Implementation

A model can add a method of this function. The default calls apply_model. A model which samples within a timestep needs to add a method, however; or if any other changes are desired within Turing. It must sample with ~ instead of from input.rng. Otherwise the model has a different log density each time it is evaluated, with no error. The same holds for an environment model, which fitting uses to fill in observations that are MissingObservation in the data.

Examples

using CognitiveModeling
using Turing

struct NoisyRescorlaWagner <: AbstractCognitiveModel end

Turing.@model function CognitiveModeling.turing_apply_model(
        model::NoisyRescorlaWagner,
        input::ModelInput,
    )

    ## Unpack input ##
    #Reward observed on this timestep
    r = input.observation.reward
    #Expected reward from the previous state
    V₋₁ = input.previous_state.expected_reward
    #Learning rate parameter
    α = input.parameters.learning_rate

    ## Update state ##
    #Sample the noise in the update
    ϵ ~ Normal(0, input.parameters.noise)
    #Update expected reward using the Rescorla-Wagner rule
    Vₜ = V₋₁ + α * (r - V₋₁) + ϵ

    return ModelOutput((; choice = BernoulliLogit(Vₜ - 0.5)), (; expected_reward = Vₜ))
end
