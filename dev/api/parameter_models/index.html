Parameter models

Models

CognitiveModeling.AbstractParametersModel — Type
AbstractParametersModel

Supertype for parameter models: the part of a full model, the model that an inference backend fits to several sessions, which gives or estimates the parameters of every session, for the cognitive model and for the environment model alike. The package comes with NoParameters, FixedParameters, SessionwiseFixedParameters, IdenticalParameters, IndependentParameters, HierarchicalGroupedParameters and HierarchicalRegressionParameters, and CompositeParameters combines several, each giving some of the parameters.

Implementation

Create a subtype, and for each inference backend it is used with, add a method of that backend's function for parameter models, as the backend's documentation describes. A method of CognitiveModeling.parameter_names lets the parameters it gives be checked before a fit, and a method of CognitiveModeling.prepare_parameters_model lets it work out once, before the backend's model is made, what doesn't change between evaluations. A model which only gives values, and estimates nothing, adds a method of CognitiveModeling.estimates_parameters.

CognitiveModeling.NoParameters — Type
NoParameters()

The parameter model of a full model which gives no parameters, so that each parameter takes the value the model gives it in default_parameters. It is the default for the parameters of the environment.

CognitiveModeling.FixedParameters — Type
FixedParameters(parameters)

The parameter model of a full model which gives every session the same values, such as (; scale = 2.0), with nothing sampled. The values are kept in the field parameters.

source
CognitiveModeling.SessionwiseFixedParameters — Type
SessionwiseFixedParameters(parameters_by_session)

The parameter model of a full model which gives each session parameters of its own, with nothing sampled. parameters_by_session holds the parameters of each session in one of three forms: by the session's symbol name, in a NamedTuple with an entry for each session, such as (; S1 = (; scale = 2.0), S2 = (; scale = 3.0)); by its data identifier, in a dictionary, such as Dict("S1" => (; scale = 2.0), "S2" => (; scale = 3.0)); or in the order of the sessions, as a NamedTuple with one vector for each parameter, such as (; scale = [2.0, 3.0]). A session with several session columns has a data identifier like (; id = "S1", block = 2) and a symbol name like id_S1__block_2, as CognitiveModeling.session_id_to_symbol gives it. Every session must have the same parameters. A full model makes the first two forms into the third once, before it is made. The parameters are kept in the field parameters_by_session.

CognitiveModeling.IdenticalParameters — Type
IdenticalParameters(priors)

The parameter model of a full model which samples each parameter once, from its prior, and gives every session that value. priors is a NamedTuple with the name of each parameter that is fitted and the distribution it is sampled from, such as (; learning_rate = Beta(2, 2)). The priors are kept in the field priors.

source
CognitiveModeling.IndependentParameters — Type
IndependentParameters(priors)

The parameter model of a full model which samples each parameter for every session from the same prior, with nothing shared between the sessions. priors is a NamedTuple with the name of each parameter that is fitted and the distribution it is sampled from, such as (; learning_rate = Beta(2, 2), inverse_temperature = LogNormal(0, 1)). The priors are kept in the field priors.

CognitiveModeling.HierarchicalGroupedParameters — Type
HierarchicalGroupedParameters(parameters)

The parameter model of a full model which samples each parameter of every session from a group-level distribution, whose own parameters are sampled from priors, once for each group of sessions. parameters is a NamedTuple with a HierarchicalParameter for each parameter that is fitted, which has its priors, its group-level distribution, its transformation and the columns that group the sessions, so the parameters can be grouped by different columns. It is kept in the field parameters.

A full model finds the group of every session once, before it is made, from the table that MultipleSessionsInfo keeps, so sessions that were prepared one at a time can only be in one group. The field groups is nothing until then, and afterwards has, for each parameter, the group of every session, group_of_each_session, the number of groups, n_groups, the symbol name of each group, group_symbol_names, and the priors of the group-level parameters, group_priors, each a NamedTuple with the prior under the symbol name of each group when the sessions are grouped, and the prior itself when they aren't.

Examples

using Turing
using LogExpFunctions: logistic

parameters_model = HierarchicalGroupedParameters((;
    learning_rate = HierarchicalParameter(
        (; mean = Normal(0, 1), sd = Exponential(1));
        transformation = logistic,
        group_by = :diagnosis,
    ),
    inverse_temperature = HierarchicalParameter(
        (; mean = Normal(0, 1), sd = Exponential(1)); transformation = exp
    ),
))

CognitiveModeling.HierarchicalParameter — Type
HierarchicalParameter(priors; distribution=nothing, transformation=identity,
                      group_by=nothing, centered=nothing)

How one parameter of a HierarchicalGroupedParameters is sampled for every session: from a group-level distribution, whose own parameters are sampled from priors, once for each group of sessions.

Arguments

  • priors::NamedTuple: the priors of the parameters of the group-level distribution, in the order in which the distribution takes them, such as (; mean = Normal(0, 1), sd = Exponential(1)). Their names name the variables of the group-level parameters.

Keyword arguments

  • distribution=nothing: the group-level distribution, as a function of its parameters, such as Normal or (location, scale) -> Laplace(location, scale). nothing is a normal distribution, whose two priors are those of its mean and its standard deviation.
  • transformation=identity: a function applied to the value of each session after it is sampled, such as exp for a parameter that must be positive or logistic for one between 0 and 1, as an inverse link function does in a regression.
  • group_by=nothing: a column of the table that the sessions were split from, or a tuple of columns, whose values group the sessions, so that each group has a group-level distribution of its own, such as :diagnosis for a clinical and a non-clinical group. Each session must have one value of each of the columns. The group-level parameters then have a value for each group under the group's symbol name, made from its values as session_id_to_symbol makes that of a session. With nothing, every session is in one group, and each group-level parameter is one value.
  • centered=nothing: for the default normal distribution, whether the value of each session is sampled from the distribution of its group, with true, or non-centered, as a standard normal value which the group's mean shifts and its standard deviation scales, with false, which is the default, since it usually samples better when the data of a session informs its parameters little. Any other distribution is always sampled from directly, and giving centered with one is an error.

Each argument is kept in a field of the same name, with group_by as a tuple of column names, which is empty for one group, centered as true or false, and a distribution that is given as a type inside a function which makes it.

Examples

julia> using Distributions: Normal, Exponential, Laplace

julia> learning_rate = HierarchicalParameter((; mean = Normal(0, 1), sd = Exponential(1)); transformation = exp, group_by = :diagnosis);

julia> learning_rate.group_by, learning_rate.centered
((:diagnosis,), false)

julia> inverse_temperature = HierarchicalParameter((; location = Normal(0, 1), scale = Exponential(1)); distribution = Laplace, transformation = exp);

julia> inverse_temperature.centered
true

CognitiveModeling.CompositeParameters — Type
CompositeParameters(parts...; named_parts...)

The parameter model of a full model which gives some of the parameters with each of its parts, which are parameter models, such as a HierarchicalGroupedParameters for the learning rate, an IndependentParameters for the inverse temperature and a FixedParameters for a bias. What the parts give is merged. The variables of a part in parts are named as that part names them, and those of a part given by keyword in named_parts are named under its keyword, such as noise.learning_rate.session for a part given as noise. No two parts can give the same parameter: this is checked when it is made, for the parts whose CognitiveModeling.parameter_names are known, and when it runs, for the others. It samples when any part does. The parts are kept in the field parts, as a tuple, with those in named_parts last.

Examples

using Turing

parameters_model = CompositeParameters(
    IndependentParameters((; learning_rate = Beta(2, 2))),
    FixedParameters((; inverse_temperature = 2.0)),
)

#The variables of the part given as noise are named under noise, as noise.bias.session
parameters_model = CompositeParameters(
    IndependentParameters((; learning_rate = Beta(2, 2)));
    noise = IndependentParameters((; bias = Normal(0, 1))),
)

Regressions

CognitiveModeling.CategoricalPredictor — Type
CategoricalPredictor(columns, prior=nothing; reference_level=nothing, coding=nothing,
                     name)

A categorical predictor of a RegressionParameter: a coefficient for each level other than the reference level, or for every level with the coding :full_dummy, with prior as its prior, such as Normal(0, 1), or with nothing the regression's default prior for a categorical predictor, from its DefaultRegressionPriors. Its levels are the values of columns, a column of the table that the sessions were split from, or the combinations of the values of several columns given as a tuple. In VaryingEffects it gives varying slopes, a deviation of each coefficient for each level of the varying effects, and prior is the prior of the standard deviation of the deviations.

Keyword arguments

  • reference_level=nothing: the reference level, such as "control", or a NamedTuple of values for several columns, such as (; diagnosis = "control", site = 1). With nothing, it is the level of the first session. The coding :full_dummy has no reference level.
  • coding=nothing: how the coefficients are coded, :dummy, :effects or :full_dummy, or with nothing the regression's default coding, from its DefaultRegressionSettings, which is :dummy unless another is given. With :dummy, each is the difference between a level and the reference level, such as the difference between a clinical and a non-clinical group. With :effects, each is the difference between a level and the mean of the levels, and the difference of the reference level is minus the sum of the others, which gives the reference level a wider prior than the others when there are three levels or more. With :full_dummy, every level has a coefficient, which is added for the sessions of that level. Without an Intercept, each is the value of its level, and every level has the same prior. With an Intercept, or another predictor coded this way, only the priors tell their coefficients apart.
  • name: the name of the predictor, which is the name of its column, or the names of its columns joined by two underscores, as in diagnosis__site. The coefficient of a level of one column is named after the predictor and the level, such as diagnosis_clinical, and that of a level of several columns after the level alone, by its symbol name, made as session_id_to_symbol makes that of a session, such as diagnosis_clinical__site_2.

Each argument is kept in a field of the same name, with columns as a tuple of names.

Examples

julia> using Distributions: Normal

julia> CategoricalPredictor((:diagnosis, :site), Normal(0, 1); coding = :effects).name
:diagnosis__site

CognitiveModeling.ContinuousPredictor — Type
ContinuousPredictor(column, prior=nothing; name=column)

A continuous predictor of a RegressionParameter: a coefficient which is multiplied by the value of column in each session, a column of the table that the sessions were split from whose values are numbers, with prior as its prior, such as Normal(0, 0.5), or with nothing the regression's default prior for a continuous predictor, from its DefaultRegressionPriors. In VaryingEffects it is a varying slope, a deviation of the coefficient for each level, and prior is the prior of the standard deviation of the deviations. The predictor and its coefficient are named name. Each argument is kept in a field of the same name.

CognitiveModeling.DefaultRegressionPriors — Type
DefaultRegressionPriors(; intercept=nothing, continuous_predictor=nothing,
                        categorical_predictor=nothing, interaction=nothing,
                        varying_intercept=nothing, varying_slope=nothing)

The priors that a RegressionParameter gives to the terms that are given without one, by their kind: intercept for an Intercept, continuous_predictor for a ContinuousPredictor, categorical_predictor for a CategoricalPredictor and interaction for an Interaction, and for the terms of VaryingEffects the priors of the standard deviations of their deviations, varying_intercept for an Intercept and varying_slope for a predictor or an interaction. With nothing, terms of that kind need a prior of their own. Each prior is kept in a field of the same name.

julia> learning_rate.terms.age.prior == Normal(0, 0.5)
true

DefaultRegressionSettings(; coding=:dummy, centered=false)

CognitiveModeling.HierarchicalRegressionParameters — Type
HierarchicalRegressionParameters(parameters)

The parameter model of a full model which gives each parameter of every session by a regression on columns of the table that the sessions were split from, such as the age and the diagnosis of a participant, with varying effects, which are also called random effects. parameters is a NamedTuple with a RegressionParameter for each parameter that is fitted, which has the terms of its regression and their priors. It is kept in the field parameters. Useful for estimating the effect of a predictor on a parameter, or the difference between groups, together with the parameters of the sessions.

A full model builds the design of every regression once, before it is made, from the table that MultipleSessionsInfo keeps, so sessions that were prepared one at a time can only have an intercept. The field designs is nothing until then, and afterwards has, for each parameter:

  • coefficient_priors and design_columns: the prior of each coefficient of the intercept, the predictors and the interactions, and the values it is multiplied by, one for every session, under the name of the coefficient: 1 for the intercept, the values of a continuous predictor, and those of the coefficients of a categorical predictor and of an interaction, as CategoricalPredictor and Interaction describe them.
  • reference_levels: the reference level of each categorical predictor, which is nothing with the coding :full_dummy, and under the name of an interaction those of the categorical predictors it was given themselves, in a NamedTuple.
  • varying_effects: for the varying effects of each column, the prior of the standard deviation of the deviations of each of their coefficients, coefficient_sd_priors, which is a NamedTuple with the prior under the symbol name of each group when the levels are grouped, the values that the deviations are multiplied by, design_columns, the reference_levels of their predictors, whether they are centered, and levels. These have the level of every session, level_of_each_session, the number of levels, n_levels, the symbol name of each level, level_symbol_names, and groups, which is nothing without groups and otherwise has the group of every level, group_of_each_level, the number of groups, n_groups, and the symbol name of each group, group_symbol_names.

Examples

using Turing
using LogExpFunctions: logistic

parameters_model = HierarchicalRegressionParameters((;
    learning_rate = RegressionParameter(
        Intercept(Normal(0, 1)),
        ContinuousPredictor(:age, Normal(0, 0.5)),
        CategoricalPredictor(:diagnosis, Normal(0, 1); reference_level = "control"),
        CategoricalPredictor(:condition, Normal(0, 1)),
        Interaction((:diagnosis, :condition), Normal(0, 0.5)),
        VaryingEffects(
            :participant,
            Intercept(Exponential(1)),
            CategoricalPredictor(:condition, Exponential(0.5));
            group_by = :diagnosis,
        ),
        VaryingEffects((:id, :block), Intercept(Exponential(1)); name = :session);
        transformation = logistic,
    ),
    inverse_temperature = RegressionParameter(
        Intercept(Normal(0, 1)),
        VaryingEffects((:id, :block), Intercept(Exponential(1)); name = :session);
        transformation = exp,
    ),
))

CognitiveModeling.Interaction — Type
Interaction(predictors, prior=nothing; name)

An interaction of the predictors in predictors, a tuple of two or more ContinuousPredictors or CategoricalPredictors of the same RegressionParameter or VaryingEffects, each given by its name or itself. A predictor given by its name, such as :age, is a term there itself, with coefficients of its own, which are its main effect. A predictor given itself, such as ContinuousPredictor(:age), is part of the interaction only, which then comes without that main effect: it has no coefficients of its own, so it is given without a prior, and a categorical one has a coding and a reference level of its own. With Interaction((ContinuousPredictor(:age), CategoricalPredictor(:diagnosis; coding = :full_dummy))), each diagnosis has its own slope of the age.

The interaction has a coefficient for each combination of one coefficient of each predictor, which is multiplied by the product of their values, as the predictors give them after coding the levels, with prior as its prior, such as Normal(0, 0.5), or with nothing the regression's default prior for an interaction, from its DefaultRegressionPriors. Two continuous predictors give one coefficient, a continuous and a categorical predictor one for each coefficient of the categorical predictor, and two categorical predictors one for each combination of their coefficients. In VaryingEffects it gives varying slopes, and prior is the prior of the standard deviation of their deviations.

The interaction is named name. By default, that is the names of its predictors joined by _by_, as in diagnosis_by_condition. Each of its coefficients is named after the coefficients it multiplies, joined by _by_, such as diagnosis_clinical_by_condition_punishment, whatever the interaction itself is named. Each argument is kept in a field of the same name, with predictors as a tuple.

Examples

julia> using Distributions: Normal

julia> Interaction((:diagnosis, :condition), Normal(0, 0.5)).name
:diagnosis_by_condition

julia> Interaction((ContinuousPredictor(:age), :diagnosis), Normal(0, 0.5)).name
:age_by_diagnosis
source

CognitiveModeling.RegressionFamily — Type
RegressionFamily(distribution_parameters; distribution)

The family of a RegressionParameter: the distribution that the value of each session is sampled from, with one of its parameters given by the regression, as in a generalized linear model.

Arguments

  • distribution_parameters::NamedTuple: the parameters of the distribution, in the order in which it takes them, as the priors of a HierarchicalParameter are, with RegressionOutcome for the one that the regression gives and a prior for each of the others, such as (; mean = RegressionOutcome(), sd = Exponential(1)). Each of the others is sampled once, for every session, and their names name their variables.

Keyword arguments

  • distribution: the distribution, as a function of its parameters, such as Normal, OrderedLogistic or (mean, dispersion) -> NegativeBinomial(dispersion, dispersion / (dispersion + mean)).

The argument is kept in the field distribution_parameters, and the distribution in distribution, inside a function which makes it when it is given as a type. The field priors has the priors among the parameters, without the outcome of the regression.

Examples

julia> using Distributions: Normal, Exponential

julia> family = RegressionFamily((; mean = RegressionOutcome(), sd = Exponential(1)); distribution = Normal);

julia> keys(family.priors)
(:sd,)

CognitiveModeling.RegressionParameter — Type
RegressionParameter(terms...; transformation=identity, family=nothing,
                    default_priors=DefaultRegressionPriors(),
                    default_settings=DefaultRegressionSettings(), name=nothing)
RegressionParameter(formula, terms...; categorical_predictors=(), priors=(;),
                    transformation=identity, family=nothing,
                    default_priors=DefaultRegressionPriors(),
                    default_settings=DefaultRegressionSettings())

How one parameter of a HierarchicalRegressionParameters is given to every session: by a regression on columns of the table that the sessions were split from, whose terms are an Intercept, ContinuousPredictors, CategoricalPredictors, Interactions and VaryingEffects. The value of a session is the sum of each coefficient of the intercept, the predictors and the interactions times its value in the session, and of the deviations of the session's levels of the varying effects, each times its value in the session, with transformation applied to the sum. Each session must have one value of every column that is used, which isn't missing. The second form writes the terms as a formula, see below.

A regression commonly has varying effects whose levels are the sessions, over the column or columns that identify them, such as VaryingEffects(:id, Intercept(Exponential(1))), which give each session a value of its own. Without them, sessions with the same values in every column that is used have the same value of the parameter.

With a family, the value of a session is sampled from a distribution instead, one of whose parameters is the transformed sum of the session, as in a generalized linear model. A discrete parameter needs one, since a sum is never discrete: with family = BernoulliLogit, the sum is the log odds that the parameter is true in a session. The values of the sessions are then variables of their own.

Every term has a name of its own, which its coefficients or its variables are named after. A term is named after its column or columns, and an interaction after its predictors, unless it is given another name.

Keyword arguments

  • transformation=identity: a function applied to the sum for each session, such as exp for a parameter that must be positive or logistic for one between 0 and 1, as an inverse link function does in a regression.
  • family=nothing: the distribution that the value of each session is sampled from. A distribution whose only parameter is the transformed sum of the session is given as it is, as a function of that sum, such as BernoulliLogit, LogPoisson or logit -> BinomialLogit(7, logit). One with other parameters is given as a RegressionFamily, which has the priors of the others, such as RegressionFamily((; mean = RegressionOutcome(), sd = Exponential(1)); distribution = Normal). With nothing, the value of a session is its transformed sum.
  • default_priors=DefaultRegressionPriors(): the priors of the terms that are given without one, by their kind, as a DefaultRegressionPriors.
  • default_settings=DefaultRegressionSettings(): the coding of the categorical predictors and whether varying effects are centered, for the terms that are given without them, as a DefaultRegressionSettings.
  • name=nothing: the name of the parameter, which a HierarchicalRegressionParameters checks against the name the regression is given under, or nothing for no check. A formula gives it.

The terms are kept in the field terms, as a NamedTuple with each term under its name, those without a prior with the one from default_priors, and those without a coding or a choice of centering with the ones from default_settings. The transformation, the family and the name are kept in fields of the same name, with a family that is given as a distribution in a RegressionFamily of it.

Formulas

With StatsModels.jl loaded, the terms can be written as a @formula, in the syntax of MixedModels.jl, such as @formula(learning_rate ~ 1 + age + diagnosis + (1 + condition | participant)). Its left-hand side is the name of the parameter. An intercept is included unless the formula has 0 +, and the same holds within varying effects. Columns joined by & are an Interaction, and a * b gives a, b and their interaction. A column of an interaction that isn't a term of its own in the same sum is given to the Interaction itself, so that age & diagnosis on its own is the interaction without the main effects. (terms | columns) are VaryingEffects over columns, or over the combinations of the values of several columns joined by &, as in (1 | participant & block), and their deviations are independent, where MixedModels.jl correlates those within one bar. Terms that a formula can't express, such as VaryingEffects with group_by, are given after the formula.

A column is a ContinuousPredictor, unless categorical_predictors has it, which makes it a CategoricalPredictor. categorical_predictors takes the name of a column, such as :diagnosis, or a tuple of names, such as (:diagnosis, :site). A column that is named has the coding of default_settings, and the level of the first session as its reference level, where StatsModels.jl takes the first level in sorted order. In the place of a name, a CategoricalPredictor gives the coding or the reference level of its column, such as CategoricalPredictor(:diagnosis; coding = :effects, reference_level = "control"). It reads one column and is named after it, and its prior is given in priors, as those of the other terms are. A column is the same predictor wherever the formula has it: as a term of its own, in an interaction and in varying effects.

Each term is named as the term of its kind is named, and priors gives the priors of terms by those names, such as (; age = Normal(0, 0.05), age_by_diagnosis = Normal(0, 0.5), participant = (; intercept = Exponential(0.5))), with the name of an interaction joining those of its predictors by _by_, and with a NamedTuple for the terms of varying effects. The other terms have the default priors.

Examples

julia> using Distributions: Normal, Exponential

julia> default_priors = DefaultRegressionPriors(; intercept = Normal(0, 1), continuous_predictor = Normal(0, 0.5), categorical_predictor = Normal(0, 1), interaction = Normal(0, 0.5), varying_intercept = Exponential(1));

julia> learning_rate = RegressionParameter(Intercept(), ContinuousPredictor(:age), CategoricalPredictor(:diagnosis), Interaction((:age, :diagnosis)), VaryingEffects(:participant, Intercept()); default_priors);

julia> keys(learning_rate.terms)
(:intercept, :age, :diagnosis, :age_by_diagnosis, :participant)

A discrete parameter, which is true in a session with log odds that depend on the age, and a parameter whose value in a session is sampled around the sum of its regression, with a standard deviation that is sampled too:

uses_rewards = RegressionParameter(
    Intercept(Normal(0, 1)), ContinuousPredictor(:age, Normal(0, 0.5));
    family = BernoulliLogit,
)

bias = RegressionParameter(
    Intercept(Normal(0, 1)), ContinuousPredictor(:age, Normal(0, 0.5));
    family = RegressionFamily(
        (; mean = RegressionOutcome(), sd = Exponential(1)); distribution = Normal
    ),
)

A regression written as a formula, with varying intercepts of the participants whose standard deviations differ between diagnoses, which a formula can't express, after it:

using StatsModels

CognitiveModeling.VaryingEffects — Type
VaryingEffects(columns, terms...; group_by=nothing, centered=nothing, name)

Effects of a RegressionParameter that vary between the levels of columns, such as between participants: for each level, a deviation of each coefficient of its terms, from a normal distribution around zero whose standard deviation has the term's prior as its prior. Varying effects are also called random effects, and the other terms of a regression fixed effects. The levels are the values of columns, a column of the table that the sessions were split from, or the combinations of the values of several columns given as a tuple. The terms are an Intercept, for a varying intercept, and ContinuousPredictors, CategoricalPredictors and Interactions, for varying slopes, as in the examples below. A term without a prior has the regression's default prior for a varying intercept or a varying slope, from its DefaultRegressionPriors. Each coefficient has a standard deviation of its own. A varying slope needs values that differ between the sessions of a level, such as a condition that changes between the blocks of a participant, and a predictor that an interaction in varying effects names is a term of the same varying effects.

Keyword arguments

  • group_by=nothing: a column of the table that the sessions were split from, or a tuple of columns, whose values group the levels, so that each group has a standard deviation of its own, such as :diagnosis for a clinical and a non-clinical group of participants. The sessions of one level must all be in one group. With nothing, the levels share one standard deviation.
  • centered=nothing: whether each deviation is sampled from the normal distribution directly, with true, or non-centered, as a standard normal value which the standard deviation scales, with false, or with nothing as the regression's DefaultRegressionSettings say, which is false unless they say otherwise. The non-centered form usually samples better when the data informs each deviation little.
  • name: the name of the varying effects, which their variables are named under: the name of their column, or the names of their columns joined by two underscores, as in id__block.

Each argument is kept in a field of the same name, with columns and group_by as tuples of names, group_by being empty without groups, and terms as a NamedTuple with each term under its name.

Examples

julia> using Distributions: Exponential

julia> by_participant = VaryingEffects(:participant, Intercept(Exponential(1)), ContinuousPredictor(:time, Exponential(0.5)); group_by = :diagnosis);

julia> keys(by_participant.terms), by_participant.group_by
((:intercept, :time), (:diagnosis,))

julia> VaryingEffects((:id, :block), Intercept(Exponential(1))).name
:id__block

CognitiveModeling.parameter_names — Function
parameter_names(parameters_model)

Return the names of the parameters that parameters_model gives every session, as a tuple of Symbols, or nothing when they aren't known before it runs. prepare_full_model checks them against the parameters of the cognitive model and of the environment model, and CompositeParameters checks that no two of its parts give the same one.

Implementation

CognitiveModeling.estimates_parameters — Function
estimates_parameters(parameters_model)

Return whether parameters_model, a parameter model, estimates the parameters it gives from the data, instead of being given their values: false for NoParameters, FixedParameters and SessionwiseFixedParameters, whether any part does for a CompositeParameters, and true for every other kind. When the environment's parameters are estimated, a full model includes the environment in every session, so that the observations in the data inform them, and it warns when the parameters of the two models can have the same variables.

Implementation

A parameter model of one's own can add a method of this function. The default returns true, and a model which only gives values returns false.

Examples

julia> CognitiveModeling.estimates_parameters(FixedParameters((; scale = 2.0)))
false

CognitiveModeling.prepare_parameters_model — Function
prepare_parameters_model(parameters_model, sessions_info)

Return parameters_model prepared for the sessions in sessions_info, with what doesn't change between the evaluations of an inference backend's model worked out once, before the model is made. A SessionwiseFixedParameters has the values of every session looked up, a HierarchicalGroupedParameters has the group of every session found, a HierarchicalRegressionParameters has the design of every regression built, and a CompositeParameters has each of its parts prepared. Used by prepare_full_model.

Implementation

A parameter model of one's own can add a method of this function, which returns a parameter model that the inference backends have methods for. The default returns parameters_model as it is.
