Saving trajectories

What a simulation or a fitted session saves of each model, chosen by name, whether it saves where the models started, as timestep 0, and the trajectories it returns.

CognitiveModeling.SaveTrajectories — Type
SaveTrajectories(; states=(), inputs=(), outputs=(), output_distributions=(),
                 save_initial_timestep_values=true)
SaveTrajectories(SaveEverything(); save_initial_timestep_values=true)

Which states, inputs, outputs and output distributions of a model a simulation or a fitted session saves, by name, and whether it saves them from before the first timestep too.

states, inputs, outputs and output_distributions are each the names of that kind to save, in a Tuple of Symbols, a single Symbol or a Vector of them, or SaveEverything for all of them. The names are those in the model's attributes, from attribute_names: for a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it receives and the outputs the observations it gives. The output distributions are what the model gave its outputs to be sampled from, named like the outputs. A kind that isn't given saves nothing, so SaveTrajectories() saves nothing, which is the default everywhere, and SaveTrajectories(SaveEverything()) saves everything. The selections are read as properties, such as save_trajectories.states.

A model with submodels keeps the state of each submodel under the submodel's name, which selects all of that state. Some of its states are selected with the name of the submodel, =>, and their names, as in states = (:surprise, :perception => :expected_reward). Several states go in a tuple, as in :perception => (:expected_reward, :prediction_error), and the states of a submodel of the submodel are selected in the same way, as in :perception => :learning => :expected_reward. They are saved under the name of the submodel, as the state keeps them, such as (; surprise = 0.1, perception = (; expected_reward = 0.5)).

save_initial_timestep_values is whether what is saved starts with timestep 0, before the first timestep: the initial states, and the previous input and output, which are BeforeFirstTimestep unless others are given. It is true by default, which matters when the initial state depends on parameters that are fitted. Since Julia counts from 1, element t + 1 of what is saved is then timestep t, and with false, element t is.

Saving some names of a kind gives a NamedTuple with those names on each timestep, and saving none gives an empty one, (;). Before the first timestep there is no output distribution, so timestep 0 has BeforeFirstTimestep() for each name that is saved.

Each model of a simulation has one: simulate_session and SessionInfo take save_cognitive_trajectories and save_environment_trajectories, and an InstantiatedModel takes save_trajectories. The trajectories that a simulation or a session returns are named by their role: the cognitive model's inputs as observations and outputs as actions, and the environment's inputs as actions and outputs as observations under environment, as simulate_session describes.

Examples

CognitiveModeling.SessionTrajectories — Type
SessionTrajectories(states, observations, actions, action_distributions, environment,
                    timestep_sizes, parameters_valid, n_timesteps, last_timestep,
                    submodel_states=(; cognitive_model=(;), environment=(;)))

The trajectories of one session, which are what changed over its timesteps, and how the session ended. simulate_session and simulate_session! return one, and a fitted session returns one for each sample.

Each argument is kept in a field of the same name, such as trajectories.states. The trajectories of each kind are a vector with one element for each timestep, after one for timestep 0, before the first timestep, when it is saved. Each element is a NamedTuple with what the SaveTrajectories of its model selects of that kind, which is empty when it selects nothing. NamedTuple(trajectories) gives the fields in a NamedTuple.

In the REPL, the trajectories of a session show the number of timesteps, the names of what was saved of each kind, for the cognitive model and for the environment, with the states of a submodel after its name, as in perception.expected_reward, and whether the parameters stayed valid. On one line, as inside a vector, they show the number of timesteps.

Arguments

  • states: the states of the cognitive model after each timestep, as returned by prepare_state_for_saving.
  • observations: the observations the cognitive model received.
  • actions: the actions the cognitive model gave.
  • action_distributions: what the cognitive model gave its actions to be sampled from.
  • environment: the trajectories of the environment model in a NamedTuple, each in the environment's own names: its states, the observations it gave, the actions it received, and the observation_distributions it gave its observations to be sampled from. A fitted session without an environment has NoEnvironment instead.
  • timestep_sizes: how much time each timestep covered: a single size for all of them, or a vector with the size of each, after BeforeFirstTimestep for timestep 0 when it is saved.
  • parameters_valid: whether the parameters of both models stayed valid on every timestep. With false, the trajectories end before the timestep on which a model set parameters_valid to false in its ModelOutput, or, in a fitted session, before a stopping_criterion that was met while the data continues. It is a Bool, also for models that can't set it, except in a simulation that a compiler like Reactant.jl masked, where it can be a traced Bool.
  • n_timesteps: the number of timesteps in the trajectories, without timestep 0. A simulation that was masked, under a compiler like Reactant.jl, has every timestep in the vectors, of which the first n_timesteps were kept, as simulate_session describes.
  • last_timestep: the last timestep that was simulated, from a simulation of models that can set parameters_valid, which is the timestep that turned invalid when parameters_valid is false: its number, under timestep, and for each model whether its parameters stayed valid on it and its state before and after it, with the cognitive model's at the top and the environment's under environment. Otherwise nothing.
  • submodel_states: which of the states hold the state of a submodel, under cognitive_model for the cognitive model and under environment for the environment: the name of each submodel with a state, with those of its own submodels with a state in a NamedTuple, as CognitiveModeling.submodel_state_names gives them, so that (; perception = (;)) says that states[t].perception is the state of the submodel perception. A model without submodels has (;).

CognitiveModeling.TrajectoryHistory — Type
TrajectoryHistory(states, inputs, outputs, output_distributions, timestep_sizes)

The trajectories that an InstantiatedModel has saved so far, which simulate_session! and simulate_timestep! add to.

Each argument is kept in a field of the same name, such as trajectories.states. The names are the model's own: for a cognitive model the inputs are its observations and the outputs its actions, and for an environment model the inputs are the actions it received and the outputs the observations it gave. The model's SaveTrajectories selects what is kept of each kind, and when it selects nothing at all, the vectors stay empty. Each vector starts with timestep 0, where the model started, when the SaveTrajectories saves the initial timestep values, which it does by default, so that element t + 1 is timestep t.

The vectors hold values of any type, since what is saved can change type from one timestep to the next, as an output does from BeforeFirstTimestep() at timestep 0 to a value.

Arguments

  • states::Vector{Any}: the states of the model, starting at timestep 0 with its initial state. Later states are those after each timestep. All of them are as returned by prepare_state_for_saving.
  • inputs::Vector{Any}: what the model received on each timestep, starting at timestep 0 with every input in the model's attributes as BeforeFirstTimestep, since it has received nothing before the simulation.
  • outputs::Vector{Any}: what the model gave on each timestep, starting at timestep 0 with its previous output, which by default has every output as BeforeFirstTimestep().
  • output_distributions::Vector{Any}: what the model gave each output to be sampled from, starting at timestep 0 with BeforeFirstTimestep() for every output, since nothing was given yet.
  • timestep_sizes::Vector{Any}: how much time each timestep covered, starting with BeforeFirstTimestep() for timestep 0, so that it has an entry for each entry of the other vectors.
