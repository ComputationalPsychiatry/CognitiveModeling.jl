Predictive checks and parameter recovery

A model that is fitted to the data of some sessions can also simulate that data. With parameters drawn from their priors, the simulated data shows what the model expects before it is fitted, a prior predictive check, and with the parameters of a fit, how well the fitted model describes the data, a posterior predictive check. Data simulated with known parameters can also be fitted again, to see whether the fit finds the parameters that simulated it: a parameter recovery. This page does all three with Turing.jl.

The package's models of the sessions take their data as arguments, and Turing.jl's decondition and condition work on the variables of a model, so they leave that data as it is. decondition_sessions takes the data out of the sessions, so that the model simulates every action as a variable, and condition_sessions puts values of those variables back in the sessions as data. Turing.jl's own functions can then simulate, and its condition can condition the model on the same variables. The page does each step in both ways, and compares them at the end.

using CognitiveModeling
using Distributions: Bernoulli, BernoulliLogit, Beta, LogNormal, Normal
using LogExpFunctions: logsumexp
using PosteriorStats: compare, loo
using Random: Xoshiro
using Statistics: mean, var
using Turing
using Turing: DynamicPPL

The model and the data

The Rescorla-Wagner model learns the expected reward of an option from the rewards it gets, and chooses the option with a probability that grows with its expected reward:

struct RescorlaWagner <: AbstractCognitiveModel end

function CognitiveModeling.initialize_state(model::RescorlaWagner, parameters)
    return (; expected_reward=0.5)
end

function CognitiveModeling.timestep_model(model::RescorlaWagner, context::ModelContext)
    #The expected reward before this timestep, and after its reward
    V₋₁ = context.previous_state.expected_reward
    Vₜ = V₋₁ + context.parameters.learning_rate * (context.input.reward - V₋₁)

    #The higher the expected reward, the more likely the option is chosen
    Pₜ = BernoulliLogit(context.parameters.inverse_temperature * (Vₜ - 0.5))
    return ModelOutput((; choice=Pₜ), (; expected_reward=Vₜ))
end

function CognitiveModeling.attribute_names(model::RescorlaWagner)
    return ModelAttributes(;
        parameters=(:learning_rate, :inverse_temperature),
        states=:expected_reward,
        inputs=:reward,
        outputs=:choice,
    )
end

The rewards come from an environment which gives a reward with a fixed probability on every timestep:

struct BernoulliRewards <: AbstractEnvironmentModel end

CognitiveModeling.initialize_state(environment::BernoulliRewards, parameters) = (;)

function CognitiveModeling.timestep_model(
    environment::BernoulliRewards, context::ModelContext
)
    return ModelOutput((; reward=Bernoulli(context.parameters.reward_probability)))
end

function CognitiveModeling.attribute_names(environment::BernoulliRewards)
    return ModelAttributes(;
        parameters=:reward_probability, states=(), inputs=:choice, outputs=:reward
    )
end

Prior predictive checks

The sessions of decondition_sessions have SimulatedMissingValue in place of every choice, so that the model simulates each choice as a variable. They have the rewards of the data, since they have no environment that could simulate the rewards:

decondition_sessions(sessions_info).sessions[1].actions.choice[1:3]

Given the full model, it returns a copy whose sessions are deconditioned. Turing.jl's sample with Prior() then simulates a data set for each draw of the parameters from their priors. The chain has the parameters and the simulated choices, as variables named such as simulated_sessions[1].timesteps[3].choice.simulated, since the deconditioned sessions are named apart from the fitted ones, sessions[1] and the others:

deconditioned_model = decondition_sessions(model)
prior_predictions = sample(Xoshiro(1), deconditioned_model, Prior(), 200; progress=false)

Posterior predictive checks

A posterior predictive check simulates the data with the parameters of each sample of a fit. Turing.jl's predict does it with the deconditioned model, and predict_session_trajectories with the model itself:

chain = sample(Xoshiro(4), model, NUTS(), 300; progress=false)
posterior_predictions = predict(Xoshiro(5), deconditioned_model, chain)
posterior_trajectories = predict_session_trajectories(
    Xoshiro(6),
    model,
    chain;
    save_cognitive_trajectories=SaveTrajectories(;
        outputs=:choice, save_initial_timestep_values=false
    ),
)
[

        participant,
        data=share_in_data[i],

Parameter recovery

A draw from the prior of the deconditioned model has parameters, and choices simulated with them. DynamicPPL.subset keeps the variables within the sessions, the simulated choices, and leaves out the parameters, which the fit is to find:

simulated = rand(Xoshiro(7), deconditioned_model)
simulated_choices = DynamicPPL.subset(simulated, [@varname(simulated_sessions)])
simulated_parameters = DynamicPPL.subset(
    simulated, [@varname(learning_rate), @varname(inverse_temperature)]
)

Turing.jl's condition conditions the deconditioned model on the simulated choices, as variables, and condition_sessions puts them in the data of its sessions, where they are scored as data from a table is. The two models give the same log joint at any parameters, here at those that simulated the choices:

turing_recovery_model = condition(deconditioned_model, simulated_choices)
package_recovery_model = condition_sessions(deconditioned_model, simulated_choices)

Comparing models

How well a fitted model predicts data it wasn't fitted to can be estimated from the fit itself, with leave-one-out cross-validation by Pareto-smoothed importance sampling, PSIS-LOO. It needs the log-likelihood of each data point with the parameters of each sample. Turing.jl's pointwise_loglikelihoods gives them with factorize = true: each session scores its choices together, and factorize splits them into a value for each choice, in the order of the timesteps that have one:

function log_likelihood_array(pointwise, output)
    session_names = collect(keys(pointwise))
    n_samples, n_chains = size(pointwise[first(session_names)])
    return stack(
        [
            getproperty(pointwise[session_name][sample_index, chain_index], output)[i] for
            sample_index in 1:n_samples, chain_index in 1:n_chains
        ] for session_name in session_names for
        i in eachindex(getproperty(pointwise[session_name][1, 1], output))
    )
end
log_likelihood = log_likelihood_array(pointwise, :choice)

WAIC estimates the same as PSIS-LOO, with a larger error and without its diagnostics, so PosteriorStats.jl no longer computes it. From the same array, by hand:

function waic_estimate(log_likelihood)
    draws = reshape(log_likelihood, :, size(log_likelihood, 3))
    log_pointwise_predictive_density = sum(
        logsumexp(draws[:, i]) - log(size(draws, 1)) for i in axes(draws, 2)
    )
    effective_number_of_parameters = sum(var(draws[:, i]) for i in axes(draws, 2))
    return (;
        elpd=log_pointwise_predictive_density - effective_number_of_parameters,
        effective_number_of_parameters,
    )
end
waic = waic_estimate(log_likelihood)

Turing.jl's functions or the package's

Turing.jl's functionsThe package's functions
Prior predictive checksample(decondition_sessions(model), Prior(), n)predict_session_trajectories(model, sample(model, Prior(), n))
Posterior predictive checkpredict(decondition_sessions(model), chain)predict_session_trajectories(model, chain)
Parameter recoverycondition(decondition_sessions(model), values)condition_sessions(decondition_sessions(model), values)

They give the same results in most cases:

  • The predictive checks simulate every action and observation of the sessions again, also those that a fit imputed, and what a model samples of its own, at its start or within a timestep, with the same distributions, so only the random numbers differ.
  • The two models of a parameter recovery have the same log joint, and so the same posterior, when the sessions have no environment, or one whose parameters are fitted.

They differ in what they return, and in a few cases:

  • Turing.jl's functions return the simulated actions and observations as variables of a chain, and predict_session_trajectories returns what the sessions save, such as the states of the models, as get_session_trajectories does.
  • A session with an environment whose parameters are fixed scores the conditioned observations against the environment's distributions with Turing.jl's condition, and leaves its environment out with condition_sessions, since nothing in it is simulated. The log joints then differ by the same amount at every value of the parameters, so the posteriors are the same.
  • Turing.jl's condition leaves out a value whose variable the model doesn't have, such as one with a misspelled name, while condition_sessions throws an error for it, and for a value of any variable that isn't an action or an observation of the sessions, such as a parameter.
  • With a CognitiveModeling.stopping_criterion, a deconditioned session with an environment checks it before every timestep, also with Turing.jl's condition. Such a session then ends where the criterion is met at the parameters of each evaluation: before its last value, which leaves out the values after it with no error, or after it, with a variable for every action and observation that follows. condition_sessions ends each session after its last timestep with a value, and doesn't check the criterion, as a fit to a table of that data doesn't.

How fast they are differs more. With 20 sessions of 100 timesteps, and the values given with a concrete type each, as rand and DynamicPPL.subset give them:

  • Fitting: with Turing.jl's condition, each evaluation of the log density took about 4 times as long as with condition_sessions, and each gradient about 1 to 10 times as long, depending on the automatic differentiation backend. With an environment, whose observations it conditioned on too, each evaluation took about 10 times as long, and each gradient about 1.5 to 20 times.
  • Simulating: sample with Prior() on the deconditioned model took about 50 times as long per draw as predict_session_trajectories, and its chain has a variable for every simulated choice. predict took about one and a half times as long as predict_session_trajectories. simulate_session took about a hundredth of that, with the parameters given for each session instead of read from a chain.
