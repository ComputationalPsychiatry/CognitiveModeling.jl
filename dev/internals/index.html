CognitiveModeling.AbstractModel — Type
AbstractModel

Supertype for cognitive models and environment models, which every function that a model implements or is used with takes. A model is a subtype of AbstractCognitiveModel or of AbstractEnvironmentModel, and not of this type itself.

The two kinds work the same way: on each timestep a model receives an input and gives an output, in a ModelContext and a ModelOutput. In a simulation or a fitted session, the outputs of the cognitive model are its actions, which are the inputs of the environment model, and the outputs of the environment model are the observations, which are the inputs of the cognitive model. A cognitive model can therefore also serve as the environment of another.

CognitiveModeling.check_names_fit — Function
check_names_fit(cognitive_model, environment, observation_map=nothing,
                action_map=nothing)

Throw an informative error if cognitive_model and environment can't be simulated together. Without a map, the outputs of each must be the inputs of the other in attribute_names: the observations the environment gives are what the cognitive model lists as its inputs, and the actions the cognitive model gives are what the environment lists as its inputs. With a NameMap for the observations or the actions, the map must take names the giver lists, and give exactly the names the receiver lists.

The names are in the types, so the check is decided at compile time and costs nothing.

CognitiveModeling.collect_initial_outputs — Method
collect_initial_outputs(save_initial_values::Val, previous_outputs, cognitive_model,
                        environment, observation_map, action_map,
                        cognitive_save_history, environment_save_history)

Return what is saved from before the first timestep, as timestep 0, in a NamedTuple with the names of the saved outputs of collect_timestep_outputs, or nothing when save_initial_values is Val(false).

The observation and the action are the previous ones, as each side receives them, the output distributions are BeforeFirstTimestep for every output, since none was given yet, and the states are the states before the first timestep. They must be saved before the first timestep runs, since it can change a state in place.

source
CognitiveModeling.collect_timestep_outputs — Method
collect_timestep_outputs(environment_output, cognitive_output,
                         observation_from_environment, observation, action,
                         action_to_environment, cognitive_model, environment,
                         cognitive_save_history, environment_save_history)

Collect the outputs of a timestep in a NamedTuple, each both as it is, which the next timestep starts from, and as it is saved, which cognitive_save_history and environment_save_history select.

observation_from_environment is the observation sampled from what the environment gave, and observation is the same observation as the cognitive model receives it. action_to_environment is action as the environment receives it. Each pair differs when a NameMap selects or renames them. The cognitive model's history holds the observation as the cognitive model receives it, and the environment's the action as the environment does.

This is its own function so that if an output can have two types, like an observation with an entry that is sometimes NoObservation, the compiler can split the call and get a concrete type for each.

CognitiveModeling.run_remaining_timesteps — Method
run_remaining_timesteps(storage, outputs, who_starts, cognitive_model, environment,

CognitiveModeling.run_timesteps — Method
run_timesteps(previous_outputs, who_starts, cognitive_model, environment,
              cognitive_parameters, environment_parameters, cognitive_save_history,
              environment_save_history, observation_map, action_map, rng,
              timestep_sizes, n_steps, save_initial_values::Val,
              check_stopping_criterion)

Run up to n_steps timesteps starting from previous_outputs, and return a NamedTuple of vectors with the saved outputs of the timesteps that ran, followed by the outputs of the last one. When check_stopping_criterion is true, the timesteps end before n_steps if stopping_criterion of either model is met, and a model where it is met already can't run any. When save_initial_values is Val(true), each vector starts with what is saved from before the first timestep, as timestep 0.

The vectors are states, observations, actions and action_distributions with what cognitive_save_history selects of the cognitive model's, and environment_states, environment_observations, environment_actions and environment_observation_distributions with what environment_save_history selects of the environment's, as saved_values arranges them for what is returned.

simulate! continues from the last outputs instead of from what was saved, because prepare_state_for_saving can return anything, and because the next simulation can change a state in place.

CognitiveModeling.timestep — Method

CognitiveModeling.columns_used — Method
columns_used(specification)

Return the names of the columns of a table that one specification of an attribute's column uses, as a tuple. A specification is one of:

  • a Symbol, the column itself;
  • a NamedTuple of Symbols, such as (; choice = :choicecol, rt = :rtcol), for a column of NamedTuples with those names built from the columns, one for each row;
  • a Tuple of Symbols, such as (:choicecol, :rtcol), for a column of Tuples;
  • a Pair of a Tuple of Symbols and a function, such as (:choicecol, :rtcol) => (choice, rt) -> [choice, rt], for a column with what the function gives for the values of each row.

A missing in any column used makes the value of that row missing. Used by MultipleSessionsInfo when it checks a table, and by build_column.

CognitiveModeling.entry — Method

CognitiveModeling.recorded_values — Method
recorded_values(columns)

Return the recorded values of each action or observation in columns, a NamedTuple with one vector per name, as a NamedTuple of vectors in the order of the timesteps. Fitting scores these against the distributions the model gave on the same timesteps: the actions against the cognitive model's, and the observations against the environment's. Each vector has the element type of its column without MissingValue and the markers for nothing happening, so that a session without recorded values for a name gets an empty vector of the same type as other sessions, which scores nothing. A name whose column can only hold those markers is left out, which is decided by its type, so that it is the same for every session of a table. Used by SessionInfo, which keeps the results in its fields recorded_actions and recorded_observations.

CognitiveModeling.replace_missing — Method
replace_missing(columns, replacement)

Return columns, a NamedTuple with one vector per name, with every missing replaced by replacement: MissingValue for a value that wasn't recorded, or NoAction or NoObservation for nothing happening on that timestep. A column whose element type allows missing gets the replacement in its element type whether it holds a missing or not, so that the sessions of one table all have the same type, and a column whose element type doesn't is kept as it is, after narrow_column.
