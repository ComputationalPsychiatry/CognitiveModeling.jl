Types

CognitiveModeling.AbstractAttributeKind — Type
AbstractAttributeKind

Supertype of the kinds of attributes of a model: ParameterKind for its parameters, StateKind for its states, and the subtypes of AbstractObservableAttributeKind, ObservationKind for the observations and ActionKind for the actions. Used to say which kind of attribute something is.

source
CognitiveModeling.AbstractObservableAttributeKind — Type
AbstractObservableAttributeKind

Supertype of the kinds of attributes that the data of a session has: ObservationKind for the observations, which are the inputs in the attributes of its cognitive model, and ActionKind for the actions, which are its outputs. Used when a table is split into sessions and when the data of a session is named, to say which of the two a column or a vector of data is.

source
CognitiveModeling.AbstractTimestepModel — Type
AbstractTimestepModel

Supertype for timestep models: cognitive models and environment models, which every function that a model implements or is used with takes. A model is a subtype of AbstractCognitiveModel or of AbstractEnvironmentModel, and generally not of this type itself.

The two kinds work the same way, one timestep at a time: on each timestep a model receives an input and gives an output, in a ModelContext and a ModelOutput. In a simulation or a fitted session, the outputs of the cognitive model are its actions, which are the inputs of the environment model, and the outputs of the environment model are the observations, which are the inputs of the cognitive model. A cognitive model can therefore also serve as the environment of another. Every timestep model is also an AbstractSubmodel, so that it can be a submodel of another model.

CognitiveModeling.check_submodels — Method
check_submodels(model::AbstractSubmodel)

Throw an informative error if the submodels of model aren't declared or named as they must be, and else return nothing. Each name that CognitiveModeling.submodel_fields gives must be a field of model that holds an AbstractSubmodel, and each of CognitiveModeling.submodels must be one. The name of a submodel must differ from the model's own names in attribute_names, since it is the name of the submodel's parameters and state. No two parameters may get the same flat name, which happens when two submodels, or a submodel and the model, have a parameter of the same name, and the model doesn't use prefixes: the error then says to give it a method of CognitiveModeling.uses_submodel_prefixes. Last, every name of get_attribute_names must be used once. The submodels of each submodel are checked in the same way. Used by get_attribute_names.

source

check_unique_flat_parameter_names(model, layout::ModelLayout)

CognitiveModeling.check_parameters_in_domains — Method
check_parameters_in_domains(model, parameters)

Throw a ParameterDomainError if a parameter in parameters is outside its domain in parameter_domains of model: of another type than the domain's, below its lower bound or above its upper bound, not one of its possible values, or not satisfying its constraint. Used by simulate_session, simulate_timestep, InstantiatedModel and fitted sessions, before anything runs, unless they are given check_parameter_domains = false.
